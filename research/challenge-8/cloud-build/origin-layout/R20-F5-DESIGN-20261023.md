# R20 synthetic unwind-copy resource control

This adds a separate source-only diagnostic for R19 review nit F5. It does not change the five existing controls or the R19 translator marker. The new fixture uses the prepared actual raw-caller pair as its parent identity, then builds a distinct paired source with an always-panicking `insert_tail` whose checked normal post is `false` and whose unwind post preserves the three-cell array, element owners, thread token, and comparator owner. Its wrapper uses the same raw local allocation and R19 marker, with only the marker's array count changed from 3 to 4.

If all source stages pass, the verifier reaches and proves the synthetic callee before the wrapper, the normal call branch is unreachable, and the sole verifier error is the exact count-4 array resource refusal at the marked assertion. The classifier requires both verifier function headers in order, the panic and call trace locations, one executed marker line, exactly one matching heap diagnostic at that line in the wrapper segment, no other verifier errors or dead-code diagnostic, zero exporter/decode/refinement exits, and exact source/stage receipts for the fixture plus the unchanged actual raw-caller preparation record. Any setup, unsupported panic lowering, missing trace, normal-path or other verifier failure is INCONCLUSIVE.

This result demonstrates that the copied block is checked against unwind resources in an isolated synthetic control. It does not test the actual `insert_tail` unwind post, does not qualify the raw caller or actual source, and grants no acceptance, B1/B2, or proof credit. The synthetic result is reported separately from the five R19 controls and cannot make their aggregate pass or fail.

The fixture's panic lowering and trace shape remain Cloud-unverified until dispatched through the existing R20 runner. No compiler, verifier, preparation pipeline, or Cloud Build was run for this change.
