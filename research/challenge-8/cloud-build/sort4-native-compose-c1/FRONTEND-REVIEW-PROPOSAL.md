# Exact helper c1 marker: proposed frontend test, before implementation

State: awaiting the second independent targeted semantic review. The first
Cloud Build should capture source, both full typed MIR functions, refinement
and the stock first verifier refusal with the tool unchanged. No semantic
overlay is implemented or accepted by this card.

## Why a new frontend action is needed

The proof source introduces one real Rust helper, `c1_source_prefix`, whose
only fallible runtime operation is the exact pinned SmallSort first comparator
`let c1 = is_less(&*v_base.add(1), &*v_base);`. It is a distinct internal
callable function and has a complete runtime body ending after c1. Its
precondition is `len>=8`, positive T size, complete source array with owners,
current F cell/owner and thread. No destination premise. The generated native
caller has the original safe signature/read-only pointer operations, guarded
diagnostic call of this helper, and intact opaque MaybeUninit scratch frame.

To satisfy both original callback outcomes, source annotations place a
`__vf_c1_compose_unwind` marker immediately before the actual FnMut call.
The source-written blocks specify, in order: close comparison debt inside
the strict `'cmp` scope; recover both borrowed cells after the checked scope
exit; join four CURRENT cells; rejoin the current first four with the
unchanged tail; close the owner foreach; explicitly leak stock T/F type
interpretations; use the original direct `Continue` unwind return. The
normal source annotations execute the same steps after `end_lft_binding`.
Stock translation does not bind this new marker, and ordinary Rust unwind
skips normal ghost steps. The earlier actual-sort4 c1 AST projection is
non-callable and cannot be used as this helper's summary.

## Proposed exact opt-in and trusted delta

Add one opt-in `SORT4_NATIVE_COMPOSE_C1_TEST=1` in the isolated
`/root/verifast-select-sort4-native-20261010` translator patch chain. It
recognizes only `c1_source_prefix` in the exact new proof source and refuses
all other bodies/markers. Its only semantic action is placement of the
source-written unwind ghost continuation on the one compiler-exported direct
Continue edge. It must not manufacture array, owner, comparator, type, lifetime
or destination permissions. It does not alter kernel, parser syntax, memory
or alias model, spec prelude, refiner, original std runtime or the frozen
whole-sort4 contract. Default off retains the current refusal. C2 remains
unbound and mandatory refusal remains untouched.

The first capture supplies the exact verified/original source hashes,
normal/readonly full helper MIR hashes, local declaration/BB inventories and
first refusal. Before enabling transformation, bind those hashes and the
pre-rewrite helper AST hash. Inspect both MIR modes independently for exactly
one `FnMut::call_mut`, ordered source operands 1 then 0, exact generic
`F,(&T,&T)` substitution, normal successor, direct Continue unwind and no
Cleanup/Drop crossing. Require one marker and one strict lifetime binding/cut.
Check source marker order and exact ghost command ASTs. Reject missing,
duplicated or mutated annotation/operand/edge/control container before
modifying the AST. A different source version requires a new admission.

At the one call, preserve the original normal continuation. For direct
unwind, close comparison debt while inside `'cmp`, leave that scope through
the existing checked strict-cut continuation exactly once, then execute the
remaining source-written recovery/join/frame/type-leak blocks and original
unwind return. The helper's normal and unwind contract remains byte-exact.
Any exception path generated by the compiler but not covered by the exact
admission is refused; no dead-code, leak, validity or unwinding check is
disabled. Neither a helper VF0 nor native VF0 accepts this translator rule
as sound without independent profile review.

If ordinary whole-module AST dumping fails at `MergeFractionsStmt`, a
separate capture-only opt-in may print the **same** pre/post helper `Func`
AST object in the translator. This is instrumentation; it cannot replace
full verification or mutate the returned object. A hash of that named AST
and the full verifier trace must be saved with the exact tool snapshot.

## Admission/regression gate

First fresh positive helper and native entry must reach VF0 with both full
normal/direct-unwind posts, returns and leak checks, plus exact source/MIR/
AST linkage. Controls should fail at the intended post/recovery obligation
after helper verification and entry, not parser/setup. Missing normal join,
false normal post and false unwind post are separate cases. Source/MIR
mutants (swapped/duplicated callback operands, wrong lifetime cut, changed
unwind edge, extra call) must refuse before proof. Default-off must preserve
the current marker refusal; prior actual C1 strict controls and C2 unbound
refusal must still hold in affected profiles. Source changes always require
fresh exact-SHA Cloud verification. A failure after the first diagnostic
must be classified, not papered over by weakening the full posts.

If independent review rejects the described trusted delta, continue only
with source/MIR discovery and return the architecture decision to the main
agent. No semantic patch is authorized by the earlier general design review.
