## 1. Решение и фактическая граница

Рекомендуется заменить попытку выбрать единственный Instance для unrestricted T
модульным доказательством общего контракта исходного `StableSmallSortTypeImpl`.
Общий контракт должен быть проверен против default **и** Freeze impl; generic
quicksort использует trait item, а не selected-method redirect. Freeze/Cell/None
наблюдения уже установлены и здесь не исследовались повторно. `None` не становится
разрешением подставить selected summary после исправления binders.

Предлагается отдельное решение владельца о критерии A1: checked trait-contract
dispatch вместо требования получить конкретный Instance для generic T. Это
закрывает содержательное обязательство A1 только после доказанной передачи
threshold/guard в исходный helper и `len + 16`, с source/binding admission.
Буквальное требование старой карточки «выбранный Instance» для unrestricted T
этим способом не выполнено; критерий не переписывается данным пакетом.

Минимальные изменения затрагивают required-item exporter/schema/decoder и
translator: представление method generics и regions; контракт safe required
method; проверку impl conformance; generic trait call. Транспорт RequiredFn
сейчас не содержит F/clauses, поэтому translator-only rename недостаточен.
Это связанные точки, но исправление представления и добавление
контрактов — разные trust obligations. Kernel, layout, alias model, prelude,
refinement checker и std runtime/signatures остаются вне предложения.

Именованные ниже `R`/`R_current` — **обозначения полного существующего native
resource envelope**, не новые opaque predicates/аксиомы. При реализации их надо
развернуть в pinned generated contracts и проверить AST equality. В envelope
входят thread token/currentThread; type interpretations/обязательства FnMut и
FnOnce::Output=bool; собственные lifetime tokens трёх mutable input borrows и
caller reborrow; typed slice metadata; initialized source `array<T>` +
`foreach(..., own<T>(t))`; opaque `array<MaybeUninit<T>>` + MU own; comparator
points-to + `<F>.own`; восстановление borrows, local-free и leak checks.
Это не право одновременно держать owned array и открытый full borrow: array
доступен только через уже проверенный native opening/reclosing protocol.

Контракты в математической форме (не готовый RSSpec синтаксис):

```
threshold<Self>:
  requires native safe envelope (thread token и типовые/trait clauses)
  normal: вернуть весь envelope; 16 <= result <= 32
  unwind: вернуть весь envelope (не unreachable по декларации)

small_sort<Self,F> — bounded base-case theorem:
  requires R(t, kv, ks, kf, v[n], scratch[m], f) && n <= 32
  normal: R_current на тех же slice bases/lengths и borrows;
          initialized current T values + owners; current MU + MU owners;
          current F + owner; все lifetime/thread ресурсы
  unwind: тот же полный R_current на тех же bases/lengths/borrows;
          нет оставшегося comparison/guard debt или утраченного owner
```

`n <= 32` — явная область **ограниченной теоремы real base case**, не новая
runtime precondition и не доказательство safe method для всех длин. Она не
должна заменять/стирать autogenerated safe resource contract. Scope review должен
зафиксировать, как extra pure premise ограниченной теоремы сосуществует с native
safe contract; arbitrary caller не получает summary без этой premise. Если
frontend может поддержать только безусловный safe контракт, сначала требуется
более общая proof method, а не молчаливое добавление bound в safe prototype.
Safety T/F остаётся unrestricted, comparator может мутировать допустимое shared
state и panic. Ни Freeze, ни Copy, purity, sizeof(T)>0, sortedness/order premise
не входят в общий интерфейс. `R_current` допускает актуальные значения после
callback; равенство входным T/F значениям не постулируется. Scratch у полной
small_sort может содержать другие MU bytes после копирований, поэтому его
**владение и validity** восстанавливаются, а не обещается неизменность bytes.
Permutation/sortedness — отдельное функциональное обязательство с собственными
premises; этот интерфейс его не заменяет и прежние функциональные результаты
не ослабляет.

`m >= 48` не требуется для safety при допустимом abort. Для теоремы отсутствия
abort в helper добавляется доказанное caller capacity `m >= 48`; более точная
достаточная premise — `n < 2 || m >= n + 16`. Не выводить её из T/Freeze.

| Исполнитель | Что обязан доказать, прежде чем summary доступен |
| --- | --- |
| Default threshold | actual return `SMALL_SORT_FALLBACK_THRESHOLD = 16`, весь normal/unwind envelope; чистый результат внутри общего диапазона |
| Freeze threshold | actual return `SMALL_SORT_GENERAL_THRESHOLD = 32`, тот же общий контракт; Freeze используется только внутри проверяемой impl |
| Default small_sort | из общего `R,n<=32`: `n<2` возвращает R; иначе actual insertion с offset=1 получает `1<=n`, full callback/normal/unwind resources. Нужен проверенный actual insertion callee той же версии; его наличие не предполагается. Самостоятельную R5 не ограничивать 32 |
| Freeze small_sort | из **того же** R,n<=32 вызывает actual helper с теми же mutable slices/F; impl-specific Freeze clause из impl header, не из generic caller. Проверить helper body/используемые actual summaries и все выходы до допуска полной small_sort summary |
| Generic quicksort | native input borrows дают R; вызывается trait threshold; actual `n <= result` + `result<=32` дают n<=32; те же v/scratch/F передаются trait small_sort. Ни literal32 вместо вызова, ни заранее supplied n<=32, ни selected Instance |
| Helper entry | n<=32 получен через проверенный impl interface. После n<2 return вычисление n+16: `n+16<=48<=usize::MAX` для pinned target; arithmetic overflow gate сохранён. При m<n+16 actual abort имеет отдельный nonreturning spec; иначе m>=n+16 получено guard, не assumed |

При `m>=48` caller исключает abort. Источник capacity для полного upstream пути:
stable/mod.rs `driftsort_main`, alloc_len=max(..., SMALL_SORT_GENERAL_SCRATCH_LEN)
и выбранный stack/heap scratch (строки 102–128); drift.rs передаёт scratch в
stable_quicksort (118, 206, 209), который вызывает quicksort (255/270);
quicksort recursive/reborrow пути сохраняют длину scratch. Это **статически
прослеженный источник premise, не доказанная цепочка allocation/borrow**.
В первом base-case fixture можно либо проверять conditional no-abort theorem
с явно названной quicksort capacity premise, либо оставлять actual abort ветвь
допустимой. Нельзя считать capacity уже выведенной из верхнего entrypoint.

Полное соответствие обеих small_sort impl общему resource контракту зависит от
открытых proofs insertion/helper. Закольцовывать это как assumed library summary
нельзя. Для первой проверки dispatch достаточно уже проверенных обеих threshold
impl; остальные интерфейсы должны иметь статус DECLARED/UNPROVED и не
использоваться как доказанные в unrestricted caller.

   erasure в runtime MIR не разрешает erase в proof. Не выключать duplicate

Contract/conformance obligation (отдельный opt-in review):

1. Safe required fn explicit spec сейчас отвергается. Поддержать common spec с
   полным native resource envelope, normal **и** unwind, а не просто удалить
   rejection и вставить пользовательский post как аксиому.
2. Для каждой impl сопоставить trait Self→impl T, method F и input/HRTB binders,
   clauses и result. Trait pre должен обеспечить impl pre; impl normal/unwind
   posts должны обеспечить trait posts. Никакой stronger Freeze/nonzero pre на
   общем item. Impl's собственная Freeze applicability разрешена только при
   проверке specialized body, и не вытекает из общего trait evidence.
3. Обе actual threshold bodies должны быть verified до generic threshold call.
   Для small_sort — обе actual bodies и actual callee summaries до полного
   generic call proof. Unverified prototype не получает credit как body.
4. Generic call остаётся trait-item application с полными args/clauses/regions;
   closed implementation inventory и specialization coverage проверены source
   certificate. Общий post корректен для любой реализации, допустимой исходной
   specialization lattice. Source-specific redirects старого selected rule не
   применяются к этому generic caller; при конфликте opt-ins жёсткий отказ.

Semantic rationale: общий post следует из всех возможных реализаций, а не из
совпадения имён/выбранной диагностики. Soundness критична в variance pre/posts,
binder scope, full FnMut clauses и unwind resources. Review обязан установить,
достаточны ли существующие kernel prototype/body checks для Rust impl mapping;
если нет, изменение kernel не входит в этот пакет — NO-GO/новое решение.

## 5. A2: resource interface первого C1–C4

Existing C1–C4 consumer использует positive sizeof(T), four initialized source
owners и optional-T destination array rights. Actual helper даёт initialized
source array и **opaque MU array**, а cast `scratch.as_mut_ptr() as *mut T` даёт
значение указателя, не destination rights. Guard `n>=8 && !(sizeof(T)<=16 &&
n>=16)` означает `8<=n<16 || sizeof(T)>16`; первая часть включает ZST.
Public `T::IS_ZST` return есть выше, но bridge к sizeof/nonzero ещё не доказан.
Generic quicksort/helper theorem от этого автоматически nonzero не становится.

Рекомендуемый **prefix-only** интерфейс до C5/первого copy:

```
input: native R(source[n], MU scratch[m], F), n>=8;
       actual helper guard/capacity, source 4 initialized logical positions;
       dst pointer = cast MU base (только identity, не T permission)
normal after C4: current initialized source[4] owners + untouched tail;
                EXACT same MU scratch frame/content/owners;
                current comparator owner; full thread/lifetime/reborrow closure
direct unwind at C1,C2,C3,C4: same full resources as above;
                восстановить текущие T/F и все temporary reference debts
```

Не требует typed destination writes: actual C1–C4 до cut не читают и не пишут
dst. Scratch оформляется native MU frame и переносится через каждый callback и
каждую cleanup ветвь; нельзя leak его или заменить `array_<T>`. Сохраняются
проверенные source borrow/recovery протоколы и четырёхвыходная структура cleanup.
Normal результаты comparator могут различаться; source/F posts — CURRENT, не
входные snapshot. За пределами prefix нужна другая post: C5/copies действительно
пишут scratch, и scratch contents больше не обязаны совпадать.

**Пока этот интерфейс не получается для полного unrestricted domain в frozen
модели.** Для nonzero T устранение unused destination-T pre в отдельной prefix
теореме выглядит proof-local, но требует новой проверки actual C1–C4 с полными
posts; старый PASS не переносится. Для ZST текущие `split_four_owned_cells` и
`split_selected_four` раскладывают array на `*(base+i)` и создают две shared
references по независимым owners. При sizeof(T)=0 адреса совпадают; обоснование
такого split/borrow нельзя получить старой nonzero леммой или pointer equality.
Нужен либо уже существующий достаточный ZST protocol в frozen model с доказанной
применимостью, либо отдельный trust decision. Это не входит в первый эксперимент.
Это отсутствие доказанной применимости текущего protocol, не доказательство
невозможности ZST verification в модели вообще.
MU→T bridge и Freeze/nonzero в исходный caller не предлагаются. Поэтому A2
остаётся OPEN даже при успехе binder/threshold этапа; C5/copies/secondcall/sort8
и qualification профиля остаются отдельно.
