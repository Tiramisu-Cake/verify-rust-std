# R13 S2 canonical-target routing review

## Decision

**Conditional GO; one reporting-integrity fix is recommended before relying on `proof_attempted` for an interrupted probe.** I found no path for the mini-probe result to substitute for the canonical helper/caller receipt or matrix admission.

The R13 mode guard is fail-closed: the runner requires `reference_own_preflight_enabled`; `reference-own-probe` is accepted only for R13; the probe itself accepts only `reference-own-probe`, `native-p1-target`, or `full-matrix`; and a bounded native target requires a supported authorization. I ran a focused synthetic `preflight_plan` check for those three R13 modes and rejection of wrong authorization/unknown mode.

The runner starts canonical stages only when the pinned seven-variant probe returns a mapping with `passed is True`. Probe-only mode always returns after recording the result; missing, exceptional, partial, or failed results also return non-admitting with canonical rows marked NOT_RUN. The probe result is retained as diagnostic data and is not passed as the helper receipt. Canonical work proceeds through the existing positive receipt stage and its same-Build exact source pair before P0c. R13 alone skips execution of the redundant R12 grammar variants; the R12 condition remains intact. S1’s saved reader result and its historical `passed=false` record remain untouched.

## Finding

- **Reporting accuracy, medium:** The R13 return computes `proof_attempted` only from a returned per-variant `stage.exit` integer ([a1-runner.py](a1-runner.py:3308)). The probe catches exceptions from `c4.stage` and records only `error_type`/`error` when the call raises ([a1-reference-own-probe.py](a1-reference-own-probe.py:139)). The pinned `selected-runtime.stage` can run the verifier, persist the terminal per-stage JSON, then raise while saving the separate `stage-progress.json` ([selected-runtime.py](selected-runtime.py:161)). In that case the probe row has no returned `stage` object and the outer result can report `proof_attempted=false` despite the on-disk terminal stage record. This does not admit proof or continue canonical execution, but it can misstate whether the probe actually ran. Preserve a type-checked terminal stage record when available, or report the aggregate as unknown when a started stage threw; add a synthetic “terminal stage saved, telemetry save raises” control. Likewise, `diagnostic_complete` currently checks only that seven variant keys exist, so an exception row counts as complete; consider requiring each row to have a classified terminal stage if that field means all diagnostics completed.

Passed the four synthetic reference-own probe tests, four runner lifecycle tests, four R13 registration tests, Python compilation, and the focused R13 mode-authorization check. The saved S1 reader record gives the exact lifetime refusal with the persistent-coefficient prefix; the corrected expected spelling matches it and the regression test rejects altered lifetime/resource spellings. No compiler, preparer, verifier, full runner, Cloud Build, or raw evidence was used.
