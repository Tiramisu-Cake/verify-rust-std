## Разделение изменений и admission

**R — representation/transport**: required-item schema/exporter/decoder и
translator получают полную compiler-derived информацию. Для literal original
trait нужен F и distinct input lifetime ids, same identities в Ty/clause/substs,
nested HRTB scope и clause validity. Нельзя hardcode число три/имена `__35/36/37`
как общую semantic норму; closed original interface certificate может требовать
ровно три input references, но идентичности берутся из exporter. Синтетические
mutations проверяют representation validation; fresh paired source/compiler
evidence и refiner остаются обязательны для actual proof.

**C — contracts/conformance**: annotations safe required method получают
проверяемый общий spec; native safe envelope и scoped pure theorem premise
согласованы явно. Existing `EnsuresAsn` hook структурно переносит post, включая
fn_outcome; это **не доказательство**, что bad impl будет отвергнута или правильный
generic caller может post употребить. Требуются proof положительных actual
threshold impl и отрицательных каждой impl; при P2 — actual small_sort bodies
с actual callees. Изменение clause matcher без conformance gates недопустимо.

Три списка `[]` в `gen_contract` не надо механически заполнять произвольными
clauses: types/drop/subtype/outlives трактуются существующим body generation
путём. Изменение должно использовать эти существующие semantic categories и
полученные compiler clauses; неизвестная clause/scope — refusal, не игнорирование.

Отдельный conformance риск уже виден в source: имя impl prototype строится из
строки `self_ty`, а Self заменяется `StructType(self_ty,[])`. Для двух generic
impl с Self=T печатная строка `<T as StableSmallSortTypeImpl>::method` сама по
себе не различает default и Freeze. Проверять надо каждый compiler impl/item
identity и source span/clauses, не объединять bodies/prototypes по этой строке.
Generic Self→T substitution должна сохранять именно type parameter T и impl
generics, не превращать его в concrete struct с именем T. Новый transport обязан
дать необходимую identity информацию; если экспортированное имя DefId тоже
display-only, дополняется scoped item identity, а не выбирается первая запись.

**G — generic call**: contract prototype именует original trait item; summary
доступен только после both-impl proofs при closed original inventory. Compile
query `None` остаётся корректным наблюдением; generic resolution и clauses не
подменяются source-specific selected-binding flags. Evidence должен различать
trait-call post consumption и concrete impl call observations. No flag может
утверждать verified both-impl merely because compiler export/refinement passed.

## Trust boundary и нерешённые вопросы

Получается минимальная область **exporter/schema/decoder + translator**, а не
только правка strings в translator. Это новая граница транспортировки trusted
compiler evidence; она должна быть явно включена владельцем в allowlist до
реализации. Существующий compiler-selected-instance observation patch не даёт
такого разрешения. Scope не включает все traits, новые layout rules или model
of specialization в kernel. Narrow opt-in: только source-certified actual
StableSmallSortTypeImpl и проверенный diagnostic observer; OFF поведение
сохраняется, mixed/unknown flags refuse.

Первый review вопрос: достаточно ли existing prototype/EnsuresAsn mechanics для
точного generic impl correspondence с full FnMut clauses и обеими outcome arms?
Если не хватает translator adaptation и нужен kernel rule, данный experiment
NO-GO до нового решения. Второй: как ограниченный n<=32 theorem оформляется рядом
с autogenerated safe contract без потери safety-domain или assumption injection?
Первый Build проверяет threshold contract (bound в small_sort pre не вводит),
поэтому не маскирует этот нерешённый вопрос зелёным target caller proof.

Последовательность review до реализации: owner scope decision → select-sort4
patch/semantic rationale → maintainer code review of R/C/G → frozen profile/pins
и regression admission → один отдельно authorized exact-SHA Cloud experiment.
Сам пакет не выполняет ни одного из этих approval/implementation шагов.
