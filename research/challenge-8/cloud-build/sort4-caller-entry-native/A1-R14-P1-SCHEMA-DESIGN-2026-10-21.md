# R14 P1 producer/consumer schema rationale

The P1 gate is a structural interface observation only. It establishes neither verification of the `small_sort` bodies nor proof credit. Its two native-reference relationships are distinct:

1. The producer validates the required common trait prototype, including its typed header and complete native pre/returning/unwind clauses, against a separately produced R-only native baseline (`normalized_header` and `normalized_native`). It separately validates that each R-only original implementation agrees with that same common interface.
2. For each current compiler-inventoried implementation (`default16` and `freeze32`), the producer binds one AST definition to that implementation's compiler item and source body span, then checks its full header and all three native components against that implementation's own R-only original. This relation is emitted as `native_matches_r_only_original_impl`; `actual_definition_bound_to_compiler_item` records the binding predicate. It is not the common-prototype comparison.

## S1 root cause and identity join

S1 produced six classified rows, one inconclusive P1, and nineteen not-run rows. The P1 classifier reason was `P1 default16 original-impl comparison/compiler identity failed`. The consumer passed `expected_inventory.compiler_item_id`—the `small_sort_threshold` item ID from runtime `structure.bound_impls`—to a gate row whose `compiler_item_id` names `small_sort`. These are distinct methods and distinct compiler item IDs. The prior positive test concealed the defect by deriving `expected_inventory` from P1's own `impl_small_sort_identities` rather than the runner's threshold-bound inventory.

The corrected join preserves both identities without overloading a field. For each exact compiler impl row in `inventory.impls`, the consumer requires exactly one `small_sort_threshold` and one `small_sort` item. It joins the run's expected `compiler_impl_id` and `compiler_item_id` to that row and its named threshold item. Separately, it joins the P1 `impl_small_sort_identities` row to the same impl row and its named `small_sort` item by impl ID, `item_def_index`, `item_def_id`, signature digest, body span, and function-signature span. Finally it checks the producer row's small-sort item ID, generated alias, compiler signature digest, and bound-definition boolean against that P1 identity. The method names and exact two-item cardinality are required; duplicate, missing, extra, swapped, or cross-implementation items fail closed. Thus runtime's threshold IDs remain the independent expected identity while P1's own small-sort ID remains explicitly distinct and source-bound.

The corrected positive fixture derives `expected_inventory` from the compiler inventory's `small_sort_threshold` item, matching the runner shape, while the P1 gate uses the distinct `small_sort` item. Negative tests mutate either method's ID, swap method identities, cross-bind implementations, and remove/duplicate/rename items. Existing source, span, signature, header, native pre/returning/unwind, pair, run-pin, and non-credit requirements remain unchanged.

The current producer output is `a1-small-sort-interface-observation-v1`. The consumer's `native_matches_r_only_baseline` spelling does not occur in that schema. A compatibility fallback would conflate the two relationships and allow an obsolete or ambiguous record to pass. The consumer must instead require the exact producer schema, exact `default16`/`freeze32` row set, literal boolean `True` for each required gate, the run's expected compiler impl and `small_sort_threshold` item identities, and a distinct `small_sort` item identity joined through the same named compiler impl row. It also requires a well-formed unique numeric implementation alias and rejects missing, null, false, wrong-typed, extra/legacy-key, duplicated, or identity-mismatched fields. It binds the gate's source-pair identity/hash to the current raw observation and requires an exact top-level five-key `run_identity` (`tool_id`, `profile_id`, `proof_id`, `infra_id`, `target_id`) that equals the invocation's `run_pins`; the runner constructs that record from the same Build's verified tool receipts and active profile/proof/infra/target. The classifier rejects missing, extra, malformed, stale, or mismatched identity values. The existing producer still owns the AST-derived header/native/span checks; the consumer does not infer them from a positive boolean or grant body/proof credit.

Testing uses `test_a1_ast_gates.p1_fixture()` and its actual `small_sort_interface(...)` producer result, paired with the current synthetic P1 observation, source-pair, and expected compiler inventory. Positive coverage passes the emitted record through `classify_case`. Negative coverage mutates the producer output/schema and independently mutates synthetic AST/compiler/source fixtures for common header, implementation header, native pre/normal/unwind, compiler identity/signature, body span, source-pair, and tool/profile/proof/infra/target identity. All should remain INCONCLUSIVE. No local compiler, exporter, decoder, refiner, verifier, or full runner is invoked.
