Read-only source review of VeriFast `f76012fb518703b1d98e243ac4f487f16877cfcb`
and the recorded selected-profile translator. This corrects the preliminary

## Existing kernel mechanism

`src/assertions.ml` handles `EnsuresAsn` in both `produce_asn_core_with_post`
(around line 615) and `consume_asn_core_with_post` (around line 1520) by passing
`Some (result_var, body)` to the continuation. It carries a deferred assertion;
it does not produce heap permission.

`src/verifast.ml:4059+`, `check_func_header_compat_core`, checks a function body
against a preceding prototype. It produces the prototype precondition, consumes
the implementation precondition, produces the implementation postcondition,
then consumes the prototype postcondition. If the prototype precondition
contains `EnsuresAsn(result, trait_post)`, the deferred trait post is used for
that final consume. The body therefore has to establish the trait post. The
same compatibility path checks normal and exceptional posts. Prototype assembly
later in `src/verifast.ml` requires the prototype to precede the implementation
and invokes this compatibility check; missing or duplicate implementations
refuse. `src/verify_expr.ml` call checking uses the resulting function
prototype's pre/post contract as its call summary.

The selected-profile translator already places synthesized trait-impl
prototypes before body declarations. Therefore a correctly constructed
per-implementation prototype can use this unchanged kernel mechanism to check
each actual body against a common trait contract. A generic caller can then use
the common trait item contract. This establishes feasibility of the kernel
mechanism, not correctness or admissibility of the current translator route.

## Remaining translator obligations

The current `compute_trait_impl_prototypes` matches by rendered trait item name
and accepts only a required-function AST with `(None, None)` function-type
clauses. It copies generic parameters after dropping `Self`, while body
translation orders impl-block generics before method generics and adds `Self`
for trait functions. The generated prototype must instead match the actual
implementation's generic parameter order and kinds, preserve method `F` and
its clauses, and instantiate trait `Self` as the implementation's generic
`T`. Translating printed `self_ty = "T"` to `Ast.StructType("T", [])` denotes a
concrete struct and is not that substitution. Default and Freeze impl records
must remain distinct by compiler impl/item identity and source span; printed
names alone can collide.

The RequiredFn schema/exporter currently omits method type generics and clauses,
so the translator lacks the input needed for this construction. R must carry
compiler-derived binder identities and clauses through schema, exporter,
generated Cap'n Proto decoder bindings, and translation. The changed exporter
must be built in Cloud and its binary pinned; the ordinary current recipe copies
the stock exporter and enforces byte equality, so that behavior must be
replaced for the A1 lane. No kernel change is presently indicated. A kernel
change is a blocker only if exact generic mapping and full contract conformance
cannot be expressed by translator-built prototypes and existing header
compatibility.

## Current lane integration facts

The authorized lane is `o26-sort4-c1-current-recovery`, routed by
`recipes/o26-sort4-c1-current-recovery.json` through
`run-o26-sort4-c1-current-recovery.sh` and
`run-sort4-c1-current-recovery.sh` to the caller-entry driver. The proof recipe
uses exact-recipe-v1; every added fixture, profile, patch, source manifest, and
runner dependency must be listed in `proof_paths`, and every changed executable
runner/recipe dependency in `infra_paths`.

Its existing rebuild path clones pinned VeriFast 26.10 commit
`f76012fb518703b1d98e243ac4f487f16877cfcb`, applies the 20 O26 profile patches,
installs the pinned decoder generator, and builds the console. The selected
driver copies that production tree, applies strict-lifetime, ten C4, native C1,
ZST-size, and dead-code identity patches, then separately rebuilds the console
at its profile gates. The schema is generated by the `vf_mir_decoder/dune`
rule from `vf_mir.capnp` during the console build. Existing code already
demonstrates the exporter rebuild target:
`make -C src build-vf-rust-mir-exporter WITHOUT_LABLGTK=yes VERBOSE=yes` in
`compiler-query.py`; the current refresh path instead copies and compares the
stock exporter binary.

An A1 route therefore needs a new phase ID in lane/driver admission, A1
source/schema/exporter/translator changes applied after the frozen profile
reconstruction, an exporter rebuild plus a console rebuild after schema and
translator edits, source/binary hashes for both products, paired normal and
readonly exports and refinement, and the planned positive/negative matrix.
Do not let an older `SORT4_SELECTED_COMPILER_BINDING_VERIFIED` flag or selected
binding patch redirect the A1 generic call; preserve the trait-item call.

The A1 budget card allows one build, 960 conservative Cloud seconds, with a
900-second maximum Build timeout. Existing build stages each cap individual
builds at 900 seconds, while the lane has download, setup, source/export,
decode, refinement, and proof stages in addition. The current source does not
establish that the full A1 matrix fits 900 seconds; exporter recompilation and
full matrices need a narrowed first-run plan or updated time estimate before
dispatch. This is a budget feasibility concern, not permission for a second
build.
