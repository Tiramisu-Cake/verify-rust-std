# R15 S3 candidate rationale — all-four c1 recovery

S1 exact sort4 reached the source-owned unwind post and failed on missing array ownership. S2 isolates the current-owner recovery and four-cell join dependencies. The c1 hook keeps the complete runtime body, all five `FnMut` calls, all selection hints, and all four copies byte-identical after ghost stripping. It changes only the c1 ghost path on the existing normal edge and direct-unwind edge; it does not skip cleanup or alter a successor.

Before c1, the source splits the four-cell owner into four current cell owners. The hook closes and borrows each cell's full-borrow content for the same `cmp_k`, then shares each borrow. `comparison_debt<T>` carries both reference debts for c1 and one `borrow_end_token` for each of the four cells. The c1 recovery closes and merges the two reference fractions, ends `cmp_k`, borrows back each of the four current cell owners with `borrow_end`/`open_full_borrow_content`, then calls the checked `join_four_owned_cells<T>` helper. No third or fourth owner/value is saved across the generic `FnMut` call, and no pre-call owner is reused. The helper adds no alias, `Freeze`, pointer, or owner assumptions.

The generated dependency sequence is `interior_pointer_limits`, `split_four_owned_cells`, `join_four_owned_cells`, `recover_pair`. The old two-cell `recover_pair` block in the recovery fixture is excluded from the generated target; the constructor emits the all-four wrapper instead. The fixture's reserved-lifetime-half negative remains a focused recovery precondition control. A missing fourth end-token is structurally excluded by the all-four debt predicate and should be included as a separate negative when the recovery-case runner can bind and classify that exact failed call. A false-old-value postcondition is not a sound control for this design: it would require retaining or constraining old generic `T` values across `FnMut`, contrary to the no-saved-values contract and potentially adding a `Copy`/`Freeze`-like assumption. Current-owner recovery is the intended postcondition.

The callback recovery is source- and call-line-bound. The existing strict lifetime scope ends `cmp_k` immediately after c1 on the normal path; the same checked four-cell recovery runs on that path and in the direct-unwind epilogue. The exact source/MIR pair, refinement relation, AST/body/resource receipts, helper checks, and tool pins remain required. This candidate is not a completed sort4 theorem, a callee summary, or proof credit.
