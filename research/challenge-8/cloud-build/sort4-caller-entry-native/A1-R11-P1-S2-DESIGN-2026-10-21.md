## Rationale and implementation boundary

Accept only the two complete observed/source-backed parameter-name tuples:
`("v", "scratch", "is_less")` and `("v", "_scratch", "is_less")`. Do not
rename names in the parsed AST, normalized full header, native precondition or
posts. `_small_sort_ast_signature` still decodes parameter types by position;
compiler signature checks continue to bind their types and positional regions.
The raw parameter names remain in `_small_sort_ast_header`, so candidate to
R-only equality rejects a body whose binding spelling changed. A separate
comparison-only header projection substitutes a marker for the second name
when comparing the common trait prototype with an impl body; it leaves all
stored headers untouched. This is necessary because the source intentionally
uses both names across the prototype and impl bodies. Candidate impls are still
compared against the exact same-item R-only header before the common-to-impl
projection is checked. Existing compiler numeric impl/item IDs, full source
spans, source-pair checks, same-name body multiplicity, type/lifetime/native
equality and refinement checks are unchanged.

Targeted native-clause fragments establish the same binding spelling inside
the preconditions/posts. The common prototype uses `Var("scratch")` and the
generated fold binder `_v0_scratch`; the default body uses
`Var("_scratch")`, `_v0__scratch` and `_v1__scratch`; the Freeze body uses
`Var("scratch")` and `_v0_scratch`. The same source parameter therefore
causes a second exact native-tree mismatch if compared raw across trait/impl
roles. A comparison-only projection now rewrites only AST `Var` nodes bound to
that record's second parameter and established generated fold `Var`/
`VarPat` names `_v0_<parameter>` and `_v1_<parameter>` to fresh NUL-containing
positional sentinels. It rejects unknown generated indices and fold names
without both binding and use. The raw native trees and their per-body hashes
remain stored unchanged; candidate-to-same-R-only-body native comparison is
still exact. Predicate/resource names, type and lifetime nodes, reference
permissions, and every other native AST field remain compared verbatim.

## Controls

- Positive: each complete observed tuple is accepted and normalizes to the
  same positional type signature.
- Representation: raw normalized headers for the two tuples remain distinct.
- Cross-role: comparison-only projection equates the two source spellings while
  preserving all parameter types and the raw stored headers. Native projection
  is limited to the parameter Var and validated fold binder AST constructors;
  synthetic resource, type, and region mutations remain distinct.
- Negative: reordered names and any third spelling are refused.
- Cross-input binding: candidate `scratch` to R-only `_scratch` drift for the
  same compiler-bound body is refused by the full-header and raw-native
  equality gates. Unknown, unbound, or unused generated-fold names are refused.
- Existing checks retain numeric compiler identities, distinct full spans,
  type/reference/region matching, native posts, and zero/multiple/unbound
  rejection.
