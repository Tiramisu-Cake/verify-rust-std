# Select-R11 P1 local-name investigation

## Defect and applicability

Build `205ff994-63f2-415b-abbe-f5f16858d751` reports the P1 source observation
`AstGateError: package Func local name` in the R10 S4 target record. The Build
Brief reports `VERIFIED_ARCHIVE_AND_INVENTORY`, while the source verdict is
`NOT_ACCEPTED_AS_REPORTED`; this observation is not proof credit and does not
establish parser-input binding or causality.

The source gate rejects a packaged `Func` unless field 4 parses as a nonempty
string without `::`, then forms its canonical name by prefixing the enclosing
`PackageDecl` owner. Targeted Evidence v0.11 reads establish two emitted
representations in the R-only AST:

- Focus/P1 `proof-ast.ml`, file ID
  `f34176aafa5725e56120787ba0805cd8976adb1101e92775fee8b655dc1b1287`,
  SHA-256 `0a3e157e363c5cdd57a93699ce33526c361490ac9d15c8672c1f55b6f7699f9b`:
  line 93 has root-package local
  `__a1_impl_18_item_20_small_sort_threshold`; lines 3–4 show owner
  `StableSmallSortTypeImpl` and local `small_sort_threshold`; line 11 shows
  local `small_sort`.
- R-only P1 `r-only-native-reference-ast.ml`, file ID
  `241e38dedc8346d7fa96c58a11783b207ae082e6bab68ab831f08de28e0e8330`,
  SHA-256 `19f8ec9ecb14cd223b2088269d4efdd65fdd479ba55c4a6670db773bbb19cdcd`:
  lines 93–101 show owner `<T as StableSmallSortTypeImpl>` and ordinary local
  names `small_sort_threshold` and `small_sort` for source declarations.
  Separately, lines 272–273 show an empty root package and a `Func` local field
  exactly equal to `<T as StableSmallSortTypeImpl>::small_sort_threshold`;
  lines 282 and 398 contain the same root-qualified local
  `<T as StableSmallSortTypeImpl>::small_sort` at distinct source spans. The
  exact local therefore carries the canonical owner and method together.

The root-qualified `Func` local is the exact representation rejected by the
gate's `"::" not in local` check. This is directly applicable to the reported
P1 error. Reader metadata explicitly says `parser_input_binding:
NOT_ESTABLISHED`, so the observation does not prove that this exact source
record caused the run failure. The repair is limited to accepting these two
known canonical full names when the enclosing package owner is empty; retain
the full field verbatim as the canonical identity. Do not strip a prefix or
apply it a second time.

## Rationale and implementation boundary

Keep package owner and local function name as separate identity components for
ordinary locals. For the two observed canonical qualified names, the `Func`
field itself is the complete identity and the root package must be empty. Reject
qualified fields under nonempty owners, every other qualified spelling, and
leaves that merely resemble the target method. Preserve duplicate
`<T as StableSmallSortTypeImpl>::small_sort` records as separate rows; downstream
selection still requires unique compiler identities and full source spans.

## Required controls for any follow-up fix

- Positive: root-qualified canonical threshold and small_sort names; ordinary
  owner plus bare local; root-package compiler alias; repeated package chunks.
- Identity: same leaf under different owners remains distinct; duplicate
  same-owner names remain separate records; prototype and definition stay
  distinct.
- Fail closed: zero selected bodies, multiple selected bodies, unbound
  candidates, malformed or empty local field, unsupported qualification, and
  a qualified local under a nonempty or unrelated owner all raise
  `AstGateError`.
- Binding invariants: retain native AST fields, numeric compiler `impl`/`item`
  identities, complete source spans, source-pair and compiler-item bindings,
  and all type/lifetime/native contract and equality/refinement checks. Never
  select first/last by order or leaf name.

## R11 S1: outer parameter binding marker

S1 Build `ec83aeb7-b15f-4bde-a95d-ccf7e1b58100` is terminal `FAILURE`; its
Brief reports `VERIFIED_ARCHIVE_AND_INVENTORY`, source report
`NOT_ACCEPTED_AS_REPORTED`, source/package `SUCCESS`, target exit 26, five
intended cases, two inconclusive cases, and 19 `NOT_RUN`. The P1 observation
reports `AstGateError: unsupported small_sort AST signature type
ConstTypeExpr`. These are runner/source observations, not formal verification
or proof credit; P0a adapter failure is the wrapper blocker and stage
causality remains `UNKNOWN`.

The exact error matches the AST gate: `_ast_ty` rejects unknown type-node
constructors, while `_small_sort_ast_signature` currently sends each parameter
node directly to it. Targeted R-only AST fragments show the canonical
root-qualified `small_sort` Func at lines 282–284 and a second same-name Func
at lines 398–401. In both, each parameter's outer node is
`ConstTypeExpr(loc, RustRefTypeExpr(...))`; the reference mutability, region,
referent and source locations remain inside it. The second Func has a distinct
source span. The translator notes in `PREPARED-PHASE-2026-10-06.md` identify
`ConstTypeExpr` as the representation of an immutable MIR local; that explains
why it can surround a parameter binding without changing the Rust reference
type. This supports only a signature-boundary normalization, not dropping
nested constness or reference/lifetime information.

Applicability is concrete at the failure-string/type-constructor level, but
still not causal proof: the Reader marks AST `parser_input_binding:
NOT_ESTABLISHED`, and the source gate diagnostic does not identify its exact
record. Accordingly, `_small_sort_ast_signature` now accepts either the
already-supported bare type or exactly one valid outer `ConstTypeExpr`, then
decodes the inner type with the existing strict decoder. It rejects nested or
malformed wrappers. The raw Func fields remain untouched; the existing
normalized header includes the full raw parameter field, while compiler type
joining uses the unwrapped Rust type. The gate therefore retains AST and
source/compiler identity, numeric impl/item IDs, full spans, duplicate
same-name bodies, and all inner ref mutability, region, ADT and type checks.

### S1 controls

The synthetic gate test accepts both bare Rust parameter types and one outer
located `ConstTypeExpr`, verifies the normalized compiler-facing type is
unchanged, and verifies the normalized header still distinguishes the raw
wrapper. It rejects nested wrappers and wrappers without a valid source
location. Existing tests continue to require exact parameter order/type,
regions, mutable references, `MaybeUninit`, compiler item/impl identities,
full source spans, and separate same-name bodies. This is a bounded parser
repair only; it does not alter source declarations, compiler/profile pins,
proof scope, transport or ledger records.
