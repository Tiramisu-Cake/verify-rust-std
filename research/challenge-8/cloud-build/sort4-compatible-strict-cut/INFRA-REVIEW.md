## Blocking implementation defect

`install_two_file_patch()` checks `git -C tool diff --name-only` after applying the candidate and requires **only** translator and `src/verifast.ml`. The copied O26+slice production tool already has a nonempty Git diff. The corresponding native-compose production worktree has `bin/rust/std/lib.rsspec` and `rust_parser.ml` modified as well as the translator. Thus the new check deterministically rejects a correctly patched tool before the isolated build. Capture the pre-apply changed-file set and require the post-apply set to equal that set plus `src/verifast.ml` (translator is already modified); also compare before/after content hashes for all files outside the two-file allowlist. Keep the canonical production applied diff and result SHA checks. Do not relax the two-file patch header allowlist.

## Admission and evidence gaps after that repair

- Marker-bearing strict-OFF uses the right explicit translator refusal text and requires no target proof entry, distinct from ordinary no-marker/default-OFF VF0. The classifier currently accepts that text anywhere in the log even if an unrelated error came first. Require it as the first relevant refusal with the marker source location and no earlier setup/frontend error.
- Both normal and readonly complete target MIR records are saved with fresh hashes and refinement is run. The driver records the number of direct-Continue edges but does not require the expected count, target marker/block coordinates, full successor/cleanup shape or identical reviewed CFG identities. The later native helper gate must additionally check the callback source cells 1 then 0; these small fixtures contain no such callback. Hash recording is evidence, not a source/MIR admission pin. Add exact expected shapes/hashes after the fresh capture is reviewed; a changed source/tool must get a new capture and review.
- The AST hook emits `strict-cut-pre-proof-ast.ml` after translation and before target VCs internally. The driver validates its token, existence and hash only **after the same verifier invocation** has run. For a mandatory pre-proof AST admission gate, use a capture-only refusal/diagnostic invocation, inspect and pin the complete fresh AST, then run the proof pass against that exact source/tool. The old Build4 AST hash `64c015...` must not be reused.
- `positive_basic`, early return, direct unwind and outgoing goto are attempted. The driver reports only `POSITIVE_VF0_CANDIDATE_PENDING_REVIEW`; it does not establish full native helper posts or exact path-level allocation/free effects. `positive_direct_unwind` also needs a checked direct-Continue edge and target unwind return, not merely a verifier zero-exit.
- The live `close live::<'cmp,T>()` heap case is a concrete strict escape candidate. Negative cases currently receive only `NEGATIVE_DIAGNOSTIC_PENDING_RAW_REVIEW` from target entry before some error. Require the first error's exact source/VC/predicate to be `A lifetime-scoped heap chunk is still live at the binding end` for heap credit; setup/refinement/other helper failure is inconclusive. `negative_type_after_cut` similarly needs exact first-VC attribution.
- The outer-variable fixture uses ghost `'cmp` in a Rust type declared *inside* the block; it neither establishes a surviving outer variable nor reliably compiles. The outer-bound fixture only asserts `type_interp::<&'cmp T>()`; it does not register a projection equality in `tparam_bounds_table`. The driver correctly marks both `NOT_RUN`, but `negative_outer_type_escape` is also listed in `NEGATIVE`, so `core_subset_passed` is structurally false. Remove it from that candidate set while retaining the explicit required `NOT_RUN` gate. Future source forms need to reach `A lifetime-scoped local type escapes the binding` and `A lifetime-scoped type escaped into current outer bound metadata` respectively.
- Wrong and duplicate marker cases are executed as `DIAGNOSTIC_ONLY`; no required first admission refusal is checked. Keep them distinct from semantic escape negatives, but require their exact translator refusal before target proof. Missing debt/owner, inferred aliases and unresolved/cyclic bounds, wrong CFG ingress/re-entry, allocation/free mutation, frozen C1/C2 unbound refusals, stock pointer-add lowering and production regressions remain explicitly `NOT_RUN`. This correctly prevents acceptance; none may be inferred from a green CUT fixture.

A further substantive risk belongs to the proof, not transport: the new current-outer-bound check inspects the first `tparam_bounds_table` entry for each outer parameter before rebasing. A scoped HRTB `FnOnce::Output = bool` equality on `F` whose tuple includes `&'cmp T` could therefore be a genuine escape refusal at the helper cut. The fixture and native helper must show whether that metadata is still live. If so, repair the source/resource protocol or obtain a separately reviewed semantic decision; do not hide the bound through early rebase. The exact two-file patch remains an experimental candidate, and previous C3/C4 conditional results retain their own profiles and verdicts.
