## Constructive general-key transfer now checked

Each original occurrence has a distinct ID. On arbitrary immutable keys, define
rel(i,j)=key_i<key_j for a chosen fixed strict weak order. The finite pullback
requires irreflexivity, strict transitivity and transitive incomparability over
all original occurrences; equal/identical keys may belong to different IDs.

`swo_rank(rel,d,i)` counts ORIGINAL occurrences z with rel(z,i). This weights
classes by their sizes, so ranks may have gaps. The checked generic bodies use
finite-law extraction and structural list/count induction: equivalent keys have
equal predecessor sets/counts; strict comparison gives a predecessor subset and
x itself witnesses strict count growth. Thus rel(x,y) iff rank(x)<rank(y),
equivalence iff equal rank, and0<=rank<length(d), without an embedding axiom.
R9f additionally checks `swo_ordered_pair`, projecting rank<= to !rel(right,left)
while keeping the full bridge's equality/bound facts inside its small context.
[Phase2 results](RANK-RESULTS.md) and [journal](RANK-EXPERIMENT-LOG.md) identify
the accepted bodies/source/tool/artifacts and remaining N13 gate.

The original phase1 written class-enumeration transfer is superseded for the
embedding by this constructive machine proof. Pure rel represents keys; the
functional application still requires preservation of every key and this order,
each comparator call returning normally with exactly rel(current_right,current_left),
and actual helper realization of token exchange. Non-key effects need not vanish.
No Copy/Freeze or stability premise is introduced. Proving those Rust applicability
requirements is outside this mathematical phase.

## Connection to the accepted integer-rank networks

Each admitted source CE uses rel(right,left). The checked local CE bridge states
that selected IDs stay in the original domain, preserve the count of every
arbitrary token q and have min/max predecessor ranks. Generated composition
checks these posts and ID/rank wire equality at every exact source step.
It includes the SAME previously accepted integer-rank proof bodies and verifies
them in the same unit before using their summaries.

The integer theorem follows a checked threshold transfer: h_t(x) is x>t,
h_t(min(a,b))=h_t(a)&&h_t(b), h_t(max(a,b))=h_t(a)||h_t(b). Exact-network
composition commutes with this projection. An inverted adjacent rank pair x>y
would produce true,false at t=y, contradicting the verified Boolean theorem.
Final rank<= therefore projects through the checked order bridge to every
adjacent key-order post. All-pairs key order follows mathematically from rank
correspondence and integer transitivity; it is not separately enumerated in
the exported machine post.

IDs each occurs exactly once, including when keys tie. This is identity
permutation; entry-value snapshot permutation additionally requires preservation
