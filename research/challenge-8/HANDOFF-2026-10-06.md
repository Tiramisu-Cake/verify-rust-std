## Что остаётся недоказанным

Шесть оставшихся публичных safety targets не имеют полного доказательства
для произвольных допустимых slices. Для всех трёх `small_sort` sorting contracts
нет. `sort4_stable`, generic swap, merge/scratch, dispatch/specialization,
произвольные длины и полная integration остаются открытыми;
[coverage ledger](coverage.md) — перечень требований.

Для generic insertion открыты compiler cleanup reuse, release held_ref до
tmpfree на normal/panic путях, ресурсные exit posts, generic loop invariants,
permutation/sortedness, termination и actual outer caller. В37417173472
проверка остановилась в ветке `sift == begin` на требовании
`CopyOnDrop.own` у generic `drop_in_place`. Второе сравнение и полный normal
return не проверены; по trace до первой ошибки нельзя считать доказанными
все альтернативные ветки, включая early return после первого сравнения.

Текущее `COMPARISON_DEBT_POST` в insertion extractor — частичный диагностический
post на normal/unwind. После strict cut долги первого сравнения уже погашены,
поэтому этот post не подходит для завершённого normal proof. Даже исправленный
Drop может сразу упереться в этот post, раньше второго сравнения.
**Не заменять его на `ens true` и не выдавать пересечение Drop за proof функции.**

Прямой Drop contract не заменяет generic MIR `drop_in_place` summary:
последний не раскрывает эффекты на dst. Также возвращённая доля src не
восстанавливает всю ячейку tmp автоматически. Для ZST не вводился явный
non-ZST bound, но пригодность array/alias модели для всех допустимых ZST
callers ещё надо проверить; отсутствие такого bound не заменяет этот анализ.

Требуемые UB checks тоже не закрыты. Kani0.67 допускает наблюдаемую запись9
в immutable static в37397720683; это измеренный detector gap, не доказательство
immutability. Actual insertion с validity instrumentation в37396688760 имеет
1/469 failed property — UnsupportedCheck для CopyNonOverlapping, хотя 7/7
covers проходят. Не отключать validity/immutable controls ради green badge.
Outer-invariant run37390973809 завершился SIGTERM143 с nondeterministic
argument-substitution warnings и без итоговых properties/covers.
Подробности: [UB measurements](ub-checks.md),
[outer diagnostic](outer-invariant-diagnostic.md).

## Текущая незавершённая реализация

Новый профиль `tuple_local_drop` реализует restricted bare-local MIR Drop call
к явно аннотированному actual Drop method в том же unit. Проверяются ADT,
substitutions, sole T:Sized impl predicate, impl/body identity, три trivial
поля rawptr/rawptr/usize, non-unwind contract и normal/unwind CFG.
Новые own/chunks/tokens не создаются. Projected places оставлены на generic
baseline как явный non-goal. Точность late-bound lifetime `&mut self` важна:
callee принимает impl T и inferred self lifetime.

Код прошёл статическое review, включая независимое review Astra; это не
формальная гарантия корректности расширения. [Caller gate](verifast-drop-caller-gate.md)
содержит direct actual Drop proof, прежние25 регрессий и9 fixtures:
normal и FnMut() callback-unwind positives; missing src/dst/T.own,
unannotated Drop, broken actual Drop post, extra field и Copy-bound negatives.
**Они подготовлены, но caller fixtures ещё не исполнялись.**

В37423344712 build остановился на unbound item.def_id; explicit
`D.trait_impl_item` annotation исправлена. Последний запуск
[37423762729](https://github.com/Tiramisu-Cake/verify-rust-std/actions/runs/37423762729)

## Где я зациклился или мог выбрать плохой путь

**Я слишком долго исправлял следующий локальный отказ вместо пересмотра
полной ресурсной истории insertion.** Переход был осмыслен: Kani обнаружил
конкретные limitations, затем generic VeriFast probe продвинулся. Но после
tuple → HRTB → lifetime cut → address bookkeeping → ManuallyDrop refs → Drop
изменений предмет работы заметно сместился от std contract к собственному
frontend/kernel. Локальный прогресс не гарантирует, что эта цепочка доведёт
до полного generic proof. Нужен отдельный decision review о цене и допустимости
растущего patched verifier и о применимости штатного RustBelt borrow model.

**Lifecycle проблемы могли быть сигналом неверно выбранной proof boundary.**
Strict early lifetime cut потребовал kernel changes, exit checks, metadata
rebasing и много fixtures. Проверки улучшают confidence, но не заменяют
доказательство soundness. Вместо ещё одного hook стоит заново проследить
полный normal/early-return/panic ресурсный путь и понять, нужен ли этот cut
для правильного контракта, а не только для нынешней ghost-разметки.

**Readonly held_ref route может оказаться тупиком для второго сравнения.**
`init_ref_readonly` позволил создать guard и пройти первую физическую shift.
Но generic comparator получает `&tmp` и может использовать interior mutability.
Нельзя продолжать readonly shortcut через него, вводить Freeze/Copy/purity premise
в safety proof или считать старые values неизменными. Нужен свежий взгляд на
реальный share/reborrow/recovery, включая panic. Для функциональности отдельно
задаются key-preservation/order laws; safety не должна зависеть от них.
Отсутствие ignore flags также не доказывает полноту alias checks: pinned
translator уже содержит shortcut для mutable Ref creation. Его роль в полном
доказательстве требуемых UB надо оценить отдельно, не выдавая baseline shortcut
за новый проверенный reference model.

**Я оставил старый COMPARISON_DEBT_POST слишком долго.** Он был полезен для
первого callback-unwind diagnostic, но перестал описывать завершённый normal
путь после успешного cut. Это может породить ещё много механических правок
при неверном конечном контракте. Следующий исследователь должен сначала
написать ledger входных/заимствованных/возвращённых ресурсов по всем exit paths.

**Часть итераций потрачена на мои ошибки инфраструктуры и анализа logs.**
Были неверный tar flag для bzip2 archive с именем .txz, слишком широкий make
target с посторонней C manifest verification, двойной MIR/name counter,
неверная привязка copy trace к началу строки, overwrite уже захэшированного
snapshot, неверное ожидание числа execution records и повтор имени функции
в error context. В latest source patch статическое review пропустило
OCaml typing и nested-match bugs. Это инженерные ошибки, не новые proof
obligations; свежему агенту не надо повторять их investigation.

**Отдельный тупик уже установлен:** попытки transparent tuple2 через RSSPEC
overlay/alias не работали из-за того, как pinned parser создаёт opaque own.
Не повторять перестановку имён/файлов и не добавлять unproved bridge.
Текущая source parser patch решает только canonical tuple2 route.

**Текущий gate тоже нельзя принимать по счётчикам без смыслового чтения.**
Header counters должны исключать `note:` duplicates. Source-span call records
на closing brace могут включать freeze/unfreeze helpers; сами по себе два
records не доказывают два actual destructor calls. Нужно связать actual MIR
normal/cleanup edges, контракт и whole-unit body/caller outcomes. Broken-post
fixture сейчас проверяет callee отдельно; это проверка body failure, не
отдельный эксперимент caller+invalid summary. Анализ оставшихся отрицательных
fixtures следует делать по конкретному missing predicate, не по общему error.

Ни один из этих рисков не является уже установленным доказательством
unsoundness. Это места, где дополнительные зелёные микротесты могут скрыть
неправильную архитектурную границу и где я рекомендую независимый пересмотр.
Независимый свежий read-only обзор Sol подтвердил различие conditional actual
Drop body proof и отсутствующего cleanup/caller proof, отметил тот же риск
наращивания форка и устаревшие standing summaries. Он не выполнял доказательства
и не устанавливает soundness patched verifier.

## Предлагаемый порядок следующих действий

После свежего read-only обзора порядок уточнён в
[пересмотренном плане](REASSESSMENT-2026-10-06.md): полный ресурсный ledger и
decision review идут до дальнейшего расширения verifier. Ниже сохранено
предложение на момент handoff; новый план не возобновляет Actions эксперименты.

1. После явного возобновления исправить только границы nested match. Сохранить
   generic fallback для non-ADT; обновить patch/output pins в builder/runner/docs.
   Разобрать Warning11 и подобные новые warnings, не подавлять их. Static checks,
   push, NEW `verifast_local_drop_caller_gate`,90min. Workflow choice уже exposed.
2. Получить честный green local-cleanup gate: all25, actual Drop body, normal и
   callback-unwind positives, все7 intended negatives, source/refinement/MIR
   evidence. При новом отказе сначала отделить frontend/setup от ресурса;
   не менять pre/post ради ожидаемой классификации.
3. Сделать decision review перед расширением verifier: точная trust boundary,
   admissibility patched tool для challenge, необходимость custom lifetime cut,
   обычный share/reborrow для generic T и альтернативный proof boundary.
   Это можно исследовать локально только чтением; не публиковать вопросы upstream
   без указания владельца. Если подход не выдерживает review, сохранить milestones
   и сменить направление вместо наращивания обходов.
4. Если restricted route остаётся выбранным, проверить отдельный onecell
   actual Drop contract: token+ref_initialized+fractional source и complementary
   origin fraction; после исходного copy ghost `end_ref_readonly(src)` и merge
   возвращают полную physical tmp cell, exact dst и ONE Town. Merge внутри
   проверенного метода нужен потому, что в actual MIR сразу после Drop идут
   StorageDead либо UnwindResume. Это лишь предложение, пока не implementation
   или proof; сначала same-unit normal/unwind fixtures с полным accounting.
5. Вернуться к исходному unrestricted `insert_tail` n>=2/T/F, исправив exit
   resource specification. Зафиксировать прохождение Drop и следующую реальную
   obligation; не уменьшать domain до n2 ради прохождения branch.
   Далее genuine borrow recovery второго сравнения, loop invariant и whole
   normal/panic range restoration. Пересмотреть proof boundary, если это требует
   ещё одной недоказанной axiom или автоматического удаления token.
6. Только после этого переносить callee contract на actual outer loop, затем
   merge/sort4/три specialization targets и functional contracts. Параллельно
   закрыть UB model gaps; bounded i32 результаты не повышать до arbitrary-length
   доказательств.
