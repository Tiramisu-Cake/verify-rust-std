## 1. Резюме

1. **V-2а получает NO_GO, гибрида нет.**
   - На неизменённом VeriFast 26.10 нет поддержки pointer `wrapping_sub`/`wrapping_add` (`smallsort.rs:734–735, 816–817`). Прежний прогон на 26.10 падал с `No such function`.
   - Есть и дополнительные препятствия:
     - нет спеки `usize::is_multiple_of` (строка 820);
     - stock-контракт `copy_nonoverlapping` требует инициализированного `dst`, а scratch не инициализирован;
     - пара аргументов `FnMut` непрозрачна, проверенного stock-примера вызова generic HRTB `FnMut(&T,&T)` без `assume_correct` нет.
   - Форк Merge, даже со всеми патчами, доказал только условную безопасность `merge_up`/`merge_down`. По `bidirectional_merge` на длинах 2–3 итог INCONCLUSIVE, для произвольной длины есть только дизайн.
   - Значит, через upstream слияние тоже не закрыть в обозримый срок. По дереву решений редакции 3 это STOP ветки «Г».
2. **Ошибка редакции 3 (§1.4) признана.** Довод «в слиянии нет конструкций, из-за которых появился форк» был верен буквально, но недостаточен. Я проверил отсутствие блокеров форка, а не наличие поддержки каждой конструкции в stock. Правило на будущее — §7.
3. **Основной путь — решение только на Kani с раскрытием ограничений (ветка «Ч»).**
   - Безопасность — по всем маршрутам, насколько дотянет K-6. Цель — до 32.
   - Корректность:
     - fallback — до 16 (полный порог);
     - network — до 17 (до `len < 18` слияние не вызывается);
     - general и stable-Freeze — до 16 (на сколько хватает формулировки 1 контракта слияния).
   - B4 — семейство постоянных длин до 20.
   - Остальное раскрывается и ведётся в tracking-issue по образцу #656 (Ch12).
4. **Главные опыты сейчас — K-6, K-8 и K-9.** Они нужны при любом исходе. Дополнительно — K-10 (верхние гармоники корректности) и K-11 (B4 до 20). K-3, K-4 и K-5 — без изменений.

## 4. Пакет раскрытия (что PR говорит о себе)

Без него ветка «Ч» не проходит ревью, поэтому это обязательная часть объёма:

2. **Ограничение по длине для корректности маршрутов со слиянием (17..32) и для B4.** Указываются:
   - числа K-1: рост ×3,2 на +4 длины; OOM `goto-instrument` на 32 GB под `proof_for_contract` с инвариантом цикла; таймаут обычной proof на 60 мин;

   - tracking-issue по образцу #656 с воспроизведением job 35 против job 40.
3. **Unwind не проверяется.** Kani компилирует с `-Cpanic=abort`. Восстановление через `CopyOnDrop` при панике comparator и при `panic_on_ord_violation` не доказано (D3 — уровень К; предел обоих инструментов, #734).
4. **UB-категории.**
   - Мутация неизменяемых байтов и invalid value — в рамках рулинга #733.
   - Uninit read на scratch — по итогу K-3.
5. **Редукции.** Сортированность сетей 9 и 13 — по принципу 0–1 на узкой ширине. Перестановка `sort13` — на u8, если так решит K-9.
6. **Ledger.** Все `assume` с `cover`, все `stub_verified` с контролем R11, ручных заглушек нет. Флаги Kani — как в CI (`run-kani.sh`).
