# Задание. Qualification и допуск цепочек N13–N20

Провести офлайн-сверку N13–N17 **через Replace sort13**, а также N18, N19 и N20. Результат — `QUALIFICATION-AND-ADMISSION-N13-N20.md` с решением по каждой длине и конкретными открытыми ролями. Проверяем точный домен `u8/KeyLess<u8>`, V34/base1, произвольные байты, q из всех `u8`, normal fork OFF. Ресурсный критерий обычного допуска — **≤6 GiB sampled child PGID на каждом корне цепочки**, включая провайдеров. Функциональный статус и ресурсный fit записывать отдельно. [Checklist](QUALIFICATION-CHECKLIST.md) · [Задание 18 на ресурсы](PILOT18-IMPL-TASK.md)

GitHub run/attempt — идентификатор прогона. Отдельно записать наблюдения из сводок и независимо связанные native evidence. Статусы архивов, exit job и число успешных assertions сами по себе не устанавливают конкретную контрактную роль. ## Сверка native ролей

- [ ] На каждый root зафиксировать run/attempt, exact selector/invocation, mode, source/tool/control commits, trees и hashes, target/argv/cfg, backend, object bits, checks/unwind, exact verified/ordinary stubs, terminal result и состояние evidence. Проверить cleanup и полноту bounded inventory. Сопоставить native ID/class/location для Pre/post/assigns, frame, safety, covers и необходимых U. Source может обосновать роль и недостижимость. Отсутствующие native данные остаются открытыми. Capacity, timeout и cap сохранять как первопричину.
- [ ] Для N13–N17 сверить пять base1 Check sort13 на 45 actual swaps. Presort modifies только `v[1..14]`. Post — полный byte numeric order префикса, count ниже того же q и q-frame. Подтвердить сохранение хвоста и внешних байтов, семь covers. Сверить в 17B q-only P‑3 с 24 covers, inclusive assigns и native Pre во всех использованных tails. Проверить actual insertion loop, q/order-stat на **всём** исходном срезе, q и outside byte frame, шесть covers каждого consumer. Для контролей подтвердить единственную `NM_N13_CORRUPT_QPOST` или `NM_N17_CORRUPT_QPOST` с двумя covers, на том же маршруте после actual возврата. q сравнивается с полным байтом в observer, а actual `KeyLess` выбирает по числовому порядку независимо от q.
- [ ] Для N18–N20 сверить обе инстанциации Check sort9 и точную геометрию каждого insert. Сопоставить native caller Pre числового порядка на том же состоянии, readable source, writable disjoint scratch32+0, active modifies и q/order-stat whole merge. Actual провайдер исполняет все up/down и guard. Для N19 сверить odd slot, для N18/N20 — оба полных потока записи. Подтвердить покрытие N slots, отсутствие old dst read, actual copy-back и итоговый q/frame. Обосновать native bounds/overflow/unwind и нужные U через exact роли. Отдельно отметить OFF и предел вывода по native uninit/validity. Сохранить прежнее решение N18/N19 до закрытия отмеченных там gaps. У N20 зафиксировать, какой q-post control поддерживает выбранную цепочку. Незавершённый N25 control требуемой роли не устанавливает. При необходимости привязки того же маршрута есть N20 compact control в задании 18.

## Решение по смешанным object bits

**Допуск по exact ребру возможен без полного повтора графа.** Успешное завершение без `too many addressed objects` подтверждает ёмкость модели этого root в своём backend. Само по себе оно не доказывает сохранение смысла сводки между двумя width. При x86_64 OB11 — 11+53 бита ID/offset, OB12 — 12+52, offset знаковый. Для конкретного интерфейса сравниваются представимые объекты, offsets и эффекты над байтами, а не ёмкость чужого полного root. [Модель указателей CBMC](https://diffblue.github.io/cbmc/memory-bounds-checking.html) · [Kani soundness](/root/kani-upstream-ch8-s1/docs/src/soundness.md:73)

- [ ] Дать отдельную строку на каждое смешанное ребро, включая контролы, которым нужен тот же Check. N13–N17 — sort13 OB11 → OB12 и отдельно endpoint controls. N18 — whole merge OB12 → OB11. N19 — правый insert и whole merge OB12 → OB11. N20 — два sort9, правый insert и whole merge OB11 → OB12. Check left insert N20 и его caller на OB12. Связать cfg и std перенос по достижимому телу, guards и определениям активных clauses. Сохранить активную модель, provenance, init/read/write, alias/disjoint, footprint и q.
- [ ] Для каждого mixed-ребра показать инвариантность при переименовании object IDs. Привязать реальные allocations и диапазоны signed offsets, включая one-past/wrapping cursor sentinels. Проверить same-allocation guards до pointer-to-int вычитаний, сравнения адресов, overflow и havoc. Для insert разность адресов берётся внутри V34. Для merge source и scratch раздельны, курсоры source сравниваются в одном source. Для sort13 показать доступ только к байтам префикса и точное havoc/assigns. Каждый root самостоятельно завершился с нужными checks. Показать полный native binding точного ребра либо оставить его открытым. Обоснование из одной лишь малости V34/scratch32 недостаточно. [Предыдущий анализ перехода OB12/OB11](QUALIFICATION-MERGE-N18N19.md#5-object-bits-и-решение-по-композиции)
- [ ] Если перенос владельцем qualification принят, зафиксировать reviewer, основание, exact scope и bindings. При открытом переносе запросить **точечный** matched-width root или недостающий inventory. Для N18/N19 сначала оценить повтор B18/B19 и правого insert на OB11. Для 17A→17B выбирать между exact потребителем на OB11 и exact Check на OB12 по риску capacity/RSS. N20 baseline на OB11 исчерпал объекты, поэтому такой повтор без изменения harness уже дал исход. Открытое ребро сохраняет статус `RESEARCH_ONLY`.

## Решение о допуске

Оформить таблицу по восьми длинам. Колонки — exact scope, native functional status, closed/open roles и edges, control evidence, максимум RSS с именем корня и источником, ресурсный fit, решение о допуске и следующий минимальный шаг. Измерения сравнивать в KiB с 6 291 456 KiB. Указать nominal/effective cap, child/outer/component peaks как разные наблюдения, VT/child и провайдеров на пути. Отдельно перечислить RSS контрольных корней. Fit оценивается по завершившимся обязательным корням, включая Check, с сохранением профиля измерения.

- **N18/N19.** При полной functional/edge сверке и подтверждённом fit оформить готовность к обычному допуску с exact scope. Отдельно закрыть прежние пробелы native inventory и mixed edges. Если доступного evidence мало, записать блокирующую роль.
- **N13–N17.** При полной functional/edge сверке оформить доказательную часть. Ресурсный статус остаётся выше цели из-за пяти Check sort13 при 7,35 GiB. Для обычного допуска нужен пригодный повтор провайдеров. Исключение оформляется решением владельца для конкретной serial lane и roots.
- **N20.** При полной functional/edge сверке оформить доказательную часть. Обычный допуск ожидает закрытия ресурсной цели у consumer и left insert либо нового квалифицированного пути. При отсутствии принятого q-post контроля зафиксировать его роль отдельной строкой. Исключение владельца должно перечислить оба тяжёлых корня и профиль.

В финальном решении дать координатору готовые строки допуска там, где gate закрыт, и короткий перечень доказательств, которых не хватает в остальных строках. Исторические receipts, ledger и `proof_credit=NONE` сохраняются. Запуск CI и смена профилей в этой офлайн-задаче требуют отдельного GO. Коммит отчёта `[skip ci]`, короткий handoff.
