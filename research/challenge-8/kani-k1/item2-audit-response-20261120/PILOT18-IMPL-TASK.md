## Решения после измерения

- **N25.** Для следующей стадии предпочесть завершившийся OB12 compact с положительным и назначенным отрицательным исходом. OB13 оставить диагностикой ёмкости, если он даёт высокий RSS. Если подходит лишь OB13, review каждого mixed-ребра включает 13+51 split и отдельно measured fit. Если оба подхода остановятся, следующий вариант — меньше дублированного состояния в wide insert observer или Check на существующей границе `insertion_sort_shift_left` и один Replace вместо трёх. У этого варианта нужны точный active footprint, сохранение q/count и numeric order при правильном префиксе, и отдельный identity/zero-write Check правого no-op на len13/offset13. Actual сеть вызывает этот loop и справа. Runtime остаётся тем же.
- **6 GiB.** Успех L17 compact под целью даёт основание повторить четыре остальные base1 геометрии тем же observer и перенести сводку только после сверки clauses. У N20 выбрать завершившийся вариант под целью и посчитать максимум его реальных зависимостей. Если у варианта с Replace ещё тяжёлый grouped insert-L, достаточно успешного exact rel9 для этого call site. Если оптимизации дадут только подтверждённые функциональные результаты выше цели, предложить владельцу **точечное исключение** для отдельной serial qualification lane. Для пяти sort13 Check ориентир 8 GiB при наблюдавшихся 7,35 и 813–830 с child. Для исходного N20 — отдельные пределы 8 GiB для grouped insert-L и 9 GiB для consumer по наблюдениям 7,12/8,65. Подтверждение caps и решение владельца записываются отдельно. Текущая полоса 6 GiB остаётся ресурсным критерием обычного допуска. Для N20 исключение затрагивает и провайдер, и consumer, поэтому приоритет — компактный маршрут. [17A](run-44896810040/SUMMARY.md) · [17B](run-44896876797/SUMMARY.md)
- **Продолжение N21–N24.** Сначала N21, затем N24 и N22/N23. Новые exact sort9 — `(1,11),(11,11),(12,11),(12,12),(13,12)`. Справа нужны base11/rel10, base12/rel9–11 и base13/rel9–11. При упоре grouped Check применять literal tails по примеру 18. Слева применить закрытые base1/rel9–11. Для каждой длины нужны exact Check whole merge и actual consumer по пригодной кодировке, с odd-copy привязкой для N21/N23. Оценка 16–20 roots и около двух 180-минутных пакетов с 600-секундными окнами.

Left base1/len13–15 переносить из 17A только после сверки `no_merge_sort13 → merge_wide`, width bridge и решения по ресурсу.
