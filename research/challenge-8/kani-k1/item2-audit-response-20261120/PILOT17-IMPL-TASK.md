## Квалификация смешанных object bits

**Позиция.** Профиль может различаться на Check и Replace после review конкретного ребра. Полный native результат без object overflow необходим для каждого root. Одного такого результата для переноса через ребро мало. CBMC хранит ID объекта в старших битах указателя и signed offset в оставшихся. Для x86_64 OB11 — 11+53, OB12 — 12+52. Меняются и ёмкость ID, и диапазон offset. В 6.11.0 выход за ёмкость порождает ошибку кодирования. Порядка включения доказательств по width отсюда не следует. [Модель указателей CBMC](https://diffblue.github.io/cbmc/memory-bounds-checking.html) · [Код CBMC 6.11.0](https://github.com/diffblue/cbmc/blob/cbmc-6.11.0/src/solvers/flattening/bv_pointers.cpp#L884-L897) · [Soundness Kani](/root/kani-upstream-ch8-s1/docs/src/soundness.md:73)

- Для каждого mixed-ребра связать exact Check и Replace с тем же телом, активными clauses, tool/checks/unwind и типом. Сопоставить domain, реальные allocations, offsets и len, frame/assigns, native caller Pre, Check post, обычные safety и нужные U. У обоих запусков нужны полный native inventory и terminal outcome без capacity error. Разобрать provenance и signed offsets фактической геометрии, включая one-past и merge sentinels. Проверить, что сравнения указателей, cast-to-int, вычитание адресов, overflow и havoc действуют одинаково при смене кодировки в пределах **этого интерфейса**. Малые V34/scratch32 дают аргумент о размере, а связка с конкретными выражениями даёт основание для переноса. Такой bridge сравнивает смысл передаваемой сводки. Вместимость всего OB12 consumer при OB11 в его предпосылки не входит.
- Применить правило к sort13 OB11 → no-merge OB12 и к wide OB11 → N20/N25 OB12. У wide левый insert повторяется на OB12, а успешные sort9, правый insert, sort13 и целый merge из 16 для соответствующих call sites остаются OB11. При согласованном bridge полный повтор графа не нужен. Для неподтверждённых рёбер повторять только недостающий exact Check на width потребителя или потребителя на width провайдера, где хватает object IDs. Пока bridge или matched replay открыт, сохранять `RESEARCH_ONLY` и `proof_credit=NONE`. Ни штатное завершение job, ни контрольная FAILURE не подменяют Check.
