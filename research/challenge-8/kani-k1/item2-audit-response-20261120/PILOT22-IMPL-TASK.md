# Кампания 22. Check merge N32 при 6 GiB

**Рекомендация — один Check с компактной пороговой проверкой, затем узкое исключение 6,5 GiB при повторном отсечении.** В 16 исходный `mw_merge_n32` дал SUCCESS, 0/734, 8/8 covers, 482 с child и пик 6,04 GiB при cap 10. Тот же Check в 21B отсечён при решении на 500 с, с пиком 6,01 GiB и той же округлённой CNF 12,8 млн. До цели от успешного замера около 41 MiB, поэтому одна локальная попытка оправдана. Изменение убирает арифметику масок, а стоимость actual merge, указателей и DFCC остаётся. Вклад observer в RSS по этим двум запускам не измерен. В post после исходных проверок q, длины и readable dst сверить все 32 позиции через `(byte < q) == (i < below)`. Накопить результат без раннего выхода по значению байта. При `below=0` это `u32::MAX`, при `below=32` — 0. В Check остаётся тот же пороговый post на каждом байте и тот же q-frame.

Не предполагать sortedness или свойства `bidirectional_merge`. Для ветвей совместно сверить прежние проверки domain/geometry, source-only capture и guard перед чтением dst. В pure сравнении обе стороны получают один и тот же q и загруженные байты. Проверить обе границы счёта и смешанный случай, где выходная пороговая маска неверна. Так SUCCESS компактного Check можно связать со старым Replace в уже проверенном N32 consumer после сверки active clauses и pins.

## Решение по результату

- По структурированным данным сверить с 21B и 16 sampled child PGID peak, effective cap, phase, переменные/дизъюнкты первой CNF и child/VT. Нужны terminal SUCCESS обоих корней, grouped native coverage ensures/DFCC/safety, успешные unwind, frame и 8/8 covers у Check. Сверить с прежним Replace, actual copy-back и q-post/control N32 из 21B. Другие длины 21A/B и sort13 21C не входят в пакет. [Правило привязки](GROUPED-PROPERTY-DECISION.md#правило-допуска)
- При очередном RSS cutoff или timeout оставить результат 16 функциональным свидетельством исходного Check. Запросить у владельца полосу **6,5 GiB только для `mw_merge_n32`**, OB11, исходный `merge_wide`, OFF, serial, 600 с, тот же tool. Успешный пик 6,04 GiB оставляет около 0,46 GiB запаса. Для ресурса использовать проверенный исторический fit, если это разрешено решением владельца. Если требуется enforced-cap замер, повторить только исходный Check на std 21B. Текущая полоса 8 GiB относится к Check sort13. [Решение владельца](OWNER-DECISION-SORT13-8GIB.md)
