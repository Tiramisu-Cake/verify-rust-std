## Check swap и правой вставки

**Swap.** `proof_for_contract(swap_if_less)` на V34 с base ∈ {1, 10}. Для a/b покрыть каждый из 25 ordered call pairs фактического sort9. Допустимый компактный fixture — произвольные `0 <= a < b < 9` на обоих base. Явно зафиксировать выбранное множество. Сохранить прежние requires по no-wrap, same allocation, читаемости и writability. Разрешённые записи — только байты по этим двум адресам. Из owned pre-state получить точный `(min(old_a, old_b), max(old_a, old_b))` по полным байтам и прежний q AND/OR при том же q. Проверить q-frame и неизменность всех остальных байтов V34. Covers на оба base, оба исхода сравнения, равные байты при разных индексах, mixed q, q=0/q=255 и useful return.

**Правый insert N19.** `proof_for_contract(insert_tail)` на V34. Литеральные `begin=backing_ptr.add(10)`, `tail=backing_ptr.add(19)`, то есть relative tail=9, span `v[10..20]`. До вызова произвольные bytes и q, условия `begin < tail`, одна allocation, читаемый и writable inclusive span и существующий q-монотонный pre. Сохранить q-пост, q-frame и assigns span. Новый отдельный пост — если старый префикс `v[10..19]` был численно неубывающим, весь новый `v[10..20]` численно неубывает. Числовой порядок остаётся предпосылкой импликации, домен Check включает q-монотонные префиксы с числовой инверсией. Frame проверяет весь V34 вне span. Covers на численно отсортированный prefix, q-монотонный численно неотсортированный prefix, ранний возврат и полный sift на численно отсортированном prefix, q endpoints и useful return. ## Check `merge_up` и `merge_down`

Два отдельных `proof_for_contract` на actual targets. В fixture source — V34, активный src начинается по абсолютному индексу 1. Scratch — отдельный объект `MaybeUninit<[u8;32]>` как у actual network. Выбрать N ∈ {18, 19}, `k∈0..=8` — сколько шагов данного направления уже выполнено. Для up `a∈0..=k` — число прежних выборов left. Для down `d∈0..=k` — число прежних выборов right. Эти границы покрывают все фактические вызовы обоих шагов. Содержимое source и q произвольны. Отсортированность источников для отдельного шага не нужна. Индексы source в таблице локальны относительно `src = &v[1]`, индексы dst — относительно scratch.

| Target | Входные source offsets и dst | Post для байта, возвращённый tuple |
| --- | --- | --- |
| `merge_up` | L=`a`, R=`9+(k-a)`, D=`k` | При `old_right < old_left` byte=right и продвижение только R на 1. Иначе byte=left и продвижение только L на 1, включая равенство. D'=D+1. Записанный пороговый бит — AND старых битов. |
| `merge_down` | LR=`8-(k-d)`, RR=`N-1-d`, DR=`N-1-k` | При `old_right < old_left` byte=left и уменьшение только LR. Иначе byte=right и уменьшение только RR, включая равенство. Сдвиг source через `wrapping_sub(1)`, DR'=DR−1 обычным `sub(1)`. Записанный бит — OR. |

- Pre гарантирует читаемость и инициализацию **обоих** входных source pointers, writable текущего dst, непересечение source/dst и допустимость не-wrapping сдвигов. Включить проверку результата `dst.sub(1)` для down. Up пишет scratch[0..9], down — scratch[9..18] или [10..19]. Up может вернуть правый offset 18, который является концом активного среза N18 и читаемым активным индексом N19. Down может вернуть левый локальный −1 (в fixture это V34[0]) либо правый offset 8/9 при k=8. В Check сравнивать pointer values и не разыменовывать возвращённый курсор. Будущий caller доказывает pre каждого нового чтения.
- Checked `modifies` разрешает один байт dst. Проверить точный full-byte результат, q-отношение, весь возвращённый tuple, сохранение q и всего V34 source. Полный байт и движение относятся к одной и той же ветке actual числового сравнения. `old` читает только source. В post чтение одного dst разрешено после actual copy. Извлекать весь scratch через `assume_init` или читать остальные raw slots нельзя. Frame scratch задаёт `assigns`. Сохранить writable-only постановку. Инициализированный dst для проверки ролей не подменяет raw scratch fixture. OFF исход сам по себе не даёт native uninit/validity credit.
- Covers отдельно для N18/N19, k=0 и k=8, `left<right`, `right<left`, равенства байтов, split q, q endpoints, полезного возврата и граничных returned cursors. Up покрывает правый returned offset 18 на N18. Down покрывает левый локальный −1. Для down записать точную проверку диапазона destination `sub(1)`, у последнего шага результат 8/9 при N18/N19.

На tool pin Replace havocs возвращаемый тип через `any_modifies`/ `kani::any`, а в stock `Arbitrary` нет реализации для сырых указателей. Кортеж возвращаемых указателей — отдельный риск для Replace в пакете B. В A исполняются actual up/down, включая tie-control. Успешный Check здесь устанавливает постусловия шага. Возможность использовать его как `stub_verified` для такого return type требует отдельной проверки. В handoff зафиксировать ограничение по исходникам. Tool и return signatures сохраняются. ## Probes и контроли

- H9-L1 вызывает actual sort9 на `v[1..10]`, H9-R10 на `v[10..19]`. В каждом Replace ровно усиленный `swap_if_less` на 25 исходных парах. H10-R10 вызывает actual sort9 на `v[10..20]`, затем actual `insertion_sort_shift_left(..., 9, ...)`, Replace ровно swap и правый insert. После presort проверить числовой порядок первых девяти, для H10 также неизменность хвостового байта до вставки. После всего маршрута проверить числовой порядок полного span, `order_post` относительно pre-state этого же span, q-frame и V34 frame. Использовать шесть обычных covers q-пилота (mixed, ties, extremes, q absent и useful return). У H10 дополнительно достижимость числового отсортированного prefix перед actual insertion loop. Все условия pre устанавливаются в proof, без `assume(sorted)`. Сверить native caller Pre каждого Replace по actual call sites. Они калибруют передачу порядка, а финальный caller precondition `bidirectional_merge` в N18/N19 будет проверен в пакете C.
- **Неверный tie Up.** В `merge_a_bad_tie` оставить actual `merge_up`, прежние pre/assigns и byte/q posts. Единственная дельта модели — отдельный cursor post `merge_up_wrong_tie_cursors`, который при равных полных байтах требует продвинуть R вместо L. На остальных входах ожидание как в положительном Check. Сохранить достижимый tie cover до вызова и useful return. Ожидание — ровно одна native `FAILURE`, привязанная к designated cursor ensures. Проверки байта, q и frame остаются успешными. CFG контроля недоступен положительным probes.
- **Порча числового порядка в H10.** Normal merge cfg, тот же actual маршрут и Replace, что у H10-R10. При all-zero pre-state span и q=2 после вызова записать `v[10]=1`, `v[11]=0`. Биты `>=2` остаются нулевыми. Проверить ровно `FAILURE` на `MA_R10_CORRUPT_NUMERIC_ORDER`, успешные q-post и frame, достижимый cover пути порчи и полезный возврат. q выбирается независимо как в positive. Равенство q=2 выделяет контрольный путь. Cover пути порчи проверить после мутации и перед назначенным assertion.
