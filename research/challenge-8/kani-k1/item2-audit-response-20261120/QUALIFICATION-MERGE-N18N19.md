## 5. Object bits и решение по композиции

На x86_64 CBMC 6.11.0 использует 12 бит object ID + 52 бита offset при OB12 и 11 + 53 при OB11. Максимумы пространства ID — 4096 и 2048, часть ID зарезервирована под null/invalid. У OB12 больше ID, у OB11 больше диапазон offsets. Глобальное включение одной кодировки в другую из числа бит не следует. В локальном теге `cbmc-6.11.0` (`820ff0f555b43fb78e0cd9332e498461bd14244b`) SAT encoder `bv_pointerst::add_addr` прекращает анализ на первом ID за пределом. Терминальный CaDiCaL export даёт косвенное свидетельство прохождения этого ограничения для закодированных адресуемых объектов при заявленном backend. Общее число объектов, native адресные свойства на каждом call site и тождество SAT-формул между профилями экспортом не установлены. [Kani soundness](/root/kani-upstream-ch8-s1/docs/src/soundness.md:73) · [CBMC SAT pointer encoding](/root/cbmc-pr9487-slop-readonly-20261119/src/solvers/flattening/bv_pointers.cpp:875)

Перенос правдоподобен на уровне исходного контракта. Объекты V34 и scratch32 отдельны, все in-object offsets и one-past значения малы для обоих полей, а q и значения байтов от номера объекта не зависят. У right insert разность `tail as usize − begin as usize` считается после same allocation и равна 9 внутри одного объекта. `abs_diff` в whole merge disjoint проверяется только если allocation одна, а в этих fixtures они разные. Pinned Kani дополнительно проверяет full-width address relation и same allocation в модели `offset`. Перенос семантики источника опирается на корректное кодирование геометрии и `assigns`.
