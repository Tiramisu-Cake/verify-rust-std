## std

Дельта `5544e01921d5c67c21d4ab919e8f76b43f884d92` → `0e9b28b293f4360b005d33583d2cf9ac06d1790b` меняет только `sorting_q_model.rs`. База — единственный parent, дерево кандидата `2d13d786186a96e3eeb55ff9969f63388eeee042`, SHA-256 файла `cbe0683c15e286951421c1deb192c4ab9b6a293a6740440ec334343d0daf7349`.

- `span` прежде проверяет `2..=17`, затем последний адрес через `readable_at` и доступность fat slice на чтение и запись. Только после этих проверок он вызывает сканер. В `order_target` и `order_post` допустимую длину проверяют до вызова сканера на валидном `&[u8]`. Во всех трёх путях `begin.add(i)`, чтение и сдвиг защищены `i < len` для каждого литерального `i` из `0..=16`. Нулевой скан даёт 0 без чтений. Inactive dispatch по-прежнему обходит захват байтов, включая вычисление `old(...)`.
- Сканер начинает с нуля и записывает лишь биты с `i < len`. Поэтому `count_ones <= len`, оба аргумента `low_mask` в order target лежат в `0..=17`, а `M(n) ^ M(n-c)` даёт ровно `c` единиц в конце активного диапазона. Это те же биты, которые старый DP выбирал по условию `c >= n-i`. `order_post` применяет ограничение `target & M(len)`, эквивалентное прежнему `zip` по длине выходного среза.
- `insert_pre` отсекает невалидный span и длины 0 и 1 до `len-1`. Формула сдвига проверяет переходы `1→0` только между соседями префикса. При длине 2 у префикса один бит, поэтому это условие всегда истинно. `insert_post` сначала захватывает `after` под теми же span guards, затем проверяет `before.len >= 2`, совпадение длин и q до вычисления последнего бита и сдвигов. Равные валидные длины дают `2 <= len <= 17`. При последнем бите 1 ожидается прежняя последовательность, при 0 — начальный ноль и прежний префикс. Полное сравнение масок эквивалентно сравнению позиций, поскольку старшие биты обеих масок нулевые.
- `sort13` сохраняет valid/q/точную длину 17, пороговый пост на первых 13 байтах и побайтовое равенство четырёх байтов хвоста. Swap pair и false-OR не затронуты дельтой. `smallsort.rs`, харнессы и контроли побайтно совпадают с базой, включая `modifies`, actual calls, Check/Replace, дублирующие assertions, `Q_ABSENT` и covers tails 1–16. В P-5c для `[0; 17]` при `q=1` target равен 0, а присваивание 255 первому байту гарантирует единицу в бите 0. Поэтому `P5C_CORRUPT_QPOST` отвергает этот выход на уровне модели.

### Независимый перебор

Python воспроизвёл исходный нисходящий DP и позиционные предикаты. Литеральные смещения сканера извлечены из Git blob кандидата. Для постусловий исходные сравнения задают по одному допустимому вектору на вход, поэтому сверка этого вектора проверяет весь предикат при сохранённых guards.

| Проверка | Случаи | Результат |
| --- | ---: | --- |
| Скан, order target и нули выше длины, все маски длин 0–17 | 262 143 | PASS |
| Insert Pre и post, все маски длин 2–17 | 262 140 | PASS |
| Insert с длинами 0 и 1 | 3 | Отклонено |
| Старый `zip` и маска префикса, каждый 17-битный target и каждая длина 0–17 | 2 359 296 | PASS |
| Скан на длинах 0, 1, 2 и 17, пороги 0/255, все значения байта | 2 048 | PASS |

При `q=0` единицы занимают весь активный диапазон, при `q=255` единица соответствует только байту 255. На длине 17 максимальное смещение 16 и `M(17)=0x1ffff`. Сценарий порчи P-5c отдельно воспроизведён в Python.
