## Semantic note: where the ZST pointers come from

- For `T = ()` the `FreezeMarker` impl routes to `small_sort_general_with_scratch` (len ≥ 2). `v` is a local `[(); N]`
  (from `array::from_fn`) and `scratch` a local `[MaybeUninit<()>; 48]`; both objects have size 0.
- Every comparator argument is `v_base`/`scratch_base` plus `add(k)` (`sort4/8_stable`, `insert_tail`, the
  `bidirectional_merge` forward and reverse cursors incl. `src.add(len - 1)`, `slice::from_raw_parts(scratch_base, len)`).
  `add` on a ZST is the identity, so all references alias one of the two base addresses; in Rust they are valid for the
  zero-byte read (non-null, aligned). Whether Kani gives a size-0 local a real object or an integer (dangling-style)
  address is a Kani model detail — not established here; root 4 vs root 3 separates "local object" from "integer address".
- N2 path (root 2): two `copy_nonoverlapping(…, 1)` into scratch, no `insert_tail`, then `bidirectional_merge` over
  scratch → exactly one `merge_up` and one `merge_down` comparison, both on scratch-derived references.
- Read differences in this tree: `ptr::read_volatile` carries `#[safety::requires(ub_checks::can_dereference(src))]`,
  an alignment `assert_unsafe_precondition!`, then `intrinsics::volatile_load`; `ptr::read` (used by `zst_aware_less` for
  ZSTs) has no `safety::requires`. Which of these emits the 4 checks (NULL / invalid / outside bounds / invalid integer
  address — CBMC's pointer-check set of one dereference) is not determined; terse output gives no location.
