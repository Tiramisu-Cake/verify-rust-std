# REV2 · независимое ревью левого S13 у N32

**ACCEPT** перенос `(base=1, len=16)` как внешнее составное свидетельство для actual `sort13_optimal<u8, KeyLess<u8>>` в исследовательском графе N32. Пост на нормальном возврате охватывает числовой порядок и полное мультимножество `v[1..14]`, исходный `q` и все 21 байт вне этого префикса. Запасной exact-корень для этого ребра не требуется. `go=NOT_GRANTED`, `proof_credit=NONE`. [Задание](REV2-S13-LEFT16-TASK.md) · [Handoff w14](REV2-S13-LEFT16-HANDOFF.md)

## Привязка к вызову и листу

1. У actual `small_sort_network(&mut v[1..33], &mut less)` на живом инициализированном V34 получается `len=32`. Условия раннего выхода `len < 2` и `len > SMALL_SORT_NETWORK_SCRATCH_LEN` ложны, порог равен 32. Получаем `no_merge=false`, `len_div_2=16`. `v.as_mut_ptr()` указывает на `v[1]`. Первый `from_raw_parts_mut` получает 16, создавая эксклюзивный `[1,17)` внутри `[1,33)`. На первой итерации `region.len() >= 13` ведёт в `sort13_optimal(region, is_less)` с последующим `presorted_len=13`. [Caller](/root/verify-rust-std-rev2-s13-geometries-w14/library/core/src/slice/sort/shared/smallsort.rs:367) · [Raw slice](/root/verify-rust-std-rev2-s13-geometries-w14/library/core/src/slice/raw.rs:150)
2. При `L ∈ 13..=17` guard `v.len() < 13` ложен. `as_mut_ptr` удаляет метаданные длины и даёт тонкий `*mut u8` на первый элемент. Остаток тела исчерпывается 45 прямыми вызовами. В каждом сверены первый и четвёртый аргументы `v_base` и `is_less`. Второй и третий аргументы `(a, b)` совпадают с `SWAP_PAIRS` FIX3 в порядке исполнения, включая повторяющиеся пары. Все `a,b` — литералы с `0 ≤ a < b < 13`, поэтому обе цели лежат в `[1,14)`. [Тело S13](/root/verify-rust-std-rev2-s13-geometries-w14/library/core/src/slice/sort/shared/smallsort.rs:597) · [Таблица FIX3](/root/verify-rust-std-rev2-s13-geometries-w14/library/core/src/slice/sort/shared/smallsort/verify/rev2_provider_cost.rs:13) · [Получение указателя](/root/verify-rust-std-rev2-s13-geometries-w14/library/core/src/slice/mod.rs:778)
3. В FIX3 base получен непосредственно от массива, в caller — по цепочке эксклюзивного среза, `from_raw_parts_mut` и reborrow. Обе цепочки дают доступ к двум адресам внутри живой аллокации V34. Смещения `0..=12` для `u8` укладываются в `isize`, остаются в аллокации без wrap. Адреса различны, выровнены, доступны для чтения и записи. `KeyLess<u8>` живёт отдельно. Компаратор получает shared-ссылки лишь на два операнда на время сравнения `is_less(&*v_b, &*v_a)`, возвращает числовое `<` без чтения `q` и не сохраняет ссылки. Затем `ptr::read` и две однобайтовые копии реализуют `(min,max)` с теми же допустимыми целями. При no-swap первая копия допускает совпадение адресов, вторая копирует из отдельного временного байта. Каждый шаг сохраняет инициализацию и доступ для следующего. [Safety и тело swap](/root/verify-rust-std-rev2-s13-geometries-w14/library/core/src/slice/sort/shared/smallsort.rs:441) · [KeyLess](/root/verify-rust-std-rev2-s13-geometries-w14/library/core/src/slice/sort/shared/smallsort/verify/cal1_model.rs:26)
4. В `swap_leaf_geometry`, `capture`, `modifies` и `post` листа участвуют только пара смещений, два адреса от тонкого указателя и точная специализация `u8/KeyLess<u8>` с наблюдением `q`. У листа отсутствует параметр длины, чтение хвоста или требование отдельного доступа к нему. У CAL1-контракта **самого S13** есть ограничение `13..=17` и проверка читаемости всего среза, которые выполняются для исходного инициализированного `[1,17)`. Capture и post этого контракта читают значения только из первых 13 байтов. Это отдельная контрактная область, а plain битовые корни исполняют actual тело. ## Пост при длине 16

Для любых двух длин из `13..=17` фиксируем одинаковые 13 входных битов и `q`. На шаге 0 совпадают префиксы, а внешние байты могут быть разными. На шаге `k+1` используются те же смещения и значения из префикса, поэтому результат на двух позициях одинаков, `q` сохраняется и внешние байты сохраняют свои исходные значения в каждом исполнении. После 45 шагов префиксы совпадают. Каждая из exact опор `(1,13)` и `(1,17)` тем самым даёт на `(1,16)` канонический упорядоченный битовый префикс с исходным popcount.

Для произвольного байтового входа фиксируем actual исполнение и `q`, затем рассматриваем каждый порог `t ∈ 0..=255`. Проекция `B_t(x) = [x ≥ t]` переводит min в AND и max в OR. По индукции после каждого вызова проекция байтового состояния совпадает с битовым исполнением на проекции входа. Каждая проекция относится к одному и тому же байтовому выходу, поскольку `t` участвует только в рассуждении. Инверсия `x > y` в выходе дала бы битовую инверсию при `t=x`. Для `C(t)=count(x≥t)` сохранение popcount даёт сохранение `C(t)` для всех `t`. Кратности равны `C(t)-C(t+1)` при `t<255` и `C(255)` для 255. Это полное мультимножество, в частности сохраняется `count(<q)=13-C(q)` при исходном `q`.

Байтовый frame следует на каждом шаге из двух локальных целей записи и неизменности компаратора. После 45 вызовов неизменны `[0,1) ∪ [14,34)`, то есть `1+20=21` байт. В том числе `[14,17)` сохраняет три произвольных исходных байта до actual `insertion_sort_shift_left(region, 13, is_less)` с `insert_tail` для rel13–15. Посты этих и правых вставок, предусловия и пост merge, copy-back и сквозной frame относятся к отдельным рёбрам N32 consumer. [Actual вставки](/root/verify-rust-std-rev2-s13-geometries-w14/library/core/src/slice/sort/shared/smallsort.rs:742) · [Граница N32](REV2-MERGE-INVARIANT-REVIEW.md#до-допуска-n32)

## Замечания и запасной корень

- Блокирующих замечаний по переносу нет. `s13_b01_l16_bits` стоит сохранять как запасной вариант на случай требования нативной exact строки `(1,16)` или расхождения привязки consumer. `check_bits::<1, 16, false>()` доступна в том же opt-in модуле, использует тот же `unwind(36)`, те же четыре поста и четыре ожидаемых covers. Native discovery и ресурсные оценки этого корня остаются непроверенными. При изменении actual тела, cfg или области доступа применимость листа следует пересверить отдельно. [Эскиз exact-корня](REV2-S13-LEFT16-HANDOFF.md#запасной-exact-корень) · [Пин модуля](/root/verify-rust-std-rev2-s13-geometries-w14/library/core/src/slice/sort/shared/smallsort/verify.rs:106)
- Для `stub_verified(sort13_optimal)` требуется отдельный Check на домене consumer с нужным контрактом и frame либо проверенный механизм композиции. Запасной plain `Proof` даёт битовую опору. CAL1 post отслеживает `count(<q)` для одного фиксированного `q`. Если Replace должен сам гарантировать полное мультимножество, контракт обязан связать все кратности с одним выходом havoc. [Граница Check → Replace](REV2-S13-BINDING-REVIEW.md#допуск-и-native-replace)
- Проверка w14 прошла на pinned Std. Независимое извлечение вызовов из Git blobs дало 45/45 совпадений и 8192/8192 булевых входов с отсортированным выходом. На временной копии проверка w14 отклонила отдельно изменение пары S13 и перестановку аргументов сравнения в swap. Она фиксирует полный blob `smallsort.rs`, выбранные рабочие blobs и fixtures в Git-объектах. При объединении overlays полную идентичность нового дерева и cfg consumer надо сверять отдельно. Ревью выполнено локально по Git и Python, без cargo, rustc, Kani, CBMC, CI и push. [Проверка w14](check_rev2_s13_left16.py)
