## Шесть обязательных корней и правые вставки

Добавь отдельный verification-only модуль `rev2_n26_n31_halves` под `kani_smallsort_rev2_n26_n31_halves`. Обязательная последовательность в таблице. Все корни вызывают фактические тела, без stubs, Replace и loop contracts. [Пример S13](REV2-S13-GEOMETRIES-TASK.md)

| Слот | Вид и точный домен |
| --- | --- |
| `S13-B14-SWAP` | `Check swap_if_less` на base14, все полные байты произвольны, `0 ≤ a < b < 13` |
| `S13-B14-L14-BITS` | Plain Proof actual sort13 на `v[14..28]`, префикс `[14..27)`, хвост `[27..28)` |
| `S13-B15-SWAP` | `Check swap_if_less` на base15, `0 ≤ a < b < 13` |
| `S13-B15-L15-BITS` | Plain Proof actual sort13 на `v[15..30]`, префикс `[15..28)`, хвост `[28..30)` |
| `S13-B16-SWAP` | `Check swap_if_less` на base16, `0 ≤ a < b < 13` |
| `S13-B16-L16-BITS` | Plain Proof actual sort13 на `v[16..32]`, префикс `[16..29)`, хвост `[29..32)` |

- **Swap.** Возьми форму байтового листа FIX3 с тем же контрактом. У каждого base проверяются min/max двух полных байтов, нативный Check write set ровно этих двух адресов, остальные 32 байта и q. Нужны прежние covers листа, в том числе swap/no-swap, равные байты на разных позициях и normal return. Привяжи `ProofForContract.target_fn` и нативные свойства к конкретной специализации. Для каждой из 45 пар подтверди адреса двух целей, инициализированность, доступ и относительный порядок actual вызовов. [Лист и native anchors](REV2-S13-GEOMETRIES-RESULTS-ANALYSIS.md)
- **Bits.** Независимые 0/1 только в первых 13 позициях. Остальной V34, включая хвост переданного среза, содержит произвольные полные байты. Посты — каноничность, порядок, исходный popcount, q и все 21 байт за префиксом. Covers mixed, inversion, actual comparator и reached post. Для полного байтового поста выведи пороговый перенос через min/max → AND/OR на всех 45 парах. Переносы B14 L14→L13, B15 L15→L14 и B16 L16→L15 опираются на одинаковый base, guard `len≥13`, то же расписание и отсутствие обращений в хвост. B01 L13–15 использует принятый перенос по длине из `S13-BASE1-BITS`, `S13-B01-L17-BITS` и `S13-SWAP-LEAF`. Сверь существенные blobs и точный профиль исторических receipts. [Пороговый аргумент](REV2-S13-BINDING-DESIGN.md#перенос-на-произвольные-байты) · [Ревью B01](REV2-S13-LEFT16-REVIEW.md)
- **Левые вставки.** Офлайн свяжи L14/L15 с первыми одной и двумя итерациями `N32-INSERT-LEFT-BYTES` (B01/L16, `45710831239`). Для L13 `tail == end`, тело цикла не выполняется. У коротких путей покажи собственный one-past-end и промежуточные порядок, кратности и frame после остановки. Доказательство конечного поста L16 само по себе не даёт промежуточного поста. [Принятый аргумент для первых двух итераций](REV2-N13-N16-OFFLINE-REVIEW.md) · [N32 byte drivers](REV2-N32-CONSUMER-RESULTS-ANALYSIS.md)
- **Правые вставки.** До заморозки roster по каждой базе сверь, закрывает ли ребро перенос с известного B17/L16: `tail` и `end` в одной живой области нужного размера, сдвиг к `begin` без выхода, read/write и непересечение каждой копии из соседней ячейки и отдельного tmp, gap восстановлен, q и байты вне половины сохранены. Укажи prefix-инвариант, адресную замену B17→B14/15/16 и остановку после нужного rel. Где остаётся открыта предпосылка, включи exact plain Proof `INSERT-B14-L14-BYTES` (N27), `INSERT-B15-L15-BYTES` (N29 и перенос к N28), `INSERT-B16-L16-BYTES` (N31 и перенос к N30). Максимально девять слотов, дополнительные drivers идут после S13 в порядке баз. Каждый driver предполагает только числовой порядок первых 13 байтов. Фактический driver с offset 13 доказывает итоговый числовой порядок, `count(<q)`, q/V34 frame и normal return, с covers без сдвига и со сдвигом на всех использованных rel. Независимость результата от q и разности соседних счётчиков дают полные кратности. Короткие варианты выводи по инварианту итераций. В handoff зафиксируй, какие рёбра закрыты переносом и для каких нужен свой нативный результат. После discovery используется уже замороженный состав. [Шаблон byte drivers и переноса](REV2-N22-N25-PROVIDERS-HANDOFF.md#геометрии-и-рёбра)

Merge pair, odd center, copy-back, сквозные корни и различающие контроли по каждой длине идут в следующих пакетах. Положительные результаты этого прогона относятся к опорам, `proof_credit=NONE`. Для `stub_verified(sort13_optimal)` нужна отдельная проверка целевого контракта или принятый нативный механизм передачи доказательства. [Правило композиции](REV2-COMPOSITION-RULE.md)
