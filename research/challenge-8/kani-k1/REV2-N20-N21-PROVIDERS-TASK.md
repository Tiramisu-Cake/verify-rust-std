# REV2 · опоры N20/N21 (m=10)

Задание для **w14**. Подготовь один локальный Ubuntu-пакет из шести последовательных слотов для N20/N21. Измеряем правую базу sort9, вставки на обеих базах, пару merge для `m=10` и нечётный центр N21. Сквозные consumers N20/N21 идут после разбора опор. [Допуск N18/N19](REV2-N18-N19-ADMISSION.md) · [План N18–N31](REV2-N18-N31-PLAN.md)

Пара m=9 заняла VT 91,73 с, cold wall 124,56 с и 2,46 GiB group RSS. Первая CNF имела 346 076 переменных и 1 972 867 дизъюнктов, а полный Check включал дальнейшие решательные вызовы. Сначала измерь общую пару m=10 перед объединением бо́льших геометрий. [Замер предыдущих опор](REV2-N18-N19-PROVIDERS-RESULTS-ANALYSIS.md) · [Смета N20/N21](REV2-N18-N19-CONSUMER-HANDOFF.md#офлайн-смета-следующего-пакета-n20n21)

## Пины и область

Создай отдельные локальные worktrees на этих ревизиях.

| Репозиторий | Commit | Tree | Parent |
| --- | --- | --- | --- |
| Std | `959087ac8632c68d8a6f0e28f58a8708475d564b` | `2123d3d5a77af26c6faf2d98d031904e75771300` | `a6f189eecbee57fe7517547bf7461c9dd2897e27` |
| Control | `6a599af76402e61eef6746c32d7500b6ac101945` | `13057fe3d9479899217b3ab3b048d9a6571ec3a3` | `33db7a6351c4549098c52ce0e245fd072eb2152f` |

Инициализированный произвольный V34, `u8/KeyLess<u8>` с числовым `<`, независимый `q: u8`. Runtime std и существующие контракты сохраняются побайтно. N20 берёт `v[1..21]`, половины `v[1..11]` и `v[11..21]`. N21 берёт `v[1..22]`, половины `v[1..11]` и `v[11..22]`. В обеих строках presort — sort9, затем вставка от offset 9 в каждой половине. Слева перенеси `S9-B01-L09-BITS` на len10 по тому же guard, base и 25 парам rel0–8 с листом FIX3. Справа перенеси новый bit Proof с len11 на len10 по той же схеме. У обоих переносов хвост за rel8 входит во frame. Scratch — отдельный writable `MaybeUninit<[u8; 32]>`. Читай его ячейки только после записи.

## Фиксированный roster из шести слотов

Новый модуль `rev2_n20_n21_providers` под `kani_smallsort_rev2_n20_n21_providers` и унаследованными cfg. Корни используют actual функции, а odd Check — привязанную к исходнику локальную транскрипцию. Replace, stubs и новые loop contracts из области исключены. Для grouped корней сохрани отдельные обязательства и covers по N20 и N21.

| № | Метка / selector | Домен и требуемый результат |
| ---: | --- | --- |
| 1 | `S9-B11-L11-BITS` / `s9_b11_l11_bits` | Plain Proof actual `sort9_optimal` на `v[11..22]`: битовый префикс `v[11..20]`, произвольный хвост `v[20..22]`. Каноничность, oracle отсортированной маски того же popcount, q и полный внешний frame; covers смешанного входа, инверсии, actual comparator и достигнутого поста. Перенос same-base к правой длине 10 у N20 должен сохранить guard, все 25 пар и отсутствие доступа к rel10. |
| 2 | `S9-B11-SWAP` / `s9_b11_swap` | Check `swap_if_less` с прежним FIX3 контрактом, base 11, полный V34 и `0 ≤ a < b < 9`. Min/max двух байтов, native modifies ровно этих адресов, frame остальных байтов и q; covers swap/no-swap, равные значения в разных позициях и normal return. Привязать actual specialization и пары sort9 на этой базе. |
| 3 | `N20-INSERT-LEFT-BYTES` / `n20_insert_left_bytes` | Plain Proof actual `insertion_sort_shift_left(&mut v[1..11], 9, ...)`; входной `v[1..10]` численно упорядочен, `v[10]` произволен. Пост: числовой порядок длины 10, `count(<q)`, q-frame и V34-frame; covers actual comparator, normal return, без сдвига и полного сдвига. Связать с левой половиной обеих строк N20/N21. |
| 4 | `N20-N21-INSERT-RIGHT-BYTES` / `n20_n21_insert_right_bytes` | Один grouped Plain Proof actual driver на base 11, с отдельными exact обязательствами и covers: N20 — `&mut v[11..21]`, offset 9, ordered prefix `v[11..20]`, вставка rel9/abs20; N21 — `&mut v[11..22]`, offset 9, тот же prefix и хвост rel9/abs20 плюс rel10/abs21. Для каждой длины доказать полный numeric order, `count(<q)`, q и внешний frame, normal return, no-shift/full-shift, а также exact bounds/coverage хвоста. Не объединять результаты так, чтобы потерялась идентификация N20 или N21. |
| 5 | `M20-M21-PAIR-STEP` / `m20_m21_pair_step` | Check verification-only wrapper actual пары `merge_up`/`merge_down`, конечный домен `N∈{20,21}`, `m=10`, `0≤k<10`. При `a+b=c+d=k`: up получает `(S+a, S+10+b, D+k)`, down — `(S+9-c, S+N-1-d, D+N-1-k)`. Числовые упорядоченные половины; writable-only scratch. Проверить точную read/write/disjoint геометрию, обе тройки возвращённых курсоров, min/max, выбор стороны на tie, source/q frame и только `D[k]`/`D[N-1-k]` в modifies. Вызовы обеих копий должны пройти applicable grouped DFCC/safety properties. Covers отдельно для N20 и N21: k=0 и k=9, полезный возврат, оба выбора каждой стороны и ties обоих направлений. |
| 6 | `M21-ODD-CENTER` / `m21_odd_center` | Check локального wrapper для N21 и `k=10`. Предпосылки `a+b=c+d=10`, `a+c≤10`, `b+d≤11`, неотрицательные счётчики, ровно один остаток. Привязать reverse pointers и границы `left_end/right_end` через `wrapping_add(1)`, выбор `left < left_end`, копию в `D[10]` и продвижение выбранного курсора. Проверить независимо выбранный источник, записанный байт, оба конечных равенства, source/q frame и modifies только `D[10]`. Covers обоих остатков, поста после копии и исчерпания левой половины при `c=10`, где `left_rev=S-1` и остаток справа. Sentinel не разыменовывается. В handoff показать соответствие actual ветке. |

Приложи ранговый вывод. После десяти пар N20 заполнен. У N21 остаётся ранг 10, который пишет нечётная ветка. Проверь конечный cursor guard и отсутствие чтений старого scratch. Инициализация ровно 20 или 21 байта следует из actual записей при uninit OFF. Copy-back и сквозной пост относятся к следующему пакету. Для вставок свяжи равенство `count(<q)` с полным мультимножеством через q-независимость actual компаратора. [Ранговая привязка N19](REV2-N18-N19-ADMISSION.md#нечётный-центр-n19)
