### F5. A2 решает задачу, созданную формой harness'ов

Факты.

- `Profile::CMP` — константа типа fn pointer ([`profiles.rs:28`][s-profile]). Обёртки принимают `cmp` и сверяют адрес ([строки 127–131][s-guard]). Все вызовы передают `P::CMP`: `network.rs:99, 905, 994, 1051, 1104`; `merge.rs:144, 159, 525`.
- Под включённым uninit уже проходят fn-item компаратор ([R4, F1][r4]) и замыкание ([Gate B′][gateb]: `merge-profile-closure-on` — SUCCESS).
- Для пункта 1 профили не обязательны: у вас уже есть доказательства реальных helpers с замыканием, которое возвращает произвольный `bool` (`helper_contracts`). Они покрывают больше поведений компаратора, чем упорядоченный профиль.
- RFC 0016 относит вызовы через function pointer к inconclusive. Профили на fn pointer не пройдут и будущий `-Z aliasing-checks`.
- План оценивает A2 в 10–20 дней с высоким риском («неполный target set даёт false SUCCESS», строка 101). «Вариант сведения» требует механизированного relation между FnPtr-обёрткой и closure-копией (строка 105).

Рекомендации.

1. Задать компаратор профиля статически: `fn cmp(a, b) -> bool` в трейте и замыкание `|a, b| P::cmp(a, b)` в теле обёртки. Косвенного вызова не остаётся. «Closure companion» становится самим профилем. Адресный guard и wrong-F контроли заменяются гарантией типов. Ориентир — 2–4 дня с переквалификацией.
2. A2 убрать с пути Challenge 8. Поддержка FnPtr в uninit-анализе остаётся полезным вкладом в #3300, если её попросят мейнтейнеры.
3. Уточнить формулу §1 (строка 30). Closure companion недостаточен, когда он и функция, потребляемая через `stub_verified`, — разные функции. Harness, который вызывает реальную функцию с замыканием, — доказательство о самой цели, а не сведение.

### F6. B: чужие PR и дизайн для #3762

Факты.

- По [#733][i733] (комментарий от 23.10) `-Z valid-value-checks` в CI не включён. На 277 harness'ах #587 флаг дал 148 отказов, из них 141 — «Kani currently doesn't support checking validity». Предложение автора — вынести invalid values за рамки, пока инструмент не сможет их установить. Для вас B — уровень К. Ваши цифры по SmallSort при этом станут прямым вкладом в рулинг.
- #5023 закрывает открытый [#5069][k5069] (kasimte, с 27.10; в сообщении коммита «Resolves #5023»). Чтения элементов среза проверяет открытый [#5073][k5073] (kasimte, с 27.10). #5057 (v3risec) слит 13.11. План оценивает эти фиксы в 3–7 дней каждый и PR не упоминает (строка 190).
- Код pass:
  - отказ на `CopyNonOverlapping` выдаётся безусловно, даже когда у pointee нет требований validity ([491–498][cv-copy]);
  - `write_bytes` проверяется в точке записи, и комментарий прямо называет это over-approximation ([550–590][cv-wb]): pass устроен как проверка у производителя;
  - intrinsic `copy`, судя по тому же блоку, не попадает ни в проверку, ни в отказ;
  - правило «mutable cast» ([697–754][cv-cast]) должно сработать на `stack_array.as_mut_ptr() as *mut MaybeUninit<T>` и `as *mut T` ([`smallsort.rs:214`][s-cast1], [`369`][s-cast2]) для `T` с требованиями validity.
- План (строка 180) запрещает проверку на каждой копии и предлагает переносить или откладывать обязательство. Это отдельная shadow-модель validity. Она заметно дороже и расходится с архитектурой pass.

Рекомендации.

1. Начать с переписи: один диагностический прогон 235 harness'ов с флагом и классификация отказов по конструкциям. #3762 — не единственный блокер, cast'ы тому пример.
2. Малый патч: у pointee нет требований validity — нет отказа. Он снимает блокировку для всех целочисленных типов и полезен не только вам.
3. Для типов с требованиями — консервативная проверка «источник типизированно валиден в момент копии», в духе `write_bytes`. В SmallSort все копии через `*T` переносят действительные элементы, поэтому ложных срабатываний быть не должно (вывод по чтению `smallsort.rs`). Padding и `MaybeUninit` не затрагиваются: проверка идёт по `ty_validity_per_offset`.
4. Добавить семейство harness'ов с типом, у которого есть требования validity: `bool`, `char`, `NonZero`. На `u8` и `u64` флаг ничего не проверяет.
5. Дизайн изложить комментарием в #3762 до кода. #5022 и #5023 из своего списка убрать, следить за #5069 и #5073.

### F7. A: порядок маршрутов и проба масштаба

Факты.

Тот же приём нужен для havoc в loop contracts (дорожка E). Гипотеза выведена из документации и на коде не проверена.
