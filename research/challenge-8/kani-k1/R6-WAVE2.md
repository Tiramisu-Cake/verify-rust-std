## Правила, новые для волны 2

- **О1 засчитывается только по варианту (А)** (R6 §2 п. 2–3). Гармоника (А) устроена так:
  - без `should_panic`;
  - `panic_on_ord_violation` заменён ручной заглушкой `#[kani::stub]` с `kani::cover` и `kani::assume(false)`;
  - любая другая паника даёт FAILED.

  Это исключение R3 распространяется на все гармоники О1 и O3-s. Заглушка записывается в ledger. Гармоники (Б) волны 1 остаются дополнительной проверкой.
- **Контроль варианта (А) обязателен до первого засчитанного прогона (А)** у каждого агента, в его же файле гармоник:
  - мутант класса `assertion` (`assert!` на нормальном пути) в гармонике (А) → ожидается FAILED с местом;
  - гармоника достижимости: `cover` на вызов заглушки.

  Контроль (А) волны 1 (job 47) построен на другой гармонике и сам по себе не переносится.
- **Comparator** — по CD-2: читает оба аргумента через `read_volatile`, затем возвращает `kani::any()`. Для O3-s он сначала читает, затем пишет новые ключи (как в K-13).
- **Целевое время ≤180 с на Linux** для каждой новой гармоники (R6 §3, «Время на macOS»). Предел приёмки по-прежнему 600 с. Гармоники дольше 180 с делятся по длинам. Если делить нельзя, они идут в M-1.
- **Семейства длин.** Одна гармоника на постоянную длину либо выбор длины через `any_where` с `cover` на каждую длину. Безопасность и перестановку держать в разных гармониках (урок job 74).
- **Срезы.** Проверки указателей CBMC идут по границам всей аллокации. Поэтому гармоники безопасности вызывают сортировку на массиве ровно нужной длины, а не на префиксе большего массива. Исключение — гармоники, где это раскрыто явно.

## Решения координатора по ходу волны 2

- **CD-5 (2026-10-26, по review K-16s `3ce9177c`). «Тихая» заглушка.** Это `panic_on_ord_violation` → `assume(false)` без `cover`. Она допустима только в двух случаях:
  - в семействах, где путь слияния недостижим: длины без слияния на network, fallback, insertion;
  - для ZST.

  В семействах, где есть длина со слиянием, обязательна заглушка с `cover`. Тогда для каждой пары «тип × маршрут» измерено, что срез вызывается.

  Контроль тихой заглушки ставится на длине со слиянием, на шаблоне K-16s: `w2_type_fixed::<u8, 18, false>` и `assert!` → FAILED.

  **ZST** — отдельная строка «только trait-уровень». Настоящие вызывающие функции возвращаются до `small_sort` при `T::IS_ZST` (`stable/mod.rs`, `unstable/mod.rs`, `select.rs`). Поэтому в покрытие публичной сортировки эта строка не идёт. Заглушка на пути ZST не стоит. Чтение аргументов по CD-2 для ZST пустое. Длины network 18+ для ZST исключены: цикл `small_sort_network` на ZST не завершается.

  **Уточнение (16:05Z).** Семейства со слиянием тоже могут идти с тихой заглушкой: она обрезает тот же путь, что и заглушка с `cover`. Но тогда для каждой пары «тип × маршрут» со слиянием нужна отдельная дешёвая гармоника достижимости: одна длина со слиянием, заглушка с `cover` и `cover` нормального возврата. Результаты u8 из job 88 засчитываются на этом условии.
