## Equivalent-oracle candidate, held for a separate step

For a fixed N<=4 let A_j=bytes[1+j] and B_j=v[1+j]. Define S_N as the conjunction B_(j-1)<=B_j for 1<=j<N. Define C_N as, for every k in 0..N, equality of the sums of indicator(A_j=A_k) and indicator(B_j=A_k) over 0<=j<N. Use finite explicit expressions for the chosen N, full u8 equality/order and usize sums bounded by N (no overflow). No assertion assumes any of these equalities.

The original model is valid for initialized u8 slices N<=4, snapshots exactly A and checks exactly S_N and C_N with loops. Unrolling those conjunctions/sums preserves the predicates. To show full multiset preservation: for each distinct input value x, C_N fixes its output multiplicity; their sum is N, the output length, so there is no output position left for a novel value. Duplicate input queries merely repeat a check. For N0, both are empty true; for N1, S is true and C iff B0=A0. A shared N01 conditional can select those two exact predicates. Frame/canary/active guard and all covers remain independent retained obligations; N1's active cell is constrained by count even though outside-frame excludes it.

Before use, require concrete expression-to-definition correspondence for every index and count, proof of both implication directions to the frozen model, equal-length/validity/initialization/type activation premises, no count overflow, and adverse examples for order corruption, count corruption, duplicates, novel values, N0/N1 active mutation and frame mutation. Finite representative tests support expression checks but are not exhaustive full-u8 proof or a provider qualification. N! permutation disjunction (2,6,24 permutations for N2/3/4) is another exact multiset characterization, including duplicates, but is larger and has no demonstrated solver advantage. A reference-sort algorithm oracle would itself need correctness; it is not a free replacement.

## Direct-call hypotheses and exact target boundaries

The present harness already directly calls small_sort_network; for N2..4 that real function **uses insertion**, with prefix1. There is no extra harness dispatcher to remove. Changing the callee to avoid insertion changes the entry theorem:

- `sort9_optimal<u8,KeyLess<u8>>` requires len>=9 (kernel:494-540); `sort13_optimal` requires len>=13 (543-555). On N<=4 the source aborts before the network. Padding to9/13 adds initialized values and changes length/frame/domain; it requires a projection/equivalence proof and a caller-control-flow bridge, and is a new target/new ID until then. Their exact claims concern their first9/13 values and all untouched storage, with comparator and safety checks retained.
- `sort4_stable` (kernel:749-768) is an unsafe out-of-place helper: initialized readable source4, writable destination4, valid lifetimes/alignment/provenance and disjoint regions, exact full-u8 comparator, correct result in dst, all other storage framed. N4's current in-place slice is not that geometry; N2/N3 do not supply four active values. Copy-in/out or padding creates a new harness/domain and needs a bridge, including init/drop/panic/normal-return and frame guarantees. It is not the branch small_sort_network takes for N4.
- `insertion_sort_shift_left(slice,1,KeyLess)` has source domain 1<=offset<=len and a sorted prefix. For N2..4 a source correspondence is plausible: small_sort_network passes the same full region/prefix1, no_merge=true, no scratch read, then returns. But this different entry still needs an actual caller/equivalence proof covering memory, frame, comparator state, abort/panic/return and any generated contracts; it is not automatically the original theorem. Calling it at N0 violates offset<=len. At N1 its empty loop differs from the original early-return entry path and needs its own bridge. The recommendation keeps the original callee for both.
- `insert_tail` needs an initialized same-allocation begin..tail region, tail>begin, writable ownership, correctly ordered preceding prefix and exact span/frame/temporary-drop behavior; a leaf for that helper is not the entire insertion loop. Swap, merge8, sort4, sort9 and insertp1 bounded source cases are not universal verified contracts. A custom sorting network would be a new algorithm, not a proof of this implementation.

## Proof DAG (all missing edges OPEN)

1. Exact typed, initialized, owned/readable/writable domains + stateless full-value comparator + frame/geometry facts feed each helper leaf. A proposed N0/N1 original-body leaf can establish early return only after native completeness, not by tail inference.
2. A qualified insert_tail leaf plus loop invariant (sorted prefix, exact full multiset, gap initialized on return/drop, outside frame, decreasing/increasing pointer bounds) and termination/safety obligations feed insertion_sort_shift_left for the exact needed domain. Bounded 1/2/3-tail cases do not yield a universal induction theorem.
3. Qualified insertion plus proved small_sort_network dispatch/caller bridge feeds the bounded N2..4 original-callee claim. N0/N1 early-return leaves and exact finite union then give only N<=4 for exact u8/KeyLess/V34/base1, not N16/N32 or generic callers.
4. Larger domains additionally require sort9/sort13 networks, both regions, merge, scratch initialization/read/write/ownership, comparator/panic effects and caller bridges. New type/comparator/geometry domains require new premises/proofs.
5. Any verified-provider use requires exact source/tool/body/domain binding, emitted contract/MIR/ADT assumptions and modification/frame binding, expanded pre/post completeness, actual provider proof and root approval of the qualification mechanism. Old source-reported outcomes and exact location exceptions do not transfer. No unproved `stub_verified` or assumed-summary edge is enabled here.

The small source domain proof and a source oracle equivalence argument do not establish any native edge. Source claims, B1 bounded evidence, B2 full proof and independently established provider credit remain distinct. Deferral remains the fallback if a separately authorized attempt cannot complete under unchanged controls.
