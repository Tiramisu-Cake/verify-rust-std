Title: Track qualified masks for whole immutable allocations

Refs #3300

Depends on #5172 and `PR-01`. This branch is based on `PR-01`; until both dependencies merge, their changes are included in this branch's diff against main.

With `-Z uninit-checks`, compiler-produced immutable allocations need their initial byte state represented in the shadow model. Otherwise, a legal comparison with an initialized constant can report an uninitialized read. This change seeds qualified whole-allocation masks and combines compatible aliases of the same emitted storage.

### Change

- Record anonymous allocation origins and bind them to emitted immutable symbols.
- Coalesce qualification only for compatible exact storage descriptors, preserving extent, layout and mask, including initialized zero bytes versus holes; reject incompatible descriptors.
- Seed exact byte masks after state reset, preserving false bits and avoiding queries for empty masks.
- Document the narrow whole-allocation qualification and conservative cases.

### Limitations

Qualification is limited to whole immutable, relocation-free allocations with a supported `Freeze` origin type and computable layout. Mutable, relocated, unqualified subrange, and conflicting origins are not admitted as initialized. This does not resolve all of #3300 or add blanket `MaybeUninit`, indirect-call, or recursion support.
