Title: Track initialization masks for whole immutable allocations

Refs #3300

Depends on #5172 and `#<PR-01>`. This branch is based on `#<PR-01>`; until both PRs merge, their changes are included in this branch's diff against `main`.

With `-Z uninit-checks`, compiler-produced immutable allocations need their initial byte state represented in the shadow model. Otherwise, a legal comparison with an initialized constant can report an uninitialized read. This change records exact masks for supported whole immutable allocations and combines compatible aliases of the same emitted storage.

### Change

- Record anonymous allocation origins and bind them to emitted immutable symbols.
- Combine compatible aliases only when their extent, layout and mask agree, keeping initialized zero bytes distinct from holes; reject incompatible descriptors.
- Set the shadow bytes from those exact masks after the state is reset, leaving uninitialized bytes uninitialized and skipping empty-mask queries.
- Document which whole allocations can be handled this way and where checks remain conservative.

### Limitations

These initial masks apply only to whole immutable allocations with no relocations, a supported `Freeze` origin type and a computable layout. Mutable allocations, allocations with relocations, subrange origins that do not meet these checks, and conflicting origins are not marked initialized by this step. This does not resolve all of #3300 or add general `MaybeUninit`, indirect-call, or recursion support.
