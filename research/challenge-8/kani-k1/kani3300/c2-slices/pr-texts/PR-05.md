Title: Analyze closure captures using their concrete layout

Refs #3300

Depends on `PR-04` and, transitively, #5172. Until the dependencies merge, this branch includes the earlier stack commits. The source tested here is `96f5d5dc8dedd369c6986a4f1dd5e698b6167f0f`.

Legitimate closure capture and contract cases were stopping at an unsupported-layout result. The analysis needs each closure's concrete environment layout to locate its upvars and padding, including zero-sized environments, so these cases can proceed through layout checking.

### Change

- Read monomorphized upvar types and offsets from the closure's concrete compiler layout, preserving padding and initialized payload boundaries.
- Handle zero-sized closure environments and add 47 mapped fixtures for closure layout and remaining integration cases, including captured-field contract and generated `modifies` cases.
- Close the remaining analysis and storage integration obligations for this scope while retaining conservative resets at unsupported nested aggregate boundaries.

### Testing

[Fork CI on `96f5d5dc8d`](https://github.com/Tiramisu-Cake/kani/actions/runs/43715788377) passed formatting, development build, Clippy, and bounded Linux suites: 451 passed and 9 pre-existing ignores. Four sensitivity mutations were exercised; three were detected by the runner. The fourth completed and produced the expected mismatch, confirmed by a coordinator's manual review after local renumbering confused the runner's name check. It was not an automated runner detection. This is not the full three-platform gate.

### Limitations

Closure support uses compiler-reported sized layouts and the existing computable payload masks; unsupported union/`UnsafeCell` capture layouts remain unsupported. Shadow transfer under `stub_verified` or `kani::recursion`, indirect calls, nested by-value union/`MaybeUninit` aggregates, analysis cycles and unmodeled intrinsics remain limitations. `select_unpredictable` still blocks verification of the whole SmallSort module.
