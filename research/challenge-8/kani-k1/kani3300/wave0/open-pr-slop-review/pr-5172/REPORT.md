## Control-flow and soundness reasoning

`CheckUninitVisitor::find_all` prepares the first instruction's target and, for an entry block, union LoadArgument operations. `visit_terminator` first visits call operands exactly once. A failed resolution appends Unsupported and exits the labeled call arm with `break 'call`, so the terminator epilogue at :498–499 stores the target. The base snapshot instead revisits operands and returns from the visitor before that epilogue, discarding the collected operations. This is the source-level explanation for the regression; no native property result is inferred from it.

The local UninitPass is enabled independently of delayed-UB targets (ptr_uninit/mod.rs:35–76). DelayedUbPass builds its target set across reachable instances and runs the points-to/instrumentation work only when that set is nonempty (delayed_ub/mod.rs:70–136). Moving the unresolved-call diagnostic into the local visitor therefore matters independently of an explicit copy helper.

The shared resolve_call retains separate intrinsic, foreign Item, MIR-backed Item/Shim, Virtual, LlvmIntrinsic, unresolved function-item and non-FnDef outcomes (points_to_analysis.rs:350–371). `checked_body` is instance-aware and protects conversion of explicit tail calls (kani_middle/mod.rs:132–150). Replacing this with definition-level has_body or an unwrap would lose the intended generated-body/fallible behavior. Initial-target discovery's `.ok()` is a conservative optional lookup, not a reason to add fatal errors or route it through the full resolver.

Unknown-call effects add no alias edges; accumulated caller edges remain. This is safe only together with the local Unsupported check that prevents reaching the unknown effect. UnsupportedCheck emits `codegen_assert_assume_false` (overrides/hooks.rs:202–235). Keep that coupling and the before-call operation order. Do not replace it with an assumed callee summary or infer that an unresolved callee has no memory effects. Keep intrinsic/allocation models and ordinary direct-call positives.

Both shim guards matter at different boundaries: the caller checks argument/destination storage, while shim entry checks parameter/result storage before LoadArgument. The recursive classifier follows by-value ADTs, tuples, arrays/patterns and closure captures, stops at pointers/references and classifies unknown shapes conservatively. Preserve its rejection behavior while coverage is incomplete. The existing regular cross-function union tests exercise ordinary Item arguments, not the new generated-shim boundary.

## Why the proposed cleanup retains these tests

Plain and seeded files must stay separately compiled. Manual harnesses without different stubs/contracts share a codegen unit (`group_by_stubs`, codegen_units.rs:245–269); delayed-UB target collection is across that unit. Combining a seeded harness with a plain one changes the analysis condition even if their Rust functions are separate. “Plain” here means no explicit copy helper; this offline review does not establish that its entire reachable target set is empty.

Keep the custom-MIR operand test: ordinary source can move `*pointer` into a preceding statement and stop testing the lost terminator operation. Keep initialized and partially initialized union entry companions: requiring only one process failure would hide a missing check or an indiscriminate failure. Keep both generated-positive harnesses so a failure in one cannot hide the other behind a cut path. Keep Fn-trait-pointer as a distinct route through generated dispatch, and Virtual as a separate instance kind. Scalar, erased-pointee, aggregate-carried and global/no-argument negative fixtures guard different unjustified assumptions about an unknown callee's effects.

The driver matches groups of substring lines anywhere in output, with trailing `\` requiring adjacency; it does not order those groups or bind them to a preceding harness header. The bounded port of those rules accepts a hypothetical naive merged initialized/partial oracle with the safety statuses swapped between harnesses. Consequently a future grouping must first bind fully qualified property names and preserve compiler flags and analysis-target isolation. The default fallback proposal above shares byte-identical text across separate invocations and does not introduce that ambiguity.

All current expected files require a verification verdict and completed harness summary. The Fn-trait files use the supported `Failed Checks:` diagnostic, not an internal compiler/backend failure. No golden ICE was found and none should be introduced. Existing `delayed-ub-unsupported-call/main.rs::{check_dyn_call,check_fn_ptr_call}`, `multiple-instrumentations.rs::{multiple_instrumentations,multiple_instrumentations_different_vars}`, `unions.rs::{cross_function_union_should_pass,cross_function_union_should_fail}` and `tests/kani/Uninit/delayed_ub_fn_ptr_in_std.rs::check_subslice` were inspected at the unchanged base/head. They support the broader baseline, but none replaces the statement-free entry/Call-operand regression or demonstrates all new shim rejection paths. No harness is removed based on an unverified claim of upstream coverage.
