`-Z uninit-checks` sets up its memory initialization state at the start of `#[kani::proof]` and `#[kani::proof_for_contract]` harnesses, but not in harnesses generated by `kani autoharness`: `is_harness` only looks for those two attributes. As a result, `kani autoharness -Z uninit-checks` does not report uninitialized reads; on `main`, a function that reads a padding byte through a raw pointer verifies.

`is_harness` now also recognizes the automatic harness intrinsic.

### Testing

`tests/script-based-pre/autoharness_uninit_reset` runs `kani autoharness -Z uninit-checks` on two functions over a `#[repr(C)]` struct with padding. One reads a padding byte and now fails with "Reading from an uninitialized pointer". The other writes the byte first and verifies.
