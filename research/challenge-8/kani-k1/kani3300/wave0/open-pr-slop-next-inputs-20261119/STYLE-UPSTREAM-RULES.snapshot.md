# Правила для кода и текстов, уходящих в upstream Kani (2026-11-16)

Источник: независимый аудит внешних текстов стека. Обязательны для всех заданий, где пишется код/тесты/описания для upstream.

## Код и комментарии
- Комментарий описывает код в том виде, в каком он лежит в файле, для человека, который диффа не видел.
  Не писать, чего код НЕ делает («This does not…», «not X but Y», «rather than»), не ссылаться на «existing»/«previous» поведение.
- Без капса-запретов (NEVER, ONLY, ALL, AFTER) и внутренних меток (A3, MU, B1, slice, seed, witness, qualification, root, receipt).
  Слова upstream: memory initialization state, shadow memory, analysis targets, unused closures, contract pass, recursion, parameters, padding / uninitialized bytes.
- Код, перенесённый без изменений, переносить с исходным комментарием upstream дословно.
- «Невозможная» ситуация в необязательном уточнении (маски и т. п.) — консервативный пропуск с `debug!`, а не `fatal`.
- Unit-тест называется по тому, что он реально проверяет.
- Пользовательская документация — языком пользователя: что поддерживается, что увидит пользователь.
- Тесты: минимальное число каталогов/файлов; один каталог autoharness проверяет несколько функций. Без `--cbmc-args --object-bits` без нужды.
- Каждый PR содержит тест, который на `main` даёт неверный результат, а с изменением — верный.

## Тексты PR/комментариев (проверка перед сдачей)
1. Первое предложение описывает поведение Kani, воспроизводимое командой.
2. Нет предложений «This does not…», «These are not…», «No … is claimed». Ограничение — только если пользователь о него споткнётся.
3. Каждый термин есть в документации или исходниках upstream на `main`.
4. Не больше одной ссылки на прогон; без SHA голов/родителей и счётчиков тестов.
5. Сказано, что падает на `main` и проходит здесь.
Структура PR как в смерженном kani#5153: два абзаца сути, короткий Testing с одной ссылкой на полный прогон стандартных workflow, лицензия, строка раскрытия
«*Disclosure: this change and description were prepared with the help of AI assistants.*». Без Co-Authored-By.
