Type-resolution rules from Kani `to_irep.rs:134–156,781–1000`:

- Resolve struct_tag/union_tag through `namedSub.identifier.id`→the named type symbol→its `type`, retaining each pointer/reference. A typedef is serialized as the underlying type with `namedSub["#typedef"]`; do not look only for a fictitious typedef node or use its label as a standalone type identity.
- Array/vector element is `sub[0]`; array size is a typed expression under `namedSub.size`, not a decimal presumed from its text. Decode constant representation only after checking expression type/width/signedness and source encoder; unresolved/nonconstant/infinite size stays symbolic/UNKNOWN. Kani flexible arrays serialize as zero arrays, so distinguish them only with an actual source/type binding. Do not turn usize::MAX values from other expressions into lengths.
- Struct/union members are `namedSub.components.sub` entries, with `namedSub.name` and `namedSub.type`. `#is_padding` marks explicit padding. Union fields serialize only padded_typ; the original logical typ is discarded by this representation. Logical payload width requires an independently bound source/type/layout projection; otherwise mark it UNKNOWN. Retain logical payload versus storage size distinction. Do not sum union alternatives or add guessed ABI padding. Unknown component/offset/alignment means UNKNOWN unless the validated backend layout or exact explicit-storage model supplies it.
- Pointer width is its declared bit width, independent of pointee size. Report target links separately and stop pointer recursion for storage sizing. Kani logical `bool` versus C/storage bool and bitvector widths must stay distinct; `bool` lacks a `width` field in this schema. Bind storage size from the machine model/backend layout, not an assumed one-bit Boolean encoding.
- Incomplete tags, missing symbols, unbounded integer/code types, symbolic extents and cycles have explicit unresolved statuses. Never call Type::sizeof/sizeof_in_bits on incomplete/recursive types or rely on a panic as a query result.

If coordinator implements pure Python projection, use arbitrary-precision integers and scalar products for N×element_bits. Check isType/kind and malformed/missing nodes before following a reference. Stop with coverage/limit reason, not a global top20 claim when a cap truncates discovery. No expansion of N elements and no width-sized allocation. These are recipe limits, not claimed installed-interface flags. No extraction implementation or synthetic test result is claimed in this package.
