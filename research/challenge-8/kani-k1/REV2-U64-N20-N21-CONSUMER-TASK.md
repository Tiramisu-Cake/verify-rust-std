## Что связывает опоры с фактической сетью

Домен — инициализированный `[u64;34]`, полный числовой `<` через тот же `u64_less`, активный срез `v[1..1+N]`. Пост на нормальном возврате — числовой порядок, полное входное мультимножество слов и неизменность внешних слов. У индекса опор SHA-256 `e9ed86f4712bb3d6307b4b8be309bd8c3fb934d8a0457a2c26155bc6a1199410`, 32 члена. Сверь их хэши и точные режимы нужных опор. Применяй утверждённое правило для общих ID. Покажи, как полноширинные min/max и битовый post на всех масках дают порядок по порогам и кратности слов. У переноса слева добавленное слово произвольно и остаётся во frame sort9. У переноса справа исключённое слово никогда не читается. Проверенные точные отображения вставок замыкают числовой порядок перед merge и сохраняют мультимножество. Для merge используй ранги `(полное значение, индекс после вставок)`. До пары `0≤k<10` каждый поток up/down потребил k элементов своего обхода и адреса обеих половин валидны. Tie-left и tie-right выбирают соответственно меньший и больший ранг. Десять пар записывают в разные ячейки первые и последние десять рангов. Для N20 отсюда `a+c=b+d=10`. Для N21 ровно один остаток обрабатывает actual ветка на `:1027–1036`. Проверь обе формулы равенств на `:1042`, включая левый reverse sentinel при `c=10`. Доказанный набор записей, включая odd center, даёт инициализированные `D[0..N]` перед `:425`. Инициализация — внешний вывод при `uninit OFF`. Покажи, что вывод применим к actual веткам, а объединение write sets сохраняет конечный frame. Локальный корень copy-back проверяет последнюю операцию на уже инициализированном префиксе.

- **Локальные copy-back.** Для каждой N независимые произвольные `[u64;N]` и V34. Запиши N полных слов в отдельную живую `MaybeUninit<[u64;32]>`. Одним actual `ptr::copy_nonoverlapping::<u64>` скопируй ровно N слов из префикса в `v[1..1+N]`. Не читай остаток scratch. Требуй скалярные `DEST_EQUALS_SOURCE`, `SOURCE_PREFIX_FRAME`, `V34_FRAME` и cover `AFTER_COPY_BACK_FRAME` после постов. Привяжи к `:425:9` по порядку вызовов, размерам объектов 272 и 256 байтов, выравниванию 8, раздельности, `count=N` и точным диапазонам. [Образец локальной проверки](REV2-U64-N18-N19-CONSUMER-HANDOFF.md#copy-back-и-конечный-frame)
- **Контроли.** Literal `0x0000_0401` для обеих длин, биты 0 и 10 соответствуют началу левой и правой половин. В каждом префиксе есть единица, tail-слова нулевые. Первая вставка с обеих сторон и вторая правая N21 делают по сдвигу. Actual `small_sort_network::<u64,_>` выполняется с обеими сетями sort9, вставками, merge и copy-back телом. Внешние слова произвольны. После `AFTER_COPY_BACK` проверь каноничность и правильную маску до порчи, затем `v[1] ^= 1u64`. После порчи тот же оракул канонической отсортированной маски по исходному popcount должен дать единственный отказ `REV2_U64_N{20,21}_ACTUAL_SORTED_POPCOUNT`. Frame и каноничность успешны. Пара масок до/после — `0x000c_0000 → 0x000c_0001` для N20 и `0x0018_0000 → 0x0018_0001` для N21. Нужны covers фактического компаратора, mixed input и actual возврата. Сверь трассы по фактическому расписанию. Для N21 ожидаются счётчики `(a,b,c,d)=(9,1,1,9)`, центр читает `S+11`. Это один маршрут различающего контроля. Обе стороны центра и sentinel покрываются отдельным существующим Check.
- Во всех четырёх слотах сверь шесть grouped свойств `ptr::copy_nonoverlapping::<u64>` на `core/src/ptr/mod.rs:587:14` и выведенные unwinding assertions при stock `unwinding=ON`. В локальном корне единственный целевой copy call связывает группу с точной геометрией. В контроле фактический возврат и исходные координаты связывают группу с `:425`. Regular подтверждает function/class/file/line/column/status. Stock подтверждает exact Proof, reach, профиль и тот же ID единственного `FAILURE` класса `assertion` в каждом контроле. Любой другой отказ, пропуск обязательного cover или потерянный anchor оставляет длину открытой. [Привязка предыдущих корней](REV2-U64-N18-N19-CONSUMER-HANDOFF.md)
