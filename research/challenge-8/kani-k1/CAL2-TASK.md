# CAL2 · задание на диагностический пакет

Подготовить один fork-пакет с независимыми Ubuntu и macOS jobs. Ubuntu измеряет две пары A/B и два коротких контрольных корня. macOS повторяет свою часть CAL1 с отдельным капом discovery. Пакет измерительный, `proof_credit=NONE`. 120 с VT и рабочие ориентиры памяти оформить как справочные поля отчёта. Решение о лимитах приёмки и режиме штатного CI остаётся отдельным. - **S13.** Одна геометрия `v[1..14]` на `[u8;34]`, независимый `q: u8`, `KeyLess<u8>`, Check реального `sort13_optimal`, реальные 45 swaps, без stubs, unwind 36. Оба плеча используют одинаковый код, q-post, q/V34 frame и covers CAL1. После нормализации путей argv различается только значением OB. `too many addressed objects` в OB11 является отдельным диагностическим исходом. Замер на OB11 не переносить на OB12.
- **MERGE.** Одна переменная — форма эквивалентного q-наблюдателя. В варианте Mask повторно использовать уже имеющиеся `merge_target_mask` и `merge_matches_mask` на N32. При `b=#(x<q)` маска `((1_u64 << 32) - (1_u64 << b)) as u32` задаёт единицы на позициях `i>=b` для всего `b∈[0,32]` и эквивалентна `Below`. Новый cfg влияет лишь на выбор представления N32 в `merge_capture`. Оба плеча используют тот же Check `bidirectional_merge`, actual `merge_up/down`, numeric order обеих половин `v[1..33]`, независимый q, `MaybeUninit<[u8;32]>` с dst по offset 0, те же requires/assigns/q-frame/V34 source frame и covers CAL1. Сохранить финальную проверку курсоров actual merge. Без новых `assume` и чтения old dst. Mask должен оставлять N25 и все остальные длины прежними. Привести в handoff проверку эквивалентности для крайних b и смешанного случая.
- Связку verified stubs `merge_up/down` оставить для отдельной работы. На точном пине return Replace генерируется через `any_modifies` → `any<T: Arbitrary>`, а шаги возвращают кортеж сырых указателей. Старые Check листьев покрывают N18/N19, а не курсоры N32. Замена observer сохраняет проверку всей цепочки и позволяет измерить одну дельту на текущем пине. [Причина из пакета B](item2-audit-response-20261120/PILOT12-IMPL-TASK.md#решение-по-replace) · [Эквивалентность N32](item2-audit-response-20261120/ADMISSION-N32.md) · [Выбор observer в CAL1](/root/verify-rust-std-cal1-w11/library/core/src/slice/sort/shared/smallsort/verify/cal1_q_merge_model.rs:178)
- N8/N9 сохраняют тела, full-value oracle, внешний frame, unwind 40 и пять covers. Исход для сверки запуска — `VERIFIED` с 5/5 в CAL1. Записать отклонение и продолжить остальные слоты, если supervisor и cleanup исправны. У Ubuntu нет batch этого пакета. Окна дают 72 мин в прежнем бюджете job. Номинальный cap 10 GiB, резерв 2 GiB. Сравнивать условия допуска по effective cap, начальному available и давлению. Разница этих условий ограничивает A/B.

## Метрики Ubuntu

1. Для четырёх слотов A/B брать групповой RSS и RSS всех принадлежащих запуску CBMC из **одного** штатного census. Записать monotonic timestamp, фазу, PID/start identity и число backend процессов. Сохранять групповой пик и RSS CBMC в его сэмпле, отдельный пик RSS CBMC со своим timestamp, последний валидный сэмпл перед остановкой, счётчики и cadence. При нескольких CBMC различать per-PID и сумму. Запись в отсутствие backend должна явно показывать `cbmc_count=0`.
2. На Linux брать точную строку `Pss:` в KiB из `/proc/<pid>/smaps_rollup` для CBMC с подтверждённой идентичностью из того же census. Выборочно, не чаще раза в секунду, с ограниченным числом незавершённых чтений и без ожидания на пути RSS/pressure/TERM/KILL. Привязать наблюдение к номеру/времени RSS-сэмпла и указать задержку чтения. Смена PID, ошибка доступа, исчезновение, отсутствие `Pss:` или слишком поздний ответ дают `null` с причиной. Сохранить число попыток и удачных наблюдений. Если PSS на самом пике отсутствует, показать отдельно ближайший валидный RSS/PSS-сэмпл с его временем. Guards продолжают использовать прежний RSS. CBMC PSS не определяет PSS всей группы. [Процессные метрики Linux](https://docs.kernel.org/filesystems/proc.html#process-specific-subdirectories) · [Текущий census](/root/kani-cal1-control-w11/ch8-cal1/supervisor.py:708)
