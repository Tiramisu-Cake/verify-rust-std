# REV2 · правило составного исследовательского допуска

Предлагается к утверждению координатором. Исследовательский допуск может опираться на проверенные нативные леммы и внешний аргумент, если вместе они устанавливают указанный пост на всей заявленной области фактического вызова. Действующие примеры — перенос sort13 по порогам и длине и индукция по рангам для merge 16+16. [Ревью S13](REV2-S13-LEFT16-REVIEW.md) · [Ревью merge](REV2-MERGE-RANK-INDUCTION-REVIEW.md)

1. **Допустимый внешний шаг.** Нужны явные предпосылки, доказанный вывод и область. Принимаются индукция по точному циклу, перенос по проверенному расписанию, эквивалентность наблюдателей и доказанное сужение геометрии. Аргумент устанавливает применимость леммы на каждом реальном вызове, сохраняет frame и доводит результат до требуемого поста. Перебор или симуляция помогают проверить аргумент. Самостоятельным доказательством они служат только для исчерпывающе проверенного конечного домена с доказанной привязкой. Выводы об инициализации из семантики фактических записей помечаются как внешние при `uninit OFF`. Инструментальное покрытие UB указывается по фактическим флагам.
2. **Привязка.** На каждом ребре фиксируются точный Std commit/tree, существенные source blobs или проверенная дельта, мономорфизация, реальные call sites и порядок, геометрия, тип, компаратор, начальное состояние, pre/post, write set и frame. Проверка сравнивает отличные роли по явно заданным базовому и целевому SHA. Изменение связанного исходника, cfg или профиля требует сверки перед повторным использованием. Для нативной опоры сверяются tool pin, object bits, unwind, флаги проверок, exact selector и режим, run/attempt, хэши receipt/projection по индексу, ID/Location/status нужных свойств и достигнутые covers. Различающий контроль проверяет ожидаемый пост или границу. Covers подтверждают достижимость, а объём доказательства берётся из успешного свойства и привязки. Опора требует завершённого успешного результата и сохранённых обязательных anchors. Для общих ID действует принятое правило grouped properties. [Grouped properties](item2-audit-response-20261120/GROUPED-PROPERTY-DECISION.md)
3. **Ревью и запись допуска.** Автор сдаёт воспроизводимую сверку и таблицу обязательств с разделением нативных и внешних шагов. Независимый ревьюер проверяет доводы, точную область, источники, anchors и фактическое закрытие промежуточных предпосылок. Координатор утверждает правило и оформляет строку допуска на принятую область. Существенный `UNKNOWN`, несовпадение или открытое ребро остаются видимыми в графе. Строка для провайдера и строка для конечного consumer оформляются по своим обязательствам. Отчётный статус диагностического run и его `proof_credit` сохраняются.
4. **Граница pr752.** В исследовательской строке явно указано «составное свидетельство» и где использован внешний вывод. Нативному `stub_verified` соответствует проверенный Check вызываемой цели на достижимой области или отдельно проверенный механизм, который передаёт доказательство в Replace. Публикацию внешнего аргумента и объём заявлений в pr752 решает владелец с учётом требований организаторов. Для утверждения о покрытии штатным CI нужны результаты в его точном профиле на обеих ОС и соблюдение лимитов проверки и партиции. При описании составного результата указывается, какая часть проверена Kani и какая обоснована внешним аргументом. [Лимиты владельца](OWNER-DECISION-LIMITS-20261125.md)

**Утверждено координатором 2026-11-26** для исследовательского допуска. Решение о заявлениях в pr752 и о публикации внешних аргументов остаётся за владельцем (пункт 4).
