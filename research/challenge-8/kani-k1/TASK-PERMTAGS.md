## Идея

Прямые доказательства перестановки упирались в солвер: u8 до N9, u64 N8 только с kissat. Формулировки были такие:
- произвольные значения;
- проба по полному значению;
- конкретный строгий порядок.

Другая формулировка:
- вход — **попарно различные теги** `0..N` в известном порядке;
- компаратор с **произвольным ответом** на каждый вызов (`kani::any()`, читает оба аргумента);
- проверка: после возврата выход содержит каждый тег ровно один раз. Например, OR по `1 << tag` равен
  `(1 << N) - 1` при N ≤ 32 и тип маски достаточной ширины. Или эквивалентная проверка без u128.

**Почему это закрывает перестановку для любых значений и любого компаратора на этом маршруте.** Код SmallSort
перемещает элементы только в зависимости от ответов компаратора; от самих значений он не ветвится, кроме выбора
маршрута по типу. Компаратор с произвольным ответом перебирает все последовательности ответов. Различные теги
однозначно отслеживают, какой элемент куда попал. Это рассуждение записать в doc модуля и в RESULT как допущение.
Отдельным корнем проверить, что маршрут для типа тегов совпадает с маршрутом исходного типа.

## Что сделать

Новый opt-in модуль `verify/permtags.rs` под `cfg(kani_smallsort_controls)`; регистрация в `verify.rs`.

1. **Network, u8** (Unstable entry, Freeze + Copy, size 1): N9, N13, N16, N17, N32. Отдельные корни по длинам.
2. **General, u64** (Stable Freeze со scratch 48): N9, N16. При запасе N17 и N32.
3. **Fallback/insertion** (blanket Stable на non-Freeze, например `Cell<u8>`; или Unstable fallback): N16.
4. **Негативный контроль:** мутант, который дублирует один элемент: копия сортирующего вызова плюс
   `ptr::copy` поверх соседнего. Он должен упасть на проверке маски.

Panic-stub `panic_on_ord_violation` такой же, как в safety-семействах Part 1: при произвольном компараторе
guard достижим. Тогда перестановка утверждается для нормального возврата.
