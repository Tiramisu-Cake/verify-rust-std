## How to read this registry

- A record is keyed by **contract target × tag × domain**. The same tag in another function, length or backing does
  not share a proof. Shared fields (tag passport, contract summary) are expanded in the two tables below.
- `T` is the element type. `F` is the Rust type of the comparator argument actually passed: always the
  **function pointer** `fn(&T, &T) -> bool`, not a function item and not an arbitrary `FnMut`. `CMP` is its value.
- For `swap_profile`, `N` is the backing array length; exactly two positions are selected. Elsewhere `N` is the
  active region length, and the backing length is given separately. Sets such as `N ∈ {2,…,9}` list every executed
  length; the harnesses choose them by a nondeterministic value or by separate harnesses.
- **Requires admit** describes what the contract accepts; **executed domain** describes what the harness builds.
  Only the executed domain is claimed (see "Requires admit vs executed domain").
- Each profile forwarder takes `cmp` by value and passes `&mut is_less` with `is_less = cmp` to the real helper:
  [specfix.rs:228](https://github.com/Tiramisu-Cake/verify-rust-std/blob/d6b8caf7fe/library/core/src/slice/sort/shared/smallsort/verify/merge/specfix.rs#L228), [specfix.rs:252](https://github.com/Tiramisu-Cake/verify-rust-std/blob/d6b8caf7fe/library/core/src/slice/sort/shared/smallsort/verify/merge/specfix.rs#L252), [specfix.rs:295](https://github.com/Tiramisu-Cake/verify-rust-std/blob/d6b8caf7fe/library/core/src/slice/sort/shared/smallsort/verify/merge/specfix.rs#L295),
  [specfix.rs:329](https://github.com/Tiramisu-Cake/verify-rust-std/blob/d6b8caf7fe/library/core/src/slice/sort/shared/smallsort/verify/merge/specfix.rs#L329). Requires compare the pointer with the canonical `P::CMP` by address
  ([specfix.rs:133](https://github.com/Tiramisu-Cake/verify-rust-std/blob/d6b8caf7fe/library/core/src/slice/sort/shared/smallsort/verify/merge/specfix.rs#L133)). Specifications evaluate the model only and never call the comparator
  ([specfix.rs:140](https://github.com/Tiramisu-Cake/verify-rust-std/blob/d6b8caf7fe/library/core/src/slice/sort/shared/smallsort/verify/merge/specfix.rs#L140), [specfix.rs:159](https://github.com/Tiramisu-Cake/verify-rust-std/blob/d6b8caf7fe/library/core/src/slice/sort/shared/smallsort/verify/merge/specfix.rs#L159)).
- `init` describes the harness fixtures. `can_dereference` states a readable/initialized premise, but the
  organizer run has no uninitialized-memory instrumentation, so uninitialized reads are not detected automatically.
- The `modifies` check on the contracted body and explicit frame assertions after the call are separate checks.

## Requires admit vs executed domain

The requires describe the precondition under which each contract is stated; the harnesses execute only the
domains in the registry. In particular:

- `swap_profile` admits any two distinct positions of any allocation and any element type of a profile; executed
  are the 14 listed backings (lengths 2, 4, 9, 13, 17) at offset 0.
- `sort4_profile` admits any valid disjoint four-element spans; executed are separate exact arrays at offset 0.
- `insert_tail_profile` admits `N ∈ {2,…,32}` in any suitable subregion; executed are `u8` begin 0 with
  `N ∈ {2,…,17}` and `u64` begin 1 with `N ∈ {2,…,16}`, both in an initialized 17-element backing.
- `merge_profile` admits `N ∈ {2,…,32}` and disjoint placements, including one allocation; executed are exact
  `u64` N2..8 and `u8` N2..9, and `u8` N9 from offset 0 of both 48-slot scratch forms to a separate `[u8; 9]`.
- The wrappers admit any valid pair placement (and, for `stable_cell`, any valid scratch); executed is N2 at
  offset 1 of a four-element backing, with the scratch shapes listed above.

## Not established

1. The requires domain (`N` up to 32, arbitrary placements) is not executed coverage.
2. Results for exact arrays do not transfer to same-allocation subregions, other scratch offsets or other lengths
   without a separate argument.
3. **`Sort4ReadU64` is not `LtU64`.** `sort4_profile` uses canonical `sort4_read_lt_u64`, with extra volatile
   reads, and the probe `PROFILE_PROBE_SORT4_U64`; `merge_profile` and `insert_tail_profile` use `lt_u64` and
   `PROFILE_PROBE_LT_U64`. The same `x >> 1` order does not make the function pointers equal or the probes shared.
   The real general sort passes one comparator through sort4, insertion and merge
   ([smallsort.rs:254](https://github.com/Tiramisu-Cake/verify-rust-std/blob/d6b8caf7fe/library/core/src/slice/sort/shared/smallsort.rs#L254), [smallsort.rs:274](https://github.com/Tiramisu-Cake/verify-rust-std/blob/d6b8caf7fe/library/core/src/slice/sort/shared/smallsort.rs#L274),
   [smallsort.rs:286](https://github.com/Tiramisu-Cake/verify-rust-std/blob/d6b8caf7fe/library/core/src/slice/sort/shared/smallsort.rs#L286)); no checked transition between these tags exists. Likewise
   `Sort4ReadB16` and `KeyB16` have different canonical comparators. A future bridge would need a shared chosen
   witness or a checked correspondence; mathematical equality of the order is not enough for canonical identity.
4. **No summary composition in the ordinary suite.** The four `stub_verified` uses of the profiles are only in the
   opt-in wrong-comparator harnesses listed above. Real callers call the raw helpers, not the profiles, and
   manual panic stubs in real-body harnesses are not uses of a profile summary. No end-to-end composition is claimed.
5. **Model trust is open** for exactly `network::swap_contract_bytes16_n2`, `network::swap_contract_bytes17_n2` and
   `merge::sort4_contract_bytes16_n4`. for a `[u8; 1]` element read through a conditionally selected pointer, Kani reports a false
   counterexample ([Kani #5104](https://github.com/model-checking/kani/issues/5104)); these three
   harnesses read byte arrays through selected pointers. Their SUCCESS is reported as is, but neither the cause, a
   false SUCCESS, nor any padding or initialization guarantee is established.
6. Inventory membership, opt-in harnesses and results on other source trees are not evidence for this snapshot.
7. No generalization to arbitrary `T`, `Profile` or effectful `FnMut`, to the default `<` for the `Lt*` tags, to tie
   stability, initialization detection, panic or unwind safety, or to the full thresholds. All counts are over the
   full typed logical model, not over one key or object padding.
