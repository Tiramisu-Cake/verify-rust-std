# REV2 · диагностика валидности на Kani main

Задание для w11 по направлению 3. Сначала локально проверь совместимость main Kani с неизменённым Std pr752. Затем подготовь пакет с двумя фазами для отдельного ревью. Kani `8c6dba5935e8b37a905145c57572d1b67489bae2`, Std `dab03cf510df5c35141cde49f1368b1242f5035e`. Закрепи эти SHA в отдельных worktrees. Kani 5205 переносит проверку с побайтовой записи на поддерживаемые типизированные чтения, в том числе после `copy`, `copy_nonoverlapping` и `write_bytes`. Модель валидности всё ещё имеет ограничения по layout и местам чтения, в частности для проекций элементов среза и дискриминантов агрегатных enum. Работа локальная, без CI, push, смены пина организаторов и правок runtime std. ## A. Standalone OFF/ON

Один малый fixture `.rs`, без сборки пользовательского Std. В матрице будущего прогона у каждого exact selector два слота с одинаковыми solver, OB12, unwind и safety checks. Единственная разница в аргументах проверки — `-Z valid-value-checks` в ON. `-Z uninit-checks` оставить OFF. Все цели доступа выровнены и в пределах живых объектов, nonoverlap действительно раздельный. Невалидный `char` записывается только как сырой байтовый шаблон. Первое типизированное чтение должно быть явным и иметь собственную строку. Используй сырой указатель до чтения, чтобы создание ссылки не стало первой проверяемой операцией. Не добавляй утверждение о значении намеренно невалидного `char` после чтения. [Тесты копирования на пине](https://github.com/model-checking/kani/blob/8c6dba5935e8b37a905145c57572d1b67489bae2/tests/expected/valid-value-checks/copies.rs) · [Тесты write_bytes на пине](https://github.com/model-checking/kani/blob/8c6dba5935e8b37a905145c57572d1b67489bae2/tests/expected/valid-value-checks/write_bytes.rs)

| Exact case | Что выполняется | Ожидание ON |
| --- | --- | --- |
| `copy_valid_read` | `ptr::copy` с валидными `char` и перекрытием, затем типизированное чтение | `SUCCESS`, результат соответствует copy с перекрытием |
| `copy_invalid_read` | `ptr::copy` из выровненного сырого источника с суррогатом `0xD800`, затем чтение `char` | Единственный validity `FAILURE` на чтении |
| `nonoverlap_valid_read` | `ptr::copy_nonoverlapping` произвольного валидного `char`, затем чтение назначения | `SUCCESS`, значение сохранено |
| `nonoverlap_invalid_read` | Disjoint copy шаблона `0xD800`, затем чтение `char` | Единственный validity `FAILURE` на чтении |
| `copy_overwritten` | Скопировать невалидные биты, записать валидный `char` до чтения | `SUCCESS`, наблюдается валидное значение |
| `write_bytes_zero` | `count=0`, байт `0xFF`, перед чтением в слоте есть прежний валидный `char` | `SUCCESS`, слот не изменился |
| `write_bytes_raw_only` | `count=1`, `0xFF` в `MaybeUninit<char>`, после записи наблюдаются только сырые байты | `SUCCESS` |
| `write_bytes_valid_read` | `count=1`, байт `0`, затем чтение `char` | `SUCCESS`, прочитан `\0` |
| `write_bytes_invalid_read` | `count=1`, `0xFF`, затем чтение `char` | Единственный validity `FAILURE` на чтении |

В OFF ожидается завершённый `SUCCESS` по включённым проверкам, включая намеренно невалидные контрольные чтения. Это проверка чувствительности флага. Для ON-negative требуй терминальный `FAILURE` с ID, классом, описанием `Invalid value of type` и координатой ожидаемого typed read, до которого есть cover на raw write. Для ON-positive требуй терминальный `SUCCESS` и covers на выполненные операции. Если проверка срабатывает на самой записи, чтение недостижимо, не найдено в нативном выводе или результат объясняется `unsupported_construct`, сохрани наблюдение и останови продвижение к Std-фазе до разбора. [Ожидаемый upstream вывод](https://github.com/model-checking/kani/blob/8c6dba5935e8b37a905145c57572d1b67489bae2/tests/expected/valid-value-checks/copies.expected)

## B. Реальные маршруты SmallSort

Отдельный verification-only модуль с harnesses под opt-in cfg в Std поверх `dab03cf510`. Все корни plain `Proof` с `--no-assert-contracts` и штатными safety/overflow/unwind checks. Исполняются реальные тела, включая `panic_on_ord_violation`, без stubs. Проверь отсутствие новых регистраций при выключенном cfg. Используй валидные произвольные значения `bool`, Unicode scalar `char`, `NonZeroU8`, полный порядок и компаратор без паник. Scratch в actual вызовах начинается `MaybeUninit`. Проверяй нормальный возврат, порядок и короткий пост о сохранении полных значений, с covers нетривиального входа и завершения участка. Явно наблюдай значения после переноса через подходящее типизированное чтение. Для каждого root сверяй место инструментированного чтения с уровнем исходника. Чтение из scratch должно следовать за реальными записями. [Места переноса в SmallSort](STATUS-S4-AND-KANI3762-20261123.md#2-kani-3762-и-5190-валидность-после-побайтовой-записи)

| Предлагаемый selector | Точная форма |
| --- | --- |
| `vv_swap_bool_n02` | Actual `swap_if_less`, `bool`, позиции 0/1. Covers swap/no-swap. `ptr::copy` и `copy_nonoverlapping` внутри тела. |
| `vv_fallback_nonzero_n03` | Actual `small_sort_fallback`, `NonZeroU8`, N3. Вставки со сдвигом и заполнением зазора. |
| `vv_stable_char_n09` | `<char as StableSmallSortTypeImpl>::small_sort`, N9 и scratch N+16, путь `small_sort_general_with_scratch`, два `sort4_stable`, досортировка и нечётный merge. |
| `vv_sort8_char_n08` | Actual `sort8_stable`, N8. Раздельные input, scratch и dst, последние два по восемь `MaybeUninit<char>`. Закрывает вложенные `sort4` и merge отдельно от полного general N16. |
| `vv_network_nonzero_n19` | Actual `small_sort_network`, `NonZeroU8`, N19. Половины 9+10, actual sort9 и вставка, оба шага merge, odd copy и copy-back. Последний слот для оценки стоимости целого network. |

Поставь OFF и ON в матрицу для одних и тех же корней. Добавь один matched контроль `vv_stable_char_n09_corrupt` OFF/ON. После реального стабильного маршрута и до проверяемого типизированного чтения подмени в одной выходной ячейке сырое представление на `0xD800`. В положительном корне то же чтение выполняется над исходным выходом. Проведи остальные функциональные проверки до точки порчи. В ON у контроля ожидается единственный назначенный validity `FAILURE`. Зафиксируй, что этот контроль проверяет наблюдаемость потребителя после actual маршрута. Для внутренних чтений опирайся на нативные проверки и привязку к исходнику. [Известные ограничения инструмента](https://github.com/model-checking/kani/pull/5205)

## Профиль, evidence и handoff

- Подготовь первую будущую диагностику на Ubuntu с фазами A → B и отдельными receipts. Запуск B зависит от совместимости Std и ожидаемых результатов A. При неожидаемом исходе A опубликуй все состоявшиеся наблюдения и отметь B как `NOT_RUN` с причиной. Используй проверенный supervisor и ограниченную проекцию из существующего пакета, если они совместимы с новым tool. Зафиксируй pinned request, точные selectors и argv, setup, cold wall, VT, group/CBMC RSS, фазу отсечки, первую CNF, нативные property ID/Location/status и covers. Не принимай aggregate `SUCCESS` как свидетельство наличия validity checks. Если ограничение проекции скрыло нужную привязку, пометь её `UNKNOWN`.
- Пределы владельца для новой проверки — 4 GiB и VT ≤120 с. Первичный отбор Std-корней — cold wall ≤180 с, jobs=1, резерв Ubuntu 2 GiB. Для коротких standalone предусмотри меньший слот по локальному smoke и отдельное окно reap/receipt. Рабочая оценка одного Ubuntu job — 110–120 мин, если у standalone слотов по 45 с cold wall плюс 15 с на reap/receipt, у 12 Std-слотов по 195 с, а setup с discovery до 35–45 мин. Уточни эту оценку и учти старт каждого слота и публикацию до заморозки пакета. Таймаут или давление памяти дают незавершённый диагноз. Ресурсный результат на Ubuntu не закрывает критерий обеих ОС. Для переноса отдельно нужны macOS VT и RSS с резервом 1,25 GiB, штатные групповые пределы и прирост критической партиции до +5 мин. [Решение владельца](OWNER-DECISION-LIMITS-20261125.md)
- Разделяй ошибку совместимости, неподдерживаемый layout или вид чтения, расхождение OFF/ON и валидность реального значения. `u8` и `u64` без ограничений на битовые представления годятся как baseline маршрута. Свидетельство чувствительности берётся с restricted types и отрицательных контролей. Совместный validity/uninit ON, Check/Replace с havoc, паника компаратора, полные матрицы длин и допуск pr752 остаются за пределами этой диагностики.
- Сдай `REV2-VALIDITY-MAIN-HANDOFF.md` в g0 с локальным вердиктом о совместимости, worktree/parent/commit/tree, версиями, exact roster и ожидаемыми исходами, верифицируемой упаковкой Std и control, `rustfmt`/статикой и результатами синтетических тестов изменённой обвязки. Приложи оценку окон и минимальный следующий пакет при блокере. Затем независимое ревью и отдельный GO. В этой стадии CI и push запрещены. Локальные коммиты с `[skip ci]`. Во всех commit messages, включая research, ledger, control и trigger, запрещён знак решётки непосредственно перед цифрой. Используй `pr752`, `kani5205`, `issue3762`.
