### Обязательные решения координатора о default и интеграции

1. Прежняя версия old(count) семантически эквивалентна count после вызова,
   так как v не в modifies, но её кодировка со снимком keys[64] другая.
   Старые времена/gate на неё не переносятся. Требование — default вновь
   сравнивает прежние count_u после вызова; его снимок только pointer+length.
2. До итога L2-1 новый контракт остаётся только на этой ветке. L1 собирает
   старый контракт. Интеграция — только при выигрыше H1, затем L1 перемеряет
   bm_*/w2p2_bm_*2..16/E-1, sort8 со stub(bm), w2p2_gs_*/general_* со stub(bm),
   R11. При восстановленном прежнем default старые результаты представительны,
   при сведении нужна перепривязка к коммиту; это не объявляется новым замером.
3. Старая формулировка L2-1 на Tagged должна иметь отдельную гармонику
   с пробой полного Tagged через default/K1Probe, теми же входом, типом,
   решателем и proof_for_contract-режимом. Отношение времён — относительно неё,
   не относительно u64 E-1. Новые длины L2-1 не начинать до нового вердикта.

### Исправления S1/S2/default для нового review

- `tagged_contract<N>` теперь использует `kani::any::<[Tagged;N]>()`:
  произвольны и key, и tag. Различие и tag<64 задаёт только requires.
  Covers: normal return, tag первого элемента63, tag0>tag1 (нетождественный
  порядок). Fixed base+i сохраняется только в отдельных caller/мутантных
  контролях, не ограничивает область contract proof.
- Default snapshot = tuple `(*const T, usize)`, без массива ключей и без
  чтения пробы до вызова. Default matcher буквально вычисляет
  `count_u(input_ptr,input_len) == count_u(dst,len)` после вызова.
  Default requires = true. K1TaggedSnapshot с keys[64] создаётся только
  внутри специализированных helper-ов.
- Для Tagged tuple сохраняет адрес и длину входа. Value-map строится
  по этому региону после вызова: источник &[T], дискретен с dst и не входит
  в modifies. Поэтому его пары равны входным; это явная опора новой кодировки
  и предмет нового review. `old()` теперь сохраняет только pointer+length,
  не ключи и не их count. Runtime-тело merge не изменено.
- S2 закрывается измерением уже написанной
