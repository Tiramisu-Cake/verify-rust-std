# REV2 · первые опоры N18/N19

Задание для **w14**. Подготовь один локальный пакет из шести singleton для Ubuntu. Цель — измерить составные опоры sort9, правой вставки N19, общей пары merge и нечётной записи. Сквозные consumers N18/N19 и их контроли идут после разбора этого пакета. Базы в отдельных worktrees — Std `49811849392302943d45b02beb4b0403509b9447` и control `ee6156445c9cdd30912d1b3a41f9e4b2444caf25` из прошедшего N17. Без push, изменений Actions variables, CI и локальных cargo, rustc, Kani или CBMC. Runtime std и действующие контракты побайтно сохраняются. [План N18–N31](REV2-N18-N31-PLAN.md) · [Пакет N17](REV2-N17-HANDOFF.md) · [Правило композиции](REV2-COMPOSITION-RULE.md)

## Точная область

Инициализированный произвольный V34, `u8/KeyLess<u8>`, независимый `q: u8`. N18 использует `v[1..19]`, половины `v[1..10]` и `v[10..19]`. N19 использует `v[1..20]`, правая половина `v[10..20]`. У обеих половин sort9 меняет только префикс длины 9. Вставка нужна только справа у N19, offset 9, rel9 / abs19. Merge получает те же две численно упорядоченные области и отдельный writable `MaybeUninit<[u8; 32]>` scratch. q сохраняется и не влияет на выбор. [Actual вызовы](/root/verify-rust-std-rev2-n17-w14/library/core/src/slice/sort/shared/smallsort.rs:367) · [Ранговая опора N32](REV2-MERGE-RANK-INDUCTION-HANDOFF.md#привязка-пары-к-actual-циклу)

Добавь модуль `rev2_n18_n19_providers` под `kani_smallsort_rev2_n18_n19_providers` и унаследованными cfg. Порядок слотов фиксирован. У положительных корней ожидаются `VERIFIED`, exit 0 и обязательные свойства и covers. Используй actual вызовы, без Replace, stubs и новых loop contracts. Подмножество пресорта и формы цикла фиксируются предусловиями из таблицы.

Левый лист base1 берётся из `S13-SWAP-LEAF` FIX3, его `b<13` включает все пары sort9. Правый лист проверяется на base10. Для каждой стороны обоснуй совпадение живой V34, provenance, пары адресов и специализации. Внешний пороговый перенос соединяет min/max с AND/OR и даёт полный байтовый пост. Для driver при том же fixed входе q не участвует в выборе, поэтому равенство счётчиков для всех q даёт все кратности, включая 255. ## Обязательства merge

**Пара.** При `a+b=c+d=k`, где a,b — число съеденных up элементов L,R, а c,d — down, передать `(S+a, S+9+b, D+k)` и `(S+8-c, S+N-1-d, D+N-1-k)`. a,c произвольны в `0..=k`, b,d — дополнения. В native домене обе половины численно упорядочены, a,c и N независимы в указанных границах. Используй writable-only scratch, без `assume_init` до установленных записей. Проверяй точную read/write/disjoint геометрию, обе тройки возвращённых курсоров, min/max в двух ячейках и как сторона определяется на равенстве. Native modifies — только `D[k]` и `D[N-1-k]`. Проверь обе копии по applicable grouped properties. Covers нужны для каждой длины, её k=0 и k=8, полезного возврата, обоих выборов каждой стороны и ties обоих направлений. Отдельно связать каждый N с соответствующими обязательствами. Прежний предикат CAL1 whole merge ограничен N20–N32, поэтому sorted halves для N18/N19 задать локальным числовым предикатом. [Образец M32-PAIR-STEP](REV2-MERGE-RANK-INDUCTION-HANDOFF.md#свидетельство-fix3)

**Центр.** При N19 и k=9 задать `a+b=c+d=9`, `a+c≤9`, `b+d≤10`, с неотрицательными счётчиками. По этим ограничениям ровно один элемент остаётся в одном из непересекающихся остатков. Сформировать cursor values с фактической wrapping-арифметикой reverse, в том числе при исчерпанной половине. Привязать `left_end/right_end` к `wrapping_add(1)`, выбор `left < left_end`, `ptr::copy_nonoverlapping(last_src, D+9, 1)` и оба обновления курсоров к pinned odd-фрагменту. Assert должен независимо определить ожидаемый исходный индекс из длин остатков, затем проверить записанный байт, оба итоговых равенства, source/q frame. Native modifies — только `D[9]`. Covers остатка слева и справа и достигнутого поста после копии. Читать выходной байт только после вызова с безусловной записью этой ячейки. В handoff показать эквивалентность verification-only wrapper фактическому фрагменту, включая reverse sentinel, который не разыменовывается. [Actual odd branch](/root/verify-rust-std-rev2-n17-w14/library/core/src/slice/sort/shared/smallsort.rs:1031)

**Связка с целым циклом.** Приложить таблицу N18 и N19 от входного числового порядка до итогового cursor guard. По порядку `(byte, входной индекс)` каждая пара снимает ранги k и `N-1-k`, сохраняет прежние записи и оставляет тот же source/q. Для N18 после девяти пар весь диапазон scratch заполнен. У N19 остаётся ровно rank 9 на proven odd-вызов, после которого оба равенства выполнены. Полная инициализация выводится из записей и непересечения при uninit OFF. Проверить, что копия в actual consumer сможет прочитать ровно N и записать `v[1..1+N]`. Отметить copy-back, сквозной post-return контроль и consumer binding как обязательства следующего пакета. Точный native Check у wrapper применяется только к его роли. [Составной N32](REV2-N32-ADMISSION.md#привязка-строки)
