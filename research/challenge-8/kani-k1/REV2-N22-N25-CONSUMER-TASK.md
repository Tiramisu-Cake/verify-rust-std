- **Presort.** Для B01 используй `S9-B01-L09-BITS` из `45749463113` и Check `S13-SWAP-LEAF` из `45661535099`. Для B13 используй `S13-B13-L13-SWAP` из `45688753097` на rel0–8 у N24 и на всех 45 парах у N25 с `S13-B13-L13-BITS`. Для same-base переносов сравни guard, base, 25 пар rel0–8, границы и frame хвоста. Порог `[byte≥t]` коммутирует с min/max, поэтому битовый результат даёт порядок и полные кратности префикса для произвольных байтов. [Исторические опоры](REV2-N22-N25-PROVIDERS-HANDOFF.md#исторические-опоры)
- **Вставки.** Для L11 выведи остановку после rel10 через actual префиксную индукцию. Перед каждым шагом уже обработанные байты упорядочены и сохраняют свои исходные кратности, хвост за ними исходный. `insert_tail` восстанавливает дыру из отдельного tmp, а сдвиги и чтения ограничены `[0,rel]`. Для L12 применяй byte post напрямую, включая q/frame. Из q-независимости компаратора и `count(<q)` для всех q следуют все кратности. Привязка должна дать две полные численно упорядоченные половины перед merge.
- **Merge.** Соедини exact pair с actual циклом по рангу `(byte, индекс в S после вставок)`. После k итераций записаны D[0..k] и D[N−k..N], следующие цели различны при k<m. Свяжи .7/.10 selected Check, min/max, frame и write set с actual up/down. У чётных длин после m шагов обе границы сходятся. У нечётных покажи оба положения единственного остатка, selected source в D[m] и завершение. После m пар `a+b=c+d=m`. Левый остаток даёт `(i,m−i,m−1−i,i+1)` при `0≤i<m`, правый `(i,m−i,m−i,i)` при `0≤i≤m`. Для канонических свидетелей исходные половины уже упорядочены и имеют i нулей слева и соответственно `m−i` или `m+1−i` справа. При правом остатке и c=m источник `S+N−1`, `left_rev=S−1` участвует только в wrapping-вычислении `left_end=S`. Повтори проверку концов для N23 и N25. Это внешняя привязка к проверенной транскрипции actual ветки. [Прецедент N21](REV2-N20-N21-ADMISSION.md#нечётный-центр-n21)
- **Copy-back и frame.** На фактическом вызове `smallsort.rs:425` размер равен N. Scratch32 отдельна от V34 и к этому моменту заполнена на D[0..N] по ранговому выводу. Выравнивание u8 равно 1. На каждом positive сохрани grouped `.safety_check.1/.2`, `.arithmetic_overflow.1`, `.precondition_instance.1/.2/.3` на `ptr/mod.rs:587:14` и `AFTER_COPY_BACK` вместе с точной привязкой последней копии. Покажи применимость по тому же N, отдельным областям и счету байтов на полном байтовом домене. Инициализация scratch до чтения — внешний вывод при uninit OFF. Итоговый байтовый пост состоит из числового порядка, полного мультимножества и неизменности q, `v[0]`, `v[1+N..34]`. [Grouped properties](item2-audit-response-20261120/GROUPED-PROPERTY-DECISION.md)

## Восемь exact корней

Модуль `rev2_n22_n25_consumer` под `kani_smallsort_rev2_n22_n25_consumer` с унаследованными cfg. Все корни — plain Proof. На каждую длину один shared helper для positive и контрольной специализаций с одинаковым actual вызовом и одинаковыми assertions. Positive получает N независимых битов в активном срезе. Остальные байты и q произвольны во всех восьми корнях. Actual сеть исполняется до copy-back без stubs, Replace и loop contracts, без предположений о порядке половин. Общий oracle проверяет каноничность и отсортированную маску исходного popcount. q/frame проверяются отдельно. Контроль инвертирует `v[1] ^= 1` после actual возврата и covers, перед тем же постом. [Шаблон N20/N21](REV2-N20-N21-CONSUMER-TASK.md#четыре-exact-корня)

| N | Positive / контроль, suffix selector | Маска контроля → правильный пост → после порчи | Обязательные covers positive / контроль |
| ---: | --- | --- | ---: |
| 25 | `n25_actual_bits` / `n25_witness_corrupt` | `0x00ff_f1ff` → `0x01ff_fff0` → `0x01ff_fff1` | 7 / 6 |
| 24 | `n24_actual_bits` / `n24_witness_corrupt` | `0x001f_f1ff` → `0x00ff_ffc0` → `0x00ff_ffc1` | 5 / 5 |

Roster в порядке таблицы, внутри каждой длины positive `Nxx-ACTUAL-BITS`, затем `Nxx-WITNESS-CORRUPT`. Positive ожидает `VERIFIED` exit 0 на всех 2^N битовых входах. Контроль ожидает `FAILED` exit 1, sole failure assertion `REV2_Nxx_ACTUAL_CANONICAL_SORTED_POPCOUNT`. Regular и stock согласуют ID, класс, exact instance, метку и координату. Другие обязательные assertions, включая q/frame и достигнутые safety/overflow/loop checks, должны сохранить успешный исход. Обязательные labels, номера строк и столбцов закрепи до запуска.

Для всех длин пять обязательных covers — actual comparator, mixed, `AFTER_COPY_BACK`, сдвиги всех левых хвостов и справа либо сдвиги всех хвостов (N22–N24), либо исходная инверсия в префиксе13 (N25). На масках контроля у каждой S9 половины первые девять байтов единицы, хвостовые байты нули. Первая вставка доходит до начала, следующие останавливаются у уже вставленных нулей после сдвига девяти единиц. Проверь путь офлайн и обозначь cover как сдвиги всех хвостов. В правой половине N25 двенадцать единиц и один ноль, поэтому есть инверсия и actual S13 исполняется при пустом driver. Для N23 и N25 эта маска даёт левый центральный остаток. Добавь cover этого пути на positive и control. У odd positive отдельно достигни правого остатка с sentinel на `0x0000_07ff` для N23 и `0x0000_0fff` для N25. У odd controls эта ветка не входит в обязательный набор. Пин сохраняет длину, роль и source coordinate каждого cover.
