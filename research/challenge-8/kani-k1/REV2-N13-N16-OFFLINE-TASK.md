# REV2 · составной допуск N13–N16 без CI

Задание для w15. Подготовь `REV2-N13-N16-OFFLINE-HANDOFF.md` с четырьмя строками исследовательского допуска к независимому ревью и утверждению координатором. Область каждой строки — actual `small_sort_network::<u8, KeyLess<u8>>` на `&mut v[1..1+N]` в инициализированном V34. Активные байты произвольны, компаратор использует числовое `<`, `q: u8` независим. Ожидаемый пост на нормальном возврате — числовой порядок, полное мультимножество активных байтов и неизменность q и всех байтов вне среза. Работа офлайн, без компиляции, verifier, CI, push и новых корней. [Правило композиции](REV2-COMPOSITION-RULE.md) · [Утверждённый допуск N32](REV2-N32-ADMISSION.md)

[Привязка опор и хэши](REV2-N32-COMPOSITE-HANDOFF.md#привязка-исторических-результатов) · [Ревью переноса S13](REV2-S13-LEFT16-REVIEW.md) · [Grouped properties](item2-audit-response-20261120/GROUPED-PROPERTY-DECISION.md)

- **S13.** Сверь base, guard, 45 упорядоченных пар, полный байтовый `min/max` лист и начальное состояние. Для N14–N16 обоснуй, что новая длина не меняет доступы к rel0–12 или компаратор. Пороговый аргумент даёт порядок и полные кратности `v[1..14]`. Остальные 21 байт V34 и q сохраняются.
- **Вставки.** Для N16 приложи байтовый пост exact левого driver N32. Для N14 и N15 докажи остановку после первых одного и двух вызовов по `tail != v_end`. Проверь provenance указателей, тот же base и offset, те же адреса и условия вызовов, отсутствие чтения `v_end` и соответствие входной области. Из терминального поста N16 промежуточный пост не следует. Для N14 и N15 нужен внешний индуктивный шаг по фактическому коду `insert_tail`. Отсортированный префикс длины `13+j` расширяется на один байт. При отсутствии сдвига он уже упорядочен. При сдвиге байты большего значения перемещаются вправо, `CopyOnDrop` заполняет последнюю щель, равные значения остаются допустимыми, все записи остаются в новом префиксе. Отрази инициализированность как внешний вывод. [Байтовая опора левого driver](REV2-N32-CONSUMER-RESULTS-ANALYSIS.md)
- **Кратности.** При фиксированном входе actual выполнение не зависит от q. Равенство `count(<q)` для всех q даёт кратности через соседние пороги, для 255 — через длину минус `count(<255)`. Инвариант вставки сохраняет кратности непосредственно.

## Перенос различающего контроля

Сверь исходники и нативные anchors двух принятых контролей. `S13-BASE1-CORRUPT-MASK` из `45676394046` инвертирует бит наблюдаемой маски после actual S13. Единственный отказ — `REV2_S13_BASE1_SORTED_POPCOUNT`. `N32-COMPOSITE-WITNESS-CORRUPT` из `45723028561` инвертирует фактический `v[1]` после normal return и copy-back. Единственный отказ — `REV2_N32_ACTUAL_CANONICAL_SORTED_POPCOUNT`, q и внешний frame успешны. [Разбор контроля S13](REV2-S13-BINDING-RESULTS-ANALYSIS.md) · [Разбор контроля N32](REV2-N32-ADMISSION.md)

Для N13 свяжи локальный oracle S13 с конечным постом через пустой driver. Для N14–N16 свяжи техники через эквивалентность наблюдения и actual post-return инверсии на канонических байтах. Пример для проверки привязки — одна единица в rel0 и нули дальше. S13 ставит единицу на rel12. Каждый хвостовой ноль достигает сдвига и перемещает единицу на следующую позицию. После normal return маска равна `1 << (N-1)`, имитируемая порча `v[1] ^= 1` даёт маску с дополнительным младшим битом. Укажи, почему общий oracle должен различить их и почему q и frame сохраняются. Для N13 отдельно учти, что нативный контроль S13 меняет наблюдение. Ни один из этих receipts не исполнял отдельный описанный no-merge контроль N13–N16.

Сдай по каждой длине статус `native`, `external/composed` и `control`. Если ревью может проверить перенос по тому же посту, точным источникам, наблюдателю и достижимому witness, отметь контроль как внешний перенос к принятию. Если связь не установлена, оставь `control OPEN` и назови недостающее свидетельство, сохранив вывод по функциональным рёбрам. Новую строку допуска утверждает координатор после независимого ревью. Диагностические статусы и `proof_credit=NONE` сохраняются. Область ограничена исследовательским составным допуском `u8`. Штатный pr752 и вход в `stub_verified` требуют своего доказательства.
