# REV2 fallback · независимое ревью

**Вердикт `CHANGES_REQUIRED`.** Двадцать примитивных корней проверяют сортировку по полному числовому значению. Опубликованные корни N0–N6 проверяют сортировку по ключу `value >> 1`. Задание требует оба компаратора одновременно. Для допуска нужно согласовать порядок и привести к нему корни и карту покрытия. Статическая сверка `cell_unstable_n16` не выявила блокирующих замечаний. `go=NOT_GRANTED`, `proof_credit=NONE`. [Задание](REV2-FALLBACK-IMPL-TASK.md) · [Handoff](REV2-FALLBACK-HANDOFF.md)

## Примитивный домен · обязательное исправление

1. Таблица задания (строки 12–13) предписывает использовать опубликованные `lt_u8` и `lt_u64`. Раздел обязательств (строки 20–21) требует числовое `<` по полному значению. В parent `merge.rs:114–126` оба опубликованных компаратора сравнивают `(*a >> 1) < (*b >> 1)`. Корни N0–N6 передают их в `fallback_route_properties`, который использует тот же компаратор и в helper, и в проверке соседнего порядка (`merge.rs:342–354,398–413,537–569`). Кандидат передаёт свои функции `a < b` в обе роли (`fallback_rev2.rs:68–118`). Это выполняет требование полного числового порядка и нарушает явное требование использовать опубликованные компараторы.
2. Геометрия, множество возможных входных значений, тело fallback и полные кратности совпадают с опубликованной схемой. Меняется отношение порядка и прохождение ветвей. Например, на N7 с входом `[1, 0, 2, 3, 4, 5, 6]` опубликованный компаратор даёт ранний возврат на первом хвосте и оставляет `1, 0`. Новый компаратор сдвигает `1` и вставляет `0` перед ним. Числовая отсортированность влечёт отсортированность по сдвинутому ключу для того же результата. Для переноса результата на вызов с опубликованным компаратором нужна отдельная связь между двумя исполнениями. В частности, числовой порядок убирает класс равных ключей с различными значениями. У опубликованного `u64` в сравнении игнорируется младший бит, а старшие биты участвуют и в сравнении, и в кратностях. Карта покрытия должна отражать различие доменов. [План REV2, шаг 3](PLAN-CH8-NEXT-REV2-20261123.md#направление-1-контракты-сортировки)
3. Для продолжения опубликованного покрытия N0–N6 согласовать в задании порядок по `value >> 1`, использовать опубликованные `merge::lt_u8` и `merge::lt_u64` для fallback и oracle, сохранить полные значения для входа и кратностей. При таком выборе covers отсортированного и строго убывающего входов нужно связать с тем же отношением порядка, сохранив cover дубликатов полных значений. Если целевой порядок остаётся числовым, явно закрепить в задании новые компараторы и отдельный домен порядка N7–N16. В обоих случаях обновить handoff и точную карту первого roster для согласованных исходников.

## Свойства и границы по исходнику

- **Cell.** `kani::any::<[u8; 34]>` даёт 34 независимых полных байта для initialized backing. `canonical_less_cell` читает оба значения через `Cell::get` и сравнивает без записи или состояния. До вызова есть `assert` и `cover` активации, без `assume`. Новая ветка `enabled` принимает только `Unstable`, N5–N16 и указатель канонического компаратора. `ensures` default Unstable использует `old(enabled)` и владеющий копиями `old(snapshot)` активного среза. Проверка диапазона предшествует чтениям `0..len` в 16-байтовый снимок. Post требует оба валидных снимка одинаковой поддерживаемой длины, сравнивает соседей по полному байту и проверяет кратности каждого исходного значения без произвольного probe. При равных длинах эти кратности исчерпывают результат. `modifies(v)` сохранён. Явный внешний frame на возврате проверяет `Cell::get` для слотов 0 и `N+1..34`, у N16 это 0 и 17–33. (`fallback_rev2.rs:25–53`, `trait_model.rs:7–13,27–29,42–70,124–149,176–213`, `smallsort.rs:101–116`.)
- **Примитивы.** Оба новых компаратора чистые. Независимый `kani::any()` для probe фиксируется до инициализации массива и вызова. Копия входа сохраняется. Переиспользованный oracle проверяет соседний порядок с тем же компаратором и совпадение счётчиков для произвольного полного probe. Совпадение для всех probe даёт равенство всех кратностей. `u8` сопоставляется по байту, `u64` по всем восьми байтам одним `read_unaligned`, включая старшие биты. Для длины до 16 развёрнутый подсчёт покрывает все позиции. В исходном массиве нет внешних слотов, выход за allocation относится к штатным pointer/bounds проверкам. (`fallback_rev2.rs:68–97`, `merge.rs:24–74,90–105,342–354`.)
- **Covers.** Классы определяются по сохранённому входу, после вызова и соответствующих проверок. Есть covers полезного возврата, неубывающего входа, строго убывающего входа и любой пары равных полных значений. Для текущих числовых компараторов неубывающий вход даёт ранний возврат на каждом хвосте, строго убывающий сдвигает каждый хвост до начала, а константный массив даёт простой пример возврата с дубликатами. Нативная достижимость остаётся открытой. В новых корнях нет ordinary или verified stubs. (`fallback_rev2.rs:8–22,36–50,81–86`, `smallsort.rs:665–695`.)
- **Unwind 36 у Cell.** На N16 инициализация и внешний frame имеют по 34 итерации, снимки до 16 каждый, циклы подсчёта до 16 на каждом уровне, проверка порядка и covers до 15 на каждом уровне. Вставка имеет до 15 хвостов и до 15 итераций на один внутренний цикл. Для хвоста `p` максимум `p` сравнений, общая граница N16 равна `1 + … + 15 = 120`. Бюджет 36 оставляет запас над самым длинным явным циклом. (`fallback_rev2.rs:8–17,25–50`, `trait_model.rs:124–148,187–197`, `smallsort.rs:661–728`.)
- **Unwind 34 у примитивов.** Сохранён опубликованный стартовый бюджет. У N7 тело вставки, проверка порядка и covers имеют не более шести итераций на явный цикл, у N16 не более 15. Подсчёт кратностей развёрнут на 32 позиции без цикла, внутреннее сравнение probe также без цикла. Эти оценки обосновывают стартовые атрибуты по исходнику. Resolved unwind и unwinding assertions требуют нативной сверки. (`fallback_rev2.rs:8–17,77–97`, `merge.rs:35–74,90–105,342–354,537–549`, `smallsort.rs:661–728`.)
- **Соседние маршруты.** Stable default Cell вызывает `insertion_sort_shift_left(v, 1, …)` напрямую, игнорирует caller scratch и имеет собственные `ensures` и `modifies(v)`. Handoff обоснованно оставляет отдельный Stable Check с проверкой scratch frame на будущее. Большой Freeze-тип в default Freeze dispatch выбирает fallback при `size_of::<T>() * 48 > 4096`. В Freeze + Copy dispatch дополнительно требуется обход сетевого предиката. Полный домен большого Freeze-типа в этом пакете отсутствует. (`smallsort.rs:32–57,151–179,189–253`.)

## Изоляция и статус

Изменены пять файлов. Родительский `verify` уже под `cfg(kani)`, новый модуль дополнительно под `cfg(kani_smallsort_fallback_rev2)`. `Cargo.toml` только декларирует имя cfg для lint. Статическое удаление девяти новых cfg-конструкций из `trait_model.rs` восстанавливает токены базовой модели с точностью до форматирования и завершающей запятой. Под cfg on сохранены N2 для Cell в Stable и Unstable, а также существующие ветки других `T/F`. Дополнительный guard активирует только Unstable Cell N5–N16. В `merge.rs` меняется только видимость oracle на `pub(super)`. `smallsort.rs`, тела runtime, атрибуты действующих контрактов, штатные harnesses, profile, tool pin и workflow по diff сохранены.

Выполнены чтение закреплённых Git blobs, независимая сверка селекторов, roster и cfg-off проекции через Python и `git diff --check`. Cargo, rustc, Kani, CBMC и CI не запускались. Discovery, нативная привязка контракта, свойств и covers, DFCC, resolved unwind и ресурсные замеры остаются `UNKNOWN`. B1 и B2 credit отсутствуют. Область будущих трёх singleton ограничена их точными селекторами.
