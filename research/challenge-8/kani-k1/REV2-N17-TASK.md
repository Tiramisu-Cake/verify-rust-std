## Геометрия и доказательный граф

Exact `small_sort_network::<u8, KeyLess<u8>>` на initialized V34, активный срез `&mut v[1..18]`, числовое `<` и независимый `q: u8`. На `len=17` берётся ветка `no_merge`. Actual `sort13_optimal` получает весь срез длины 17, сортирует префикс `v[1..14]` и сохраняет хвост. Привяжи его к `S13-B01-L17-BITS` из run `45688753097`, листу FIX3 на base1 и принятому пороговому выводу. Actual `insertion_sort_shift_left(region, 13, ...)` затем вызывает `insert_tail` на rel13, 14, 15 и 16, абсолютные индексы 14–17. Последний вызов — новая обязанность. На `no_merge` тело возвращается после driver, поэтому ни второй S13, ни merge, ни copy-back не исполняются. [S13 в геометрии N17](REV2-S13-GEOMETRIES-RESULTS-ANALYSIS.md) · [Actual путь](/root/verify-rust-std-rev2-n32-composite-w14/library/core/src/slice/sort/shared/smallsort.rs:367)

Байтовый пост S13 устанавливает initialized sorted prefix13. Native byte root ниже должен доказать numeric order, count `<q` и frame на всём активном N17 после четырёх вызовов driver. q-независимость actual компаратора позволяет вывести полное мультимножество из равенства счётчиков для всех q. Сквозной битовый Proof проверяет тот же actual путь на канонических входах. Для вывода на произвольных байтах используй граф pre/post, включая последнюю вставку. Укажи source blobs, exact call sites и anchors, включая условия и выход на rel16. Нативный `stub_verified` в этой схеме отсутствует. [Прецедент двух byte roots](REV2-N32-CONSUMER-RESULTS-ANALYSIS.md#исследовательский-допуск-n32)

## Exact roster

Три новых opt-in plain `Proof` под `kani_smallsort_rev2_n17` и унаследованными cfg. Слоты в указанном порядке.

| Слот / selector | Точный вход и ожидаемый исход |
| --- | --- |
| `N17-INSERT-BYTES` / `n17_insert_bytes` | Произвольный полный V34, предусловие numeric order префикса `v[1..14]`, произвольный хвост `v[14..18]` и независимый q. Actual `insertion_sort_shift_left(&mut v[1..18], 13, ...)`. `VERIFIED`, numeric order всего активного среза, count `<q`, q-frame и V34 frame вне среза. |
| `N17-ACTUAL-BITS` / `n17_actual_bits` | 17 независимых битов как 0/1 в активном срезе, остальные байты произвольны, q независим. Actual `small_sort_network`. `VERIFIED`, каноничность, порядок, исходный popcount, q-frame и внешний frame. |
| `N17-WITNESS-CORRUPT` / `n17_witness_corrupt` | Общий helper и oracle битового корня, входная маска `0x0000_0001`. После actual normal return инвертировать `v[1]` через `^= 1`. `FAILED`, exit 1, единственный native `FAILURE` на помеченном общем посте. |

- У байтового корня нужны covers actual компаратора, нормального возврата и нетривиальной **четвёртой** вставки. Например, при отсортированном исходном префиксе `before[17] < before[13]` гарантирует сдвиг на rel16, если первые три вставки сохранили прежний максимум в предшествующем префиксе. Привяжи условие к исходнику и посту предыдущих вставок.
- У битовой пары нужны covers actual компаратора, mixed input, сдвига на rel16 и actual normal return до порчи. Маска контроля содержит одну единицу в префиксе и нули на rel13–16. После S13 она перемещается к правому краю на каждой вставке. На нормальном возврате ожидаемая маска `0x0001_0000`, после инверсии начального байта наблюдается `0x0001_0001`. q и все 17 внешних байтов V34 произвольны и сохраняются. Зафиксируй координату общего поста по точному Std commit и требуй совместимого native ID/class/location в regular и stock. [Образец конкретного контроля](REV2-N32-COMPOSITE-HANDOFF.md#конкретный-контроль)
- Пара использует прежнее представление поста через ожидаемую маску и popcount с шириной 17. Actual вызовы без stubs, Replace, новых loop contracts и предположений о промежуточных состояниях. Сохрани `VERIFIED`/`FAILED` как нативные исходы отдельно от `MATCHED` и ресурса. Для составной строки проверяются все три слота. `PAIR_WITHIN_PROFILE` битовой пары не закрывает байтовый driver. Scope пакета — N17 `u8`.
