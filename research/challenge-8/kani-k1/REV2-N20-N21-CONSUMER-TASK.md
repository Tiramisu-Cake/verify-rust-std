# REV2 · сквозные N20/N21 с контролями

Задание для **w14**. Подготовь один локальный Ubuntu-пакет из четырёх exact singleton по образцу N18/N19. Базы в отдельных worktrees — Std `f72f4303bacfff4706b20268a87b2a1031a8ee0b` / tree `03f9ce753b375729c2f8e53c18b2eaf7f3f07fc1` и control `8e1603eef95407eaf03bb592266d7513540682f8` / tree `b4a386280f9a01b72e435ce0fe0546353fd757c4`. Работа офлайн, без CI, push, изменения Actions variables и локального запуска cargo, rustc, Kani или CBMC. Runtime, существующие контракты и опоры сохраняются побайтно. [Результаты пары](REV2-MERGE-PAIR-FIXED-RESULTS-ANALYSIS.md) · [Допуск N18/N19](REV2-N18-N19-ADMISSION.md)

## Составной граф

Общий домен — actual `small_sort_network::<u8, KeyLess<u8>>` на инициализированном V34, активные срезы `v[1..21]` и `v[1..22]`, полный произвольный `u8`, числовое `<`, независимый `q: u8`. Для каждого ребра сверить точный call site, source blob, режим, пины и receipt/projection. [Геометрии](REV2-N20-N21-PROVIDERS-HANDOFF.md#presort-и-вставки) · [Правило композиции](REV2-COMPOSITION-RULE.md)

| Ребро | Точная привязка |
| --- | --- |
| Presort | Обе длины слева берут `v[1..11]`, справа — `v[11..21]` или `v[11..22]`. Слева `S9-B01-L09-BITS` и FIX3 swap на base1 с переносом на len10. Справа `S9-B11-L11-BITS` и `S9-B11-SWAP` с переносом на len10 для N20. Оба переноса сохраняют guard, base, 25 пар rel0–8 и frame. Пороговый аргумент даёт числовой порядок и кратности prefix9. |
| Вставки | `N20-INSERT-LEFT-BYTES` на `v[1..11]`, offset 9, rel9 / abs10, для обеих длин. В `N20-N21-INSERT-RIGHT-BYTES` выбрать точную ветку N20 или N21 на base11. N20 вставляет rel9 / abs20, N21 вставляет rel9 и rel10 / abs20 и abs21. Для фиксированных байтов q не влияет на результат, поэтому равенство `count(<q)` для всех q даёт все кратности. Перед merge получены две численно упорядоченные полные половины с исходными кратностями. |
| Merge | `M20-PAIR-FIXED` и `M21-PAIR-FIXED` из `45785063793` применяются к своим десяти парам. Ранговая индукция даёт порядок, footprint и заполнение `D[0..20]` у N20. У N21 остаётся ранг 10 для `D[10]`, который пишет `M21-ODD-CENTER` из `45772968167` через привязку локального wrapper к actual коду. Сверь выбранный source, sentinel `c=10` и оба терминальных равенства. Адаптируй аргумент 19 конфигураций N19 к 21 конфигурации N21. Это офлайн-сверка, а не отдельные нативные covers на каждую конфигурацию. |
| Copy-back и выход | Actual `ptr::copy_nonoverlapping(scratch_base, v_base, N)` на `smallsort.rs:425`. На положительных битовых корнях сверить достигнутый `AFTER_COPY_BACK` и grouped `.safety_check.1/.2`, `.arithmetic_overflow.1`, `.precondition_instance.1/.2/.3` на `ptr/mod.rs:587:14`. Для полного байтового домена обоснуй N инициализированных байтов в отдельной scratch32, выравнивание 1, доступное назначение и disjointness. Факт полной записи scratch следует из рангов и actual копий при uninit/validity OFF. Итоговый пост — порядок и исходное мультимножество, те же q, `v[0]` и `v[1+N..34]`. |

## Четыре exact корня

Модуль `rev2_n20_n21_consumer` под `kani_smallsort_rev2_n20_n21_consumer` и унаследованными cfg. Все четыре — plain Proof, по одному общему helper для положительного и отрицательного корня каждой длины. На positive все N битов независимы, внешние байты и q произвольны на всех корнях. Actual сеть исполняет все вызовы без stubs, Replace, loop contracts или предположений о порядке половин. Проверяй каноничность и отсортированную маску исходного popcount общим assert, q/frame — отдельно. Контроль инвертирует `v[1] ^= 1` после actual возврата и covers, перед тем же oracle.

| Слот / suffix selector | Вход и ожидаемый нативный исход |
| --- | --- |
| `N20-ACTUAL-BITS` / `n20_actual_bits` | Все 2²⁰ канонических входов. `VERIFIED`, exit 0, пост и frame `SUCCESS`. |
| `N20-WITNESS-CORRUPT` / `n20_witness_corrupt` | `0x0007_fdff`. В обеих половинах prefix9 из единиц и один нулевой хвост, обе вставки сдвигают девять единиц. Ожидаемая маска `0x000f_fffc`, после порчи `0x000f_fffd`. `FAILED`, exit 1, sole failure общего поста. |
| `N21-ACTUAL-BITS` / `n21_actual_bits` | Все 2²¹ канонических входов. `VERIFIED`, exit 0, пост и frame `SUCCESS`. |
| `N21-WITNESS-CORRUPT` / `n21_witness_corrupt` | Та же входная маска `0x0007_fdff`, дополнительно нулевой rel20. Слева одна вставка со сдвигом, справа обе вставки сдвигают единицы. Вторая справа останавливается у уже вставленного нуля. Ранг 10 — левая единица, её пишет odd branch. Ожидаемая маска `0x001f_fff8`, после порчи `0x001f_fff9`. `FAILED`, exit 1, sole failure общего поста. |

У всех корней нужны covers actual компаратора, mixed input, сдвига на каждой стороне и `AFTER_COPY_BACK`. У обоих N21 добавь достижимые условия обеих правых вставок и левого остатка. Одно условие может свидетельствовать о двух сдвигах, если handoff выводит оба по исходнику. Для N21 positive отдельно cover `0x0000_03ff`. Левая половина состоит из единиц, правая из нулей, поэтому down выбирает все десять левых байтов, `c=10`, `left_rev=S−1`, центр берёт правый остаток. Covers входов закрепи вместе с выводом о выполненном пути. У обоих контролей regular/stock согласуют один и тот же failure ID, класс и метку, файл/строку и точный helper, при успешных frame, прочих проверках и covers. Gate сохраняет точные line и column, включая вложенные метки.
