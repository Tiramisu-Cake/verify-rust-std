## Инвариант

После конца номинального binding `'cmp` внешняя continuation не должна получать пригодный для использования тип с этим локальным именем, изменяемый inference alias, разрешающий позднее подставить такой тип, или неподтверждённое scoped ограничение, позволяющее нормализовать чужую projection либо получить типизированный ресурс без исходного основания. Сохранённые объекты и права должны соответствовать исходным внешним типам; действующие loan/token obligations нельзя обходить посредством metadata или SMT equality.

Временная инстанциация ограничения внешнего F внутри блока не является утечкой. В частности, истинная lifetime-indexed формула, обычный scalar typeid и значение `lifetime_t` не становятся запрещёнными только потому, что исчезло локальное имя типа. Нужно показать недопустимое использование — неверную нормализацию другого индекса, незаконную подстановку во внешний тип или получение права без требуемого token/ownership. Ни restore таблицы, ни наличие формулы с локальным символом отдельно не доказывают этот инвариант или его нарушение.

## Точный путь типов, ресурсов и SMT

Все ссылки на локальный tool ниже относятся к проверенному HEAD4a34010; исходники восстанавливаются также из pinned tool bundle прежнего внутреннего пакета. Проверены шесть effective hashes, включая kernel `37ed2550d276abccbbe0a9ced678137ef587f80782bcff763062df394c2a440c`.

1. **Entry.** [BlockStmt и freeze_strict_type](/root/verifast-maintainer-c4-composition-20261010b/src/verifast.ml:2526) разрешают `EqConstraint` рекурсивно, отвергают unresolved/cyclic inference и копируют структуры bounds без этих mutable aliases. На2586–2590 фиксируются внешние типы и entry bounds до локальной регистрации. [register_tparam_eq](/root/verifast-maintainer-c4-composition-20261010b/src/verifast1.ml:2046) добавляет новую immutable запись списка, а не изменяет старый record snapshot на месте. Локальный typeid `'cmp` связывается с `typeid_of_lft(cmp_k)`; имя не затеняет внешние типы/значения. Шесть reference/tuple temporaries объявлены внутри strict block, а не в entry snapshot.

2. **Основание регистрации.** [Translator](/root/verifast-maintainer-c4-composition-20261010b/src/rust_frontend/vf_mir_translator/vf_mir_translator.ml:7385) находит compiler projection clause с двумя bound regions, соответствующим FnMut trait и RHS Bool. Call matcher4380–4465 сверяет compiler F/T/call/tuple с ghost аргументами; оба допустимых региона инстанцируются одной `'cmp`. Это основание принадлежит compiler-derived HRTB, а не произвольному source `assume`. Квалификация всей trusted compiler/frontend цепочки остаётся унаследованным условием, а не новым результатом этого review.

3. **Два эффекта statement.** [Runtime registration](/root/verifast-maintainer-c4-composition-20261010b/src/verifast.ml:560) вызывает `ctxt#assert_term` и `register_tparam_eq`. Это добавление факта в solver, не отдельное доказательство equality. Схематически факт имеет вид `Output_typeid(Args_typeid(Ref(K,T),Ref(K,T)),F) = Bool_typeid`, где `K = typeid_of_lft(cmp_k)`. [typeid_of_core/typeid_of_type_projection](/root/verifast-maintainer-c4-composition-20261010b/src/verifast1.ml:6386) сохраняют аргументы и lifetime typeid; это не формула `F = Bool` и не правило для произвольного другого индекса. Bounds также участвуют в [instantiate_type](/root/verifast-maintainer-c4-composition-20261010b/src/verifast1.ml:2013): projection выбирается по точному trait/args/associated-name ключу.

4. **Ресурсы callback.** [FnMut spec](/root/verifast-maintainer-c4-composition-20261010b/bin/rust/std/lib.rsspec:44) потребляет thread token, receiver cell/F owner и Args owner. На normal возвращает receiver/F owner и output owner; на unwind — receiver/F owner без результата. Здесь Output=Bool, поэтому результат, присваиваемый внешнему `result`, не несёт `'cmp`. Debt содержит `T` как type argument, а `cmp_k` — как обычный term, что не эквивалентно живому heap chunk типа `&'cmp T`.

5. **Cut и continuation.** [continue_outside_scope](/root/verifast-maintainer-c4-composition-20261010b/src/verifast.ml:2830) сначала freeze проверяет текущие bounds/outer exit types/heap type arguments. [rebase_outer_bounds](/root/verifast-maintainer-c4-composition-20261010b/src/verifast.ml:2734) заменяет learned bounds внешних type parameters в surviving heap type arguments entry bounds, сохраняя binder shadowing. Затем проверяются прямые lifetime-dependent heap/outer-local types и entry snapshot. Внешняя continuation работает с entry table; внутреннее saved состояние временно возвращается после её завершения, а финальный `do_finally`2913 снова устанавливает entry table. Normal, return и goto paths используют эти wrappers; обычный exception escape из strict block отдельно отвергается. Здесь unwind реализован goto к recovery epilog, а не обходом wrapper.

6. **Mutable inference.** [resolve_inferred_type](/root/verifast-maintainer-c4-composition-20261010b/src/verifast1.ml:3220) действительно меняет ref cell и может добавить placeholder-typeid equality. Freeze не является глобальным rollback всех таких cells/caches: он устраняет aliases в проверяемых snapshot/exported types и отвергает unresolved состояния. У данного callback site inferred region expressions принадлежат шести внутренним temps; наружу выходит Bool и исходные T/F ресурсы. Не найдено внешнего незамороженного alias, разрешающего подставить `'cmp` после cut. Отсутствие ошибки freeze в логе подтверждает прохождение checks, но лог не является полным dump всех OCaml inference cells. Relaxed unifier игнорирует некоторые lifetimes; [Rust выбирает strict matching для generic heap type arguments](/root/verifast-maintainer-c4-composition-20261010b/src/verifast1.ml:3276). Общее доказательство всех inference путей здесь не заявлено.

7. **SMT после cut.** Strict BlockStmt не делает solver-pop при переходе к внешней continuation. [push_contextStack](/root/verifast-maintainer-c4-composition-20261010b/src/verifast1.ml:360) — undo/context stack; настоящий `ctxt#push/pop` используется функцией/ветвями. [verify_func](/root/verifast-maintainer-c4-composition-20261010b/src/verifast.ml:3533) обрамляет функцию solver context, pop3694 снимает её факты; [execute_branch](/root/verifast-maintainer-c4-composition-20261010b/src/verifast1.ml:388) изолирует branch-local additions. Ground projection fact, добавленный перед normal/unwind split, может быть доступен при обеих внешних continuations. Но это по-прежнему обоснованная HRTB инстанциация. Ни её аргументы, ни Bool RHS не предоставляют lifetime token/owner или неподтверждённое equality другого индекса. В сохранённом post-cut AST нет использования локальной projection: только recovery, исходные posts и возврат Bool. Недопустимого вывода на этом пути не найдено. Полный SMT-query dependency trace при verbose2 не сохранён; это ограничение review, а не доказательство общего conservativity/erasure.

**Cut106 не является end_lifetime(cmp_k).** [Исходник](../../cloud-build/verifast-c4-select-integration/outer-bound-escape.rs) создаёт `cmp_k` снаружи на77, закрывает номинальный binding на106, а `recover_pair` вызывает `end_lifetime` на44 после возврата зарезервированной половины token. [begin/end lifetime spec](/root/verifast-maintainer-c4-composition-20261010b/bin/rust/rust_belt/lifetime_logic.rsspec:71) различает живой token и retired lifetime; type-identity формула сама не означает liveness.

## Отрицательное покрытие: непроверенный эскиз

На нынешнем Fbool пути подходящий negative **не найден**: HRTB уже обосновывает Bool для любой допустимой аргументной lifetime инстанциации. Второе имя для того же живого `cmp_k` также не создаёт запрещённого эффекта.

Минимальная логическая цель другого контроля — проверять **необоснованное отождествление разных lifetime-indexed outputs**, а не требовать удаления всех ground formulas. Эскиз отдельного source: `F: for<'r> FnMut(&'r T, &'r T) -> &'r T` (обычный higher-ranked pick-left callback показывает осмысленность bound). Два локальных borrowing scopes используют `k1`, затем `k2`, с действительными T/F owners и tokens. До каждого cut все reference/loan obligations должны быть закрыты; из каждого scope наружу сохраняется только обычный scalar witness typeid его Output, а не reference owner. После второго cut проверяется требование `saved_Output_typeid(Args(k2),F) == saved_Output_typeid(Args(k1),F)` **без исходного equality/outlives/normalization bridge**. Запрещённый эффект — считать первый lifetime-specific output пригодным вместо второго лишь из-за потерянного ключа или inference alias. Ожидается semantic non-entailment у этого конкретного type-equality VC, а не ошибка heap-leak либо заранее навязанный отказ translator. Контроль не обязан отказывать именно на106.

Это **NOT_RUN эскиз, не готовый fixture**. `begin_lifetime` не обещает `k1 != k2`: нельзя считать разные вызовы автоматически различными lifetime values. При утверждении именно неравенства нужен независимо обоснованный distinctness/nonalias premise; для equality-negative достаточно корректного непредположенного equality и проверенного контрпримера/nonvacuity. `ref_typeid` — uninterpreted symbol, не доказанная injective constructor; отказ доказать equality не устанавливает неравенство typeids. Сохранение scalar witness само допустимо. Обе resource closures, реальный Rust/source/MIR путь, typeid observer и nonvacuity ещё требуют разработки/review. Текущий C3 matcher допускает только Bool и не поддерживает этот путь: его более ранний admission refusal не закроет negative. Поэтому отрицательное покрытие пока остаётся явным пробелом; эскиз проверяет key conflation, но не всю metadata/SMT soundness.
