# Минимальные executable gates — условный план, NOT_RUN

Нет combined source head/profile, поэтому нет готового executable dispatch command. Эти gates определены по фактическим I↔v8 различиям, а не по имени lane. Первая граница — trust decision B-ORIGIN/B-LAYOUT/B-FREEZE/B-DEFAULT из COMPATIBILITY.md. Никакая новая Cloud/proof execution этой сессией не разрешена. После согласованного ограниченного решения один новый effective tool должен получить own source/patch/profile/compiler/schema/binary receipts; тогда формируется точная команда. Восстановление whole I/glue historical command проверяло бы старые отдельные инструменты.

C2 не лицензирует generic T/ZST/arrays layout расширение: его домен scalar u64 + один nongeneric guard на x86_64, с existing I ZST rules неповреждёнными. C3 не доказывает B1 целиком до выполнения всех его required controls. C4/C6 не доказывают их соединение; C5 outer-F не закрывает O23. Actual insert_tail updated gap, multi-cell caller, late comparator panic cleanup — самостоятельная B2/applicability задача, за пределами этой compatibility-сессии.

Незатронутые доказательства: mathematical networks/order/permutation/stability, merge index geometry, старые Kani bounded sorting результаты и теоремы unrelated entrypoints не входят в новый replay plan. Byte-identical aliasing definitions не требуют отдельного generic alias campaign лишь из-за имени glue; повторяется конкретный receiver/end и allocation consumer, где композиция изменилась. Unchanged C4 математическая форма контрактов не требует новых theory proofs, но actual compiled routing/resources/refinement должны быть проверены на новом pin.

Минимальность C4–C7 зависит от согласованной default isolation и сохранения I paths. Если решение потребует более широкой kernel/memory/alias смены или общих AST rewrites, этот bounded gate list недостаточен и нужен новый scope, а не автоматическое расширение текущей задачи.
