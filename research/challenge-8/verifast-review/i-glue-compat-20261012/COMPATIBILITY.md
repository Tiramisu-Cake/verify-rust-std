## Предлагаемая минимальная архитектурная граница

I остаётся базой целиком: strict freeze/FRAME/native/selector/Bool/ZST/slice/MDnew/typed source transport. До tool source assembly требуется решение по **qualified layout + live-origin span** и сохранению provenance receipt через I strict scope, с явным default isolation. Возможный additive порядок после разрешения: model/AST/marker isolation → exact exporter/schema/decoder layout/selected metadata → selected receiver/effect/canonical compatibility → observation/actual generated body/refiner gates → отдельно gated diagnostics. Это design dependency order, не авторизованный implementation chain.

Минимальная альтернатива без kernel extension — проверенный existing-resource bridge для actual constructor geometry и physical lifetime в I при неизменных contracts. Такой bridge пока не предъявлен. Менять entry premises, предполагать source/destination separation или receiver/FBC/end-token, ослаблять normal/unwind posts, отключать validity/dead/leak/refinement нельзя.

Новый trust decision должен указать допустимую receipt модель, exact compiler/source/layout allowlist, сохранение всех I safety checks, default-off границу и regression gates **до** реализации. Только после этого можно получить реальный combined source head/profile/binary hashes и executable command. Сейчас head=null и будущая proof dispatch команда намеренно не сформирована: подставлять I/v8 вместо отсутствующего combined head было бы проверкой другого инструмента.
