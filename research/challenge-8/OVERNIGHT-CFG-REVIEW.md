**Problem.** In `vf_mir_translator.ml`, `ManuallyDrop::<T>::new` is translated as `FnCallResult arg`. For a call with a destination, this produces an assignment and `Mir.GotoTerminator` to the normal target. The generic tail then nevertheless appends `unwind_targets` from the MIR unwind action to the successor inventory returned for AST block discovery. The identity lowering emitted no corresponding unwind statement or edge, so this inventory advertises a successor absent from the translated control flow. For the recorded forget MIR, that extra reachability makes the orphan `UnwindResume` cleanup return enter the AST despite having no translated incoming edge.

**Proposed semantics.** Mark only the exact `std::mem::ManuallyDrop::<T>::new` identity lowering. When that marked lowering also has a concrete destination and the generated terminator is the normal `Goto`, return only the normal target in the successor inventory. Do not generate or delete statements, alter the exported MIR, change the ordinary call translation, or prune blocks globally. Any cleanup block with a separate real predecessor remains in the graph and inventory through that predecessor. Calls with no normal destination and all other identity operations retain existing behavior.

**Trust boundary.** This changes Rust frontend CFG correspondence for one named operation in VeriFast's translator. The repository source at the pinned std says `ManuallyDrop::new(value)` directly constructs `ManuallyDrop { value }`; the stock MIR records the actual operation and normal/cleanup targets. The translator already models that operation as identity, which is itself a trusted source-to-model correspondence. This patch makes its successor inventory agree with that emitted identity-plus-normal-goto model. It does not establish general non-panicking-call semantics, alter kernel/refinement/exporter behavior, or prove the pinned Rust implementation by itself. The compiler-provided unwind edge is intentionally omitted only for this already-elided exact identity call; a future change to its lowering must revisit this rule.
