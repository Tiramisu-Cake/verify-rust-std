# Actual generic `select_unpredictable`: remaining safety gap

Design note, 2026-10-09. **No generic proof, profile acceptance, or proposed tool change.** The source authority is repository std `cd371e035c7e573760c43bf934d53e8118ee3e7d`, [`library/core/src/hint.rs:838–886`](../../../library/core/src/hint.rs#L838), under pinned VeriFast `f76012fb518703b1d98e243ac4f487f16877cfcb`. The function keeps its actual `T: [const] Destruct` signature and runtime body. The current R2 experiment remains an unaccepted `T = *const Element` specialization; its source-only wrapper rebase and full proof have separate gates in [the R2 card](CLOUD-WRAPPER-REBASE-PROFILE-CARD.md).

## Resource distinction

The actual body constructs two `MaybeUninit<T>` slots ([lines 844–845](../../../library/core/src/hint.rs#L844)), selects their storage pointers, constructs `DropOnPanic<T>`, drops the unselected value, forgets the guard, and extracts the selected wrapper ([lines 871–885](../../../library/core/src/hint.rs#L871)). R2 instead models `MaybeUninit<*const Element>` with `MaybeUninit_pointer_own<Element>` from [S6](../overnight-s6/verifast-s6-26.10-candidate.patch); its nested [`raw_ptr_own` is `true`](https://github.com/verifast/verifast/blob/f76012fb518703b1d98e243ac4f487f16877cfcb/bin/rust/rust_belt/general.rsspec#L109). Saving and rebasing those indexed pointer-value chunks grants no `<Element>.own` or generic `<T>.own`. S6 constructor, `as_mut_ptr`, intrinsic and pointer-drop correspondences, plus A1 `assume_init`, are pinned to pointer/wrapper specializations. Their exact-source certificates cannot be reused for arbitrary `T`.

For generic `T`, the caller transfers **two** `<T>.own` resources, including when `T` is zero-sized and both pure values or numeric storage addresses coincide. The proof must track selected and unselected *logical slots* and linear rights through the condition branches; pointer inequality or a positive-size premise cannot establish that ownership. A nominal guard owner must receive the selected initialized slot and its `<T>.own` exactly once, then either consume it during cleanup or return it on disarm. The stock [generic `drop_in_place<T>` contract](https://github.com/verifast/verifast/blob/f76012fb518703b1d98e243ac4f487f16877cfcb/bin/rust/std/lib.rsspec#L597-L600) consumes the initialized cell and `<T>.own` and returns an **uninitialized** cell on normal and unwind. Arbitrary `T` may panic in Drop, so R2's outer `on_unwind_ens false` is not a generic post. The stock [SAFE `forget<T>`](https://github.com/verifast/verifast/blob/f76012fb518703b1d98e243ac4f487f16877cfcb/bin/rust/std/lib.rsspec#L419-L422) consumes its argument's ownership and returns only the thread; it does not itself give the selected slot back.

## Target and missing correspondences

A truthful whole-helper contract starts with the current thread and one owner for each input. On normal return it gives the current thread, `result` equal to the condition-selected input value, and exactly one **current** `<T>.own(t, result)`. On unwind it gives the current thread, with both moved input owners consumed, no result owner, and all guard/slot resources accounted for by the original cleanup and leak checks. The latter post is intentionally weaker than normal because unselected `T`'s destructor can panic and the live guard then drops selected `T`. Preserve all original cleanup edges, validity, dead-code, return, leak and refinement checks. Neither post assumes `Copy`, `Freeze`, purity, nonpanicking Drop or a positive size.

Same-version actual-call correspondence remains necessary for generic `MaybeUninit<T>::new` and `as_mut_ptr`, both `*mut T` intrinsic selects, generic `drop_in_place<T>`, nominal guard ownership and its actual nested `Drop`, SAFE `forget(guard)` with a checked disarm/ownership-transfer route, wrapper selection, and generic `MaybeUninit<T>::assume_init`. The generic local pointer-drop and source-shaped guard Drop have checked normal/unwind evidence [here](../overnight-guard/O20-POST-ADMISSION-REVIEW.md). The latest Cloud proof-order **TEST** verifies the actual generic nested Drop with full normal/unwind return/leak; TEST scheduling does not accept a production profile ([status](../STATUS.md), [card](CLOUD-NESTED-PROOF-ORDER-TEST-CARD.md)). The same-source-body `checked_forget_owned<T>` is only an unsafe local callee, with no SAFE actual-call redirect ([O22 result](../overnight-forget-own/RESULT-O22.md)). Each actual callee needs its own verified body at the selected source version before its summary is used. A generic guard/forget bridge must transfer existing rights, never fabricate them.

## Smallest falsifiable diagnostic

Prepare a *separate* exact-source actual-helper fixture with unrestricted implicit-Sized `T`, including symbolic zero size, and the full target posts above. First capture byte-identical ghost-stripped runtime/signature, complete NORMAL and readonly MIR, all pointer/guard/Drop/forget/assume-init calls and cleanup successors, refinement, and the first full-verifier blocker with all checks enabled. Predict only that pointer-specific admission rejects and that the generic proof stops at a concrete missing callee/resource obligation; a parser or profile failure is setup, not a proof negative. Next admit **one** same-source generic callee correspondence at a time with a verified body and an isolated wrong-type/operand/cleanup admission negative. A panicking non-Copy Drop witness and a fieldless aligned ZST witness should exercise the two distinct resource paths; neither narrows the symbolic target. A successful prefix remains diagnostic until the actual whole-helper normal/unwind/return/leak proof and all targeted negative controls pass.

Even a symbolic generic proof cannot by itself certify concrete ZST representation. The pinned 26.10 exporter/schema omit `repr(align)` and the verifier assumes positive struct size; a concrete fieldless `repr(align(8))` ZST therefore lacks a faithful size/alignment model ([model boundary](../SORT4-ALIGNMENT-MODEL-BOUNDARY.md)). Resolving that trust boundary is separate from R2 and from the proposed generic diagnostic. No existing pointer result is promoted to generic or ZST safety here.
