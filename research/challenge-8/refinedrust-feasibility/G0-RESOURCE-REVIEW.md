## A. Exceptional FnMut — PROOF REQUIRED; actual composition UNKNOWN

**Подтверждено.** [`fp_unwind_post` и call rule](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/rust_typing/primitive/functions.v#L41) различают pure unwind condition и `iProp` post. [`ensures_on_unwind`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/rr_frontend/translation/src/spec_parsers/verbose_function_spec_parser.rs#L1087) задаёт spatial post. Но [base `FnMut::call_mut`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/stdlib/closures/output/closures/generated/generated_specs_closures.v#L258) имеет normal `PostMut`/ghost observation и exceptional post `True`; `UnwindCondition` не возвращает отдельные ресурсы из `Pre`.

Это **не доказательство потери F**: callee получает `&mut self`, а не owned F. [`mut_ref` invariant](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/rust_typing/mut_ref/def.v#L9) хранит `∃ r', gvar_auth γ r' ∗ l ↦ inner.ty_own_val r'` в pinned borrow. [`type_borrow_mut_end_owned`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/rust_typing/typing/program_rules.v#L4522) создаёт lender-side blocked place; при `Hdead` его inheritance возвращает existential **current** `r'` и observation. [Call continuation](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/rust_typing/primitive/functions.v#L294) сохраняет residual `R3` и local lifetime context на unwind. Поэтому отсутствие отдельного callback unwind post ещё не означает отсутствие recovery через frame/lender.

**Путь без patches.** Сохранить lender F и range/guard frame, завершить короткий receiver reborrow и shared argument loans на actual unwind edge, восстановить existential current F/T, затем выполнить guard cleanup. Это ownership post, а не обещание прежнего значения или normal `PostMut` relation. [`UnsafeCell` binding](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/stdlib/cell/src/lib.rs#L10) существует; его наличие само по себе не закрывает current-T recovery при interior mutation. Нельзя удерживать старые bytes и выдавать их за current payload.

**Не хватает.** Source-linked lemma о смерти comparator loans на обоих panic edges; closure shared T → current owned T с его semantic invariant; доказательство достаточности базового FnMut contract без потери необходимых auxiliary `Pre` resources. [Поле `FnMut_call_mut_spec`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/stdlib/closures/output/closures/generated/generated_specs_closures.v#L135) допускает полный custom spec и inclusion, но предполагать stronger exceptional spec для произвольного F нельзя: нужно вывести его из доступных generic premises либо обходиться lender recovery. Дополнительный trusted axiom не установлен и не предлагается; assumed resource return был бы запрещённым новым bridge. No-panic, purity, Copy/Freeze не являются решением.

## B. ManuallyDrop lifecycle — PROOF REQUIRED; frontend admission UNKNOWN

**Подтверждено.** В [actual std](https://github.com/Tiramisu-Cake/verify-rust-std/blob/c7ca8c467aecf10a4b53039372ee97714f854ee3/library/core/src/mem/manually_drop.rs#L156) `ManuallyDrop<T>` — transparent struct с полем `MaybeDangling<T>`, а не union. `new` вызывает `MaybeDangling::new`; [`Deref`](https://github.com/Tiramisu-Cake/verify-rust-std/blob/c7ca8c467aecf10a4b53039372ee97714f854ee3/library/core/src/mem/manually_drop.rs#L271) вызывает `as_ref`. [MaybeDangling new/as_ref](https://github.com/Tiramisu-Cake/verify-rust-std/blob/c7ca8c467aecf10a4b53039372ee97714f854ee3/library/core/src/mem/maybe_dangling.rs#L76) — struct construction/field borrow. Их собственные specs отсутствуют в исследованной RR stdlib; это библиотечный пробел, не найденный отказ semantics.

Frontend [принимает repr(transparent)](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/rr_frontend/translation/src/types/translator.rs#L798). [Drop terminator](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/rr_frontend/translation/src/body/function_translation/terminator.rs#L406) использует rustc `needs_drop_raw` перед вызовом glue; [glue translator](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/rr_frontend/translation/src/body/drop_glue_translation/mod.rs#L89) берёт compiler-generated MIR. Следовательно suppression следует проверять по compiler identity/MIR, а не моделировать destructor произвольно. [`type_local_dead`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/rust_typing/typing/program_rules.v#L5192) требует owned storage, stratification и преобразования к uninit: убрать local — не вернуть owner автоматически.

**Путь без patches / недостающие proofs.** Admit exact wrappers/callees, доказать constructor ownership и shared field projection для `&*tmp`; после callback завершить loans, применить C к CURRENT held value, перенести owner в gap ровно один раз, оставить tmp только как raw storage и закрыть его на normal/unwind. Actual `CopyOnDrop::drop` и его glue доказываются отдельно. Это кандидат на обычные библиотечные specifications/lemmas в существующей логике, без стирания wrapper или переписывания generic signatures.

**Trust.** Требуются существующие compiler/drop/layout correspondence и проверенные summaries exact callees; новой аксиомы suppression не предлагается. Compiler-known lang item и const/Deref admission на RR nightly ещё не проверены. Полная будущая dangling-семантика MaybeDangling не доказана и не нужна как допущение для этого live-value пути; source требует отдельно проверить остаточные tmp bytes после переноса. Заменить actual wrapper модельным struct и объявить успех нельзя. Union rejection относится к MaybeUninit/scratch и не является отказом этого ManuallyDrop helper.

## C. Raw-copy bridge — PROOF REQUIRED, core rules SUPPORTED

**Подтверждено.** [`ptr::read`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/stdlib/ptr/src/lib.rs#L47) требует logical Copyable, совпадение syntype и ops; [proof_read](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/stdlib/ptr/output/ptr/proofs/proof_read.v#L10) заканчивается Qed. Это допускает `value_t true (st_of T)`, не требует Rust `T: Copy`. [`typaram_wf`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/rust_typing/primitive/functions.v#L129) уже включает sized/ops premise.

Есть **конкретный bridge**, а не только надежда на expressiveness: [`ofty_own_split_value_typed`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/rust_typing/base/value.v#L662) отделяет `v @ T` от source storage `value_t true`; [`ofty_own_merge_value_typed`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/rust_typing/base/value.v#L699) потребляет этот owner и destination bytes для восстановления T. [Untyped split/merge](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/rust_typing/base/value.v#L680) обслуживают byte copy. Untyped value имеет иной syntype: просто подставить его в typed read нельзя.

[`copy_nonoverlapping` spec](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/stdlib/ptr/src/lib.rs#L157) возвращает source/destination byte arrays; [его proof](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/stdlib/ptr/output/ptr/proofs/proof_copy_nonoverlapping.v#L10) применяет owned array loop invariant и заканчивается Qed. Owner T остаётся отдельным и при merge расходуется один раз; физическая копия сама не создаёт второго T owner. Typed merge использует decoded-value compatibility, untyped merge — равенство representation, включая pointer-valued bytes, не только numeric addresses.

**Открытые obligations.** Доказать source/destination alignment/layout/bounds/provenance, typed validity при read и initialized destination после merge; получить full source bytes после shared loans, включая CURRENT mutation. Scalar split не подаётся прямо в copy spec: при len=1 тот требует `value_t false (ArraySynType (st_of T) 1)` и destination `uninit` той же array shape. Нужны layout-preserving scalar↔one-element-array conversions для обоих locations и обратный merge; exact derivation ещё не показана. В [`copy shim`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/stdlib/ptr/theories/shims.v#L75) TODO safety checks: отдельные owned footprints дают spatial separation при положительном extent, но не заменяют полный alignment/nonoverlap correspondence audit. Для zero extent этот вывод о разных адресах неприменим. [Heap zero-size rule](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/radium/heap.v#L294) есть; логические ZST owners учитываются отдельно. Actual R5 bypass при ZST сохраняется; его safety нельзя сужать до size>0 или выдавать synthetic helper call за reachable branch.

**Trust closure.** В прочитанных ptr proofs, split/merge и их локальных specs не найдено `Admitted`/новой resource axiom. Это не transitive assumption certificate: imports ведут в общую typing library, [logical axioms](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/theories/refinedrust/rust_typing/base/axioms.v) включают proof irrelevance/functional extensionality (UIP выводится). [`generate_linking_requirements=true`](https://gitlab.mpi-sws.org/lgaeher/refinedrust-dev/-/blob/332d945fafa14bf55c0c8390cb35ec4b0c012cff/README.md#L164), фактическая dependency closure и Print Assumptions/kernel audit нужны в будущем Cloud. Qed shims проверяют modeled code; source correspondence к actual std остаётся trust gate. Нельзя предполагать его либо импортировать admits из Vec/MiniVec. Новый owner-transfer axiom не нужен на уровне найденных rules; их actual применение ещё не доказано.

## Решение по G1

**GO для отдельного G1 admission experiment как диагностического следующего шага; не GO для generic theorem/G2 и не разрешение запуска.** Найден реалистичный путь на существующей логике: lender recovery → CURRENT held owner → split/copy/merge → закрытие guard/tmp. Не найден статический semantic отказ, который уже исключает helper. Но ключевые связи пока PROOF REQUIRED/UNKNOWN; поэтому общий вывод прежнего report «может выразить intended proof» следует читать как гипотезу, не установленную generic FnMut closure.

G1 после отдельного разрешения может устранить: (1) admission exact ManuallyDrop/MaybeDangling/new/Deref/copy/guard на RR nightly; (2) наличие правильного compiler Drop/cleanup и отсутствие payload Drop; (3) расположение borrow-end annotations на первом и позднем panic edges, особенно до guard copy; (4) какие syntypes, method specs и linking obligations фактически получает generic caller, включая scalar/len1-array shapes. Минимальный linked control может проверить compiled rule/dependency assumptions. Сам по себе MIR/export PASS **не докажет** CURRENT ownership, UnsafeCell/shape bridge, full negative suite или generic source correspondence: это последующие proof gates.

Первый отказ фиксируется со stage/location и exact identities. Не продолжать через stronger F premise, assumed owner bridge, no-panic, erased cleanup или semantic patch. Если нет actual callee admission/source closure либо нужны новые trusted semantics — NO-GO для дальнейшего POC на этом pin и возврат решения владельцу. Никаких Cloud Builds, lanes, CI или tool changes сейчас; следующий шаг — оценка этого пакета владельцем.
