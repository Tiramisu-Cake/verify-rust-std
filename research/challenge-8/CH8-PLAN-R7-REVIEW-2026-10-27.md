## 1. Поправки

| Где в R7 | Что меняется | Критерий |
|---|---|---|
| **§1 В2, В4; §4 L1 — ресурсы CI** | Ресурсы раннеров организаторов учитываются явно. Ubuntu: 16 ГБ, `KANI_JOBS=2`. macOS (`macos-latest`, M1, 3 ядра): 7 ГБ, `-j`. Расчёт времени через предполагаемое равное распределение по партициям убрать | Измерены фактические партиции: wall time, совокупная память, swap, OOM, полнота выполнения. Штатный параллелизм и способ разбиения сохранены. Одиночный PASS в пределах 13 GiB это не подтверждает |
| **§3 — основной Linux-lane** | Cloud Build, пул `e2-standard-4` (4 vCPU / 16 ГБ) — основной Linux-lane **с сопоставимыми ресурсами**, не с идентичной производительностью. Эмуляцию 13 GiB убрать. Source, tool и флаги остаются закреплёнными; схема партиций организаторов воспроизводится | Первый прогон подтверждает фактические ресурсы и параметры запуска. Полную нагрузку оценивать по раскладке итогового набора вместе с базовыми гармониками репозитория |
| **§3 — бюджет** | Общий потолок **$35 на оба пула вместе**, включая потраченное и зарезервированное | Учёт различает тарифы пулов. Смена пула не обнуляет бюджет и не пересчитывает старые записи. В lane — консервативная ставка до сверки биллинга владельцем: по публичному прайсу `e2-standard-4` стоит около $0,012/мин, прежняя оценка — $0,0194/мин |
| **§3 — macOS** | Сначала выяснить причину HTTP 422 и восстановить допустимый запуск в форке. Отдельный публичный репозиторий — только по явному решению владельца, без обхода блокировки Actions. Запасной вариант — платный CircleCI с macOS executor | M-1 фиксирует архитектуру, доступную память и параллелизм. Прогон на более мощном executor не подтверждает работу на 7-ГБ раннере GitHub. При `-j` на 3 ядрах на гармонику приходится около 2 ГБ. Если партиция на macOS упирается в память — дробить дальше или заранее раскрыть ограничение по macOS. Linux-цель без замера не ужесточать |
| **§4 — исполнители** | **Codex — исполнитель по умолчанию; смена исполнителя согласуется с владельцем.** Прежнее правило «задачи с контролями — только Claude» (R6 §2 п. 7 и ссылка на него в R7 §4) отменяется. Оно появилось, когда фильтр OpenAI блокировал Codex. В волне 2 Codex сам делал мутанты, контроли и CD-5 | Мутанты и отрицательные контроли сами по себе исполнителя не меняют. Правила независимого review не меняются |
| **§4 L1; §2 B4 — дробление** | Семейства с высоким пиком памяти разбить по длинам, при необходимости по смещениям. Начать с подготовленных N13/14/15: `w2_k11s_13_15` (11,8 ГиБ, job 108) и `w2_o3_insertion_13_15`. Рабочая цель — около **5 ГБ** на одну гармонику на Linux | Покрытие исходного семейства сохранено полностью. Новые гармоники прошли. Итоговый job с двумя параллельными проверками укладывается по памяти и времени. Подготовленные, но не запущенные варианты считаются непроверенными |
| **§1 В5; §4 L1u — U-1** | U-1 — **проверка осуществимости** uninit. Только пути, где scratch реально читается: general ≥8, network ≥18. Положительный и отрицательный контроль. `-Z uninit-checks` нет в флагах CI организаторов (`run-kani.sh:87`), атрибутом гармоники он не включается | Установлены поддержка инструмента и стоимость. **E1 не закрывается**, пока такой запуск и заявленный домен не включены в CI организаторов. До этого результат учитывается отдельно, как свидетельство вне CI |
| **§1 В2–В3; §4 L2 — H1** | `bidirectional_merge<T>` — generic, постусловие не может ссылаться на `key`/`tag`. Первый шаг — малый опыт специализации по образцу `K1Probe` (`kani_k1/merge.rs:105`): `Tagged` проверяется по-новому, остальные типы — прежней пробой. Проверить и `proof_for_contract`, и `stub_verified` | Контроли подтверждают, что выбрана нужная специализация и постусловия действуют. Сохраняются связь «ключ ↔ метка», маска входного региона, применимость к фактическим маршрутам; ширина маски достаточна. Только после этого — длины 20/24/32 |
| **§2 K-9s; §4 L1** | Вместо одного `[T;32]` — **16 гармоник**: `[T;N]`, N=9..16, u8 и u64. Обобщить `w2night_k9s_indices17` на `const N`, результаты N=17 сохранить. Исправить `cover`, которые зависят от N: позиция 12 недостижима при N<13 | Проверены различные символьные позиции, неизменность остальных ячеек и тот же comparator, что в K-10. Закрыт конкретный пробел размеров в K-10. Перенос на другие аллокации остаётся раскрытым как общая посылка |

## 2. Решения владельца

1. Создать в проекте `smallsort-k1` пул Cloud Build `e2-standard-4`. Сервисный аккаунт lane пулы создавать не может.
2. Подтвердить, что потолок $35 общий на оба пула.
3. Отдельный публичный репозиторий для GitHub Actions: да или нет. Рассматривается, только если причину HTTP 422 в форке устранить не удастся.
4. Платный CircleCI с macOS executor как запасной вариант для M-1.
5. Пул `e2-highmem-4` (32 GB): удалить или оставить. Пока он простаивает, денег не берёт.
