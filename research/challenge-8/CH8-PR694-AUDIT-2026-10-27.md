Аудиторский просмотр исходников #694 был ранее разрешён владельцем. Здесь опубликованы его выводы в форме для передачи исполнителям. ## 3 Покрытие и существенные ограничения

В таблице приведены выводы разрешённого аудита указанного head. «Не установлено» означает отсутствие достаточного основания для соответствующего утверждения, а не найденную ошибку Rust std или доказанную некорректность PR.

| Ось | Что подтверждает аудит | Ограничение для сравнения |
| --- | --- | --- |
| Целевые функции Challenge 8 | В наборе представлены семь целей безопасности, в том числе три trait-входа сортировки и внутренние помощники | Наличие цели в наборе не означает покрытие всех её входов, типов и длин |
| Comparator | Проверки используют корректное сравнение значений | Безопасность при несогласованном или произвольном comparator не установлена; соответствующие аварийные пути не покрыты этим аргументом |
| Non-Freeze и внутренняя изменяемость | Тип с внутренней изменяемостью присутствует | Сравнение читает значения; безопасность при изменении элементов самим comparator не установлена |
| Non-Copy и Drop | Тип с Drop представлен; для него есть проверка безопасности при N=16 и корректности при N=8 | Не установлена проверка однократного уничтожения каждого элемента при плохом comparator; присутствие Drop само по себе её не заменяет |
| Длины верхних маршрутов | Есть проверки отдельных выбранных длин general/network; полный диапазон до 32 не установлен | Нельзя переносить результат максимальной проверенной длины на все меньшие длины: пути выполнения различаются |
| Fallback | Есть символьная проверка длин 1..16 для прямого insertion-пути с начальным отсортированным префиксом длины 1 | Заявление автора о полном fallback-домене шире непосредственно установленного: это не вся матрица типов и trait-dispatch |
| Insertion в реальных callers | Покрытие до 16 с указанной выше предпосылкой | Длины 17..20 и все допустимые позиции начала вставки не установлены |
| Границы размеров и типов | Присутствуют несколько классов типов, включая широкий тип и non-Freeze; свойство выбора эффективного swap проверяется по восьми классам ширины | Это выбранные инстанциации, не полное произведение «тип × маршрут × длина». Для 16-байтного типа отмечена длина 4; она не подтверждает все ветви general. Для крупного fallback-типа отмечена длина 8 |
| Контракты | Два контракта на `swap_if_less` и `insertion_sort_shift_left`: предусловия, область изменений и гармоники `proof_for_contract` | Постусловий сортировки/перестановки в этих контрактах нет; композиционное использование через `stub_verified` не представлено |
| Неинициализированная память | Автор отдельно раскрывает отсутствие экспериментальных uninit-проверок | Полное E1 не закрыто. Зелёный штатный Kani CI не превращает стандартные проверки в проверку чтений неинициализированной памяти |
| Panic и unwind | Полное доказательство поведения при раскрутке стека не установлено | Нельзя засчитывать сохранность владения и Drop на unwind-путях |
| Контроли | Есть одна самопроверка проверяющих предикатов и cover; автор заявляет 25/25 cover | Самопроверка не заменяет мутационные проверки целевого кода. Набор таких мутационных контролей аудитом не установлен |

### Корректность сортировки

Ниже — конкретные точки, установленные аудитом. Они не обозначают сплошной диапазон от нуля до указанного N и не обобщаются на все типы.

| Проверяемое свойство и маршрут | Установленная точка | Граница утверждения |
| --- | --- | --- |
| General и stable, сортировка и перестановка | `i32`, N=8 | Не полная корректность general до 32 |
| Network, сортировка и перестановка | `u8`, N=9 | Не весь диапазон network |
| Сеть размера 13, упорядоченность | `u8`, N=13 | Отдельное свойство |
| Сеть размера 13, перестановка | N=13, значения из домена 0..3 | Перенос на весь домен значений требует отдельного обоснования; ограниченный PASS сам по себе его не даёт |
| Fallback с внутренней изменяемостью | N=8 | Comparator только читает |
| General с Drop | N=8 | Корректный comparator; это не проверка сохранности при произвольном сравнении |
| Прямой insertion | N=8 | С собственными предпосылками входа |
| Прямое слияние | `i32`, N=8, отсортированные входные половины | Не общий контракт слияния до порога |
| Стабильная сортировка четырёх элементов | `u8`, N=4 | Фиксированный размер и тип |

Автор признаёт пределы решателя на длинных general/network-входах и ошибки контрактных макросов на специализирующихся trait-методах. Эти ограничения не являются скрытыми дефектами подачи. Однако формулировки «no UB» и «полный fallback» при сравнении следует читать вместе с доменами из таблицы, ограничением comparator и отсутствием uninit/unwind-проверок.

Действует [R8 от 2026-10-27](CH8-PLAN-R8-2026-10-27.md), опубликованный коммитом `73ed3906fa25fba9efed3e0669b0b6aeae377d91`. Аудит не меняет его приоритетов, критериев и границ полномочий.

Наши результаты ниже взяты из R8 и отчёта волны 2, на который он ссылается. Это состояние, сообщённое планом, а не новый независимый пересмотр Cloud evidence.

| --- | --- |
| Безопасность при произвольном comparator до порогов на `u64` | Проверенные домены каждого маршрута и длины, ограничения обработки panic; не заявлять полный unwind |
| Comparator с внутренней изменяемостью и проверки сохранности non-Copy | Отдельные домены и результаты. Матрицу граничных типов и выбранные длины Drop не выдавать за полное произведение всех типов и длин |
| Контракты корректности и композиция | Подтверждённые callee и контроли действительности постусловий; успешный caller не заменяет доказательство callee |
| Мутационные контроли и раскрытие | Каждый предусмотренный мутант обнаруживается; таблица требований показывает оставшиеся пробелы |
| Пригодность итогового набора для CI | Полные фактические партиции с базовыми гармониками, штатный параллелизм, время и память всего job; отдельная macOS-проверка |

**Минимальный пакет может быть сильнее #694 без успешного расширения корректности на 17..32.** Основание — более строгие проверки безопасности и контракты в подтверждённых доменах. Пробелы коротких длин, ZST и прочие ограничения должны получить предусмотренную планом проверку или явное раскрытие; результат, допускающий раскрытие вместо PASS, не превращается в закрытое требование.

Один лишь факт выполнения всех шагов с допустимыми STOP/раскрытиями не гарантирует превосходства по каждой оси. Сейчас преимущество #694 — уже продемонстрированный итоговый CI. Наши ожидаемые результаты нельзя представлять как полученные; окончательное сравнение делается по L1-10 и фактическому итоговому набору.

Регулярные итерации на Cloud Build `e2-standard-4` и редкие контрольные прогоны GitHub Actions соответствуют плану. Частота использования Actions не является критерием качества доказательств. Сопоставимые Linux-ресурсы не заменяют измерение macOS; U-1 остаётся проверкой осуществимости вне штатного CI и сам по себе не закрывает E1. Рабочая форма подачи — `Towards #56`.
