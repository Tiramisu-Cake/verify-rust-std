# Independent semantic review: incoming span / MIR storage lifetime

Review of `RATIONALE.md` at 2026-10-09 19:03 UTC. This is an experimental design review, not tool acceptance or a proof result. No compiler or verifier was run.

**Conditional judgment.** With geometry restricted to independently nonzero scalar and pointer extents, I found no intrinsic unsoundness in excluding a new, genuinely live stack allocation from the bytes owned by an eligible incoming physical points-to chunk. The original broad scan is not acceptable: a hoisted local can remain in VeriFast's heap after its Rust storage ends. The proposed rule must run at the MIR `StorageLive` event and must never infer liveness from a raw pointer, numeric address, or entry snapshot alone.

The decoded retired-local control contains `StorageDead(_2)` for `tmp0` before `StorageLive(_7)` for `tmp1`; the baseline translator discarded both. At `StorageDead`, consume the local's initialized or uninitialized storage permission using the existing cleanup obligation, remove its address binding on that symbolic path, and retain any copied raw pointer as a pure value. Reject death while the required permission is unavailable. A later `StorageLive` needs a new symbolic address and allocation epoch; duplicate live, missing marker, unsupported reactivation, and double cleanup must fail closed. Normal, return, unwind, and goto paths must use the same path-local epoch state. Hoisted declarations must not produce storage before their first `StorageLive`. This scope is plausible without a general alias-model rewrite, but it requires implementation and Cloud controls.

Capture entry anchors after producing the function precondition and before heapifying parameters or declarations. Match only the **same heap `Chunk` object** still in the current heap at local allocation, with a provably positive real, non-dummy fraction. The generic Rust dereference read path in `verify_expr.ml` consumes and reinserts its returned chunk; for an exact read this can preserve identity. `ManuallyDrop::new` is translated as the value itself. A call or predicate transformation that consumes and reproduces an equivalent chunk must lose eligibility; no equality of predicate, address, coefficient, or value can restore it. An untouched positive fraction framed through a checked call remains eligible because deallocation would require its permission. Closed predicates and alternate byte representations are outside this rule.

An entry points-to precondition remains conditional on a real caller. The actual `&mut [T]` caller has generated `array<T>` and element ownership, but modular `insert_tail(begin, tail, is_less)` has only raw pointers; it cannot infer that slice borrow from pointer numbers. Any relational ghost witness must be discharged by verification of the actual call, not supplied as an axiom. The comparator call before `tail.read()` may reconstruct the incoming chunk and therefore make this identity rule inapplicable on the actual path. A simple read-only control does not establish that consumer path.

The scalar/pointer restriction resolves the specific generic ZST hazard for **this geometry rule**. Do not re-enable `GhostTypeParam` or `BoundedGhostTypeParam` using the current `sizeof` positivity test: the Rust struct-size axiom makes `sizeof(())` positive despite unit being zero-sized. The unchanged generic consumer is therefore expected to remain blocked unless an independently sound size model or guard is provided. A positive control, retired-local reuse failure at the marked inequality, consumed-anchor failure, overlap control, zero-extent control, and actual normal/unwind resource closure are still required. Until then this profile is **NOT_ACCEPTED**.

## Implementation review of `75099c958eb6a6d46016babf0a845a624f77d9ab`

Read-only review at 2026-10-09 19:12 UTC; no compile or verifier execution. I found no localized fatal soundness defect in the new marker handling. The translator emits markers in MIR statement order. The verifier intercepts them before ordinary expression verification, so the marker's `Var` argument is an identifier rather than a read of the local. Hoisted declarations with a live marker defer physical storage production and register with normal block cleanup. `StorageDead` uses the existing initialized/uninitialized cleanup obligation and removes the address from the path-local environment. The immutable per-body entry/context lists are restored through `do_finally`; only the current heap's exact entry `Chunk` objects qualify. The dereference read path reinserts the same consumed `Chunk` object. The geometry gate excludes generic types and other layout-dependent extents.

Cloud validation must distinguish expected generic-span failure from a marker compatibility failure: all translated `StorageDead` events now reach the verifier, including locals outside the new geometry rule. An address-taken local with no matching declaration in the collected map fails closed, as does a live marker for an eagerly allocated local. This is a regression/completeness risk, not a reason to accept a proof. The code review alone cannot establish normal, return, unwind, or loop path closure, nor that the actual consumer retains an eligible entry chunk after its call sequence.

**Additional integration gate (19:47 UTC): reserved-call origin.** The marker arm checks the spelling and shape of an ordinary `CallExpr`; it does not distinguish one emitted for MIR `StorageLive`/`StorageDead` from a source call. The Rust call translator preserves a callee's name and a plain local `Var` operand, and a diverging call (`target = Nothing`) becomes an `ExprStmt`. `TrName.split_def_path` documents bare root-level names. The only `vf__` prefix check found is in `verify_func`, which verifies bodies, so it does not establish rejection of an extern prototype. A root-level diverging `extern "Rust"` declaration named `vf__rust_storage_dead` or `vf__rust_storage_live` may therefore forge an event; the special arm bypasses ordinary function resolution and the encoded terminator can fall through. This is a code-derived potential unsoundness, not a tested exploit. Integration requires an unforgeable marker origin or a verified source/front-end rejection rule covering prototypes and ghost escape paths. The previous conditional no-defect finding does not clear this gate.
